## 零、初学者先读：没有报错的排错法

> 2026-11-06 整理的教学补充。首次学习先读本节，再进入后面的公式、原课代码与纠错。[第11课](<11：PyTorch入门——nn.Module与autograd.md>)、[第12课](<12：JAX入门——纯函数、jit与vmap.md>)教你把网络跑起来；本课教你回答跑起来之后真正的问题——为什么结果不对。

### 0.1 先理解这一课在做什么

传统软件坏了会崩溃：空指针抛异常、类型不匹配编译期报错。神经网络不给你这个待遇——一个坏掉的网络会**跑完、打印损失、输出预测**，损失可能还在降，预测看起来也挺像样，但模型是悄悄错的：学了捷径、背了噪声、掉进了没用的局部极小值。原课引用的估计：约 60—70% 的 ML 调试时间花在这种“静默 bug”上（原课参考）；《Recipe for Training Neural Networks》（2019）开篇第一句就是“最常见的神经网络错误是不崩溃的 bug”（原课引用）。好网络和坏网络的差别常常只是一行代码：漏了 zero_grad、维度转置、学习率差 10 倍。本课给你一套**按顺序排查**的流程和五个可以落地的诊断技术，让你不靠运气抓出这些 bug。

### 0.2 本课术语先翻成白话

- 静默 bug（silent bug）=不报错但让模型变差的 bug，ML 的主要失败模式
- 死 ReLU（dead ReLU）=输入恒为负的 ReLU 神经元：输出恒 0、梯度恒 0，永久失活
- 梯度消失（vanishing gradients）=梯度逐层反向传播时指数缩小，前面的层等于被冻结
- 梯度爆炸（exploding gradients）=梯度逐层指数放大，更新过猛，损失跳成 NaN
- 梯度检查（gradient checking）=用“数值导数”对照“反向传播算的导数”，不一致就说明 backward 有 bug
- 相对差（rel_diff）=|解析−数值|/max(|解析|,|数值|,1e-8)，<1e-5 正确，>1e-3 几乎必有 bug
- 过拟合单批测试（overfit-one-batch）=只拿一小批数据训练 100+ 步，损失应几乎归零；不能则模型或循环有根本性 bug
- 学习率探查器（LR finder）=学习率从小到大大致指数扫描一遍，看损失在哪里开始恶化
- 数据泄漏（data leakage）=测试集信息漏进训练，准确率高得可疑
- 激活统计（activation statistics）=逐层记录激活的均值/标准差/零占比，判断死层、饱和、爆炸
- 梯度裁剪（gradient clipping）=梯度范数超阈值时按比例压小

### 0.3 用小数字走一遍：损失不降时的排查决策树

（补充：把原课的决策树整理成“数据→损失→学习率→初始化→梯度”的可手算清单）

**第 1 步·先问“随机水平是多少”。** 10 类分类，模型输出均匀分布时交叉熵 = −ln(1/10) ≈ 2.303。所以损失**卡在 2.30 附近不动** = 模型在瞎猜 = 大概率不是模型问题，先查数据：标签有没有和图像错位？标签是不是被洗牌打乱了对应关系？

**第 2 步·看损失曲线的形状。** 振荡甚至 NaN → 学习率过大，先降 10 倍；纹丝不动 → 学习率过小或梯度全零。

**第 3 步·梯度检查（最硬的证据）。** 取 loss(w)=w²，解析梯度 2w。在 w=3、eps=0.1 处手算数值梯度：((3.1)²−(2.9)²)/(2×0.1) = (9.61−8.41)/0.2 = 6，与解析值 2×3=6 一致，rel_diff=0，backward 正确。假设手写反向传播时把导数错写成 3w（比如把损失记成了 w³），解析值变成 9，rel_diff=|9−6|/max(9,6)=0.33 ≫ 1e-3——一个手算就能抓到的 bug。

**第 4 步·查初始化与死神经元。** 权重全填 −1、偏置全填 −5（原课 BUG 2 的构造）：输入 x>0 时第一层输出 ≈ −x−5 < 0，ReLU 输出 0，梯度也是 0——这个神经元**永远**不再更新。逐层看激活的零占比，>50% 就该换 LeakyReLU 或调初始化。

**第 5 步·最后才怀疑架构容量。** 前四步都对而仍学不动，才是“模型太小/太深”的问题。

**交叉验证一切：过拟合单批测试。** 拿 8 个样本反复训：损失应能压到接近 0、准确率 100%。8 个点都记不住，说明损失函数、backward、优化器接线、数据对齐至少有一处是坏的——30 秒排查，省下几小时的全量训练。

以上是用于理解的算例，不是新增的训练或性能实测。

### 0.4 怎样连接到正文代码

第二节是“查什么”：三大症状（不降/降但差/NaN）+ 主诊断表；五个技术（梯度检查、激活统计、梯度流、过拟合单批、LR 探查）各自对应一小节，其中梯度检查的两个公式就是 0.3 第 3 步用的。第四节 Build It 把五件工具写成一个 NetworkDebugger 工具箱，再故意造三个坏网络（学习率 10、死 ReLU、漏 zero_grad）当“病人”，用工具箱逐个诊断，最后附一个健康网络做对照。读代码时把每个类/函数对回 0.3 决策树的一步即可。

### 0.5 理解检查（含参考答案）

**问题1：** 为什么过拟合单批测试能抓住“损失函数写错”这类 bug？

**参考答案：** 它验证的是“**能不能学**”而非“学得好不好”：一批数据重复训 100+ 步，任何容量足够的网络都能把它背下来（Zhang et al. 2017 证明网络连随机标签都能背，原课引用）。损失函数错、backward 错、优化器没接到参数、数据标签错位，任何一条都会让“背 8 个样本”失败——所以失败即证明存在根本性 bug，成功才允许进入全量训练。

**问题2：** 梯度全零有哪几种可能？

**参考答案：** 死 ReLU（激活恒 0 → 梯度恒 0）、计算图被 detach（张量没带 requires_grad、或中间 `.detach()` 切断）、以及本课演示的“梯度累加掩盖”——三种都会让权重不再更新，要分别用激活统计、`param.requires_grad` 检查、zero_grad 检查区分。

**问题3：** 训练准确率 = 测试准确率 = 随机水平（比如 10 类下都是 10%），和训练高测试低，各指向什么？

**参考答案：** 前者=模型什么都没学（先跑过拟合单批测试，再查数据管道）；后者=过拟合或数据泄漏（加正则、查划分方式）。

## 一、这一课解决什么问题？

传统调试是“看报错、改、再看”；神经网络的反馈回路慢（一次训练几分钟到几小时）、症状含糊（损失差可能是二十种原因），print-and-pray 不可行。本课给的是系统化方法：三大症状的分类诊断、五个可执行技术（梯度检查、激活统计、梯度流可视化、过拟合单批、LR 探查）、一套 PyTorch 常见 bug 清单，最后组装成可复用的诊断工具箱。黄金法则只有一句：**从最简单的配置开始，一次加一个部件，逐件独立验证**（原课）。

## 二、核心概念与推导

### 2.1 症状一：损失不降

- **学习率不对**：过大→振荡或跳 NaN；过小→慢到像没动。Adam 从 1e-3、SGD 从 1e-1/1e-2 起步，每次跨 10 倍试三个（如 1e-2、1e-3、1e-4）再下别的结论（原课建议，典型值为原课参考）。
- **死 ReLU**：神经元收到大负输入后输出 0、梯度 0，永不复活。检查法：打印每个 ReLU 后激活恰好为 0 的比例，>50% 换 LeakyReLU 或降学习率。
- **梯度消失**：sigmoid/tanh 深网络里梯度逐层指数缩小，第一层 ≈0（原课建议：ReLU/GELU、残差连接、batch norm；呼应[第04课](<04：激活函数——非线性、ReLU与饱和区.md>)）。
- **梯度爆炸**：反向放大，损失跳 NaN。修法：梯度裁剪、降学习率、加归一化。

### 2.2 症状二：损失在降但模型差

- **过拟合**：训练/验证损失差距随时间拉大。修法：更多数据、dropout、权重衰减、早停（呼应[第07课](<07：正则化——L2、Dropout与早停.md>)）。
- **数据泄漏**：先洗牌再划分、用全量统计做预处理、训练测试集有重复样本——都是泄漏源。修法：先划分再预处理、查重复。
- **标签错误**：多数真实数据集 5—10% 标签是错的（Northcutt et al., 2021，原课引用），模型会把这些噪声也学进去。

### 2.3 症状三：NaN/Inf

四个来源：学习率过大（权重爆炸，降 10 倍）；log(0)（交叉熵里预测概率恰好为 0，clamp 到 [eps, 1−eps]，eps=1e-7）；除以零（batch norm 遇到常数批 std=0，分母加 epsilon）；数值溢出（大激活进 exp 变 Inf，softmax 用“先减最大值”的 log-sum-exp 技巧）。

### 2.4 技术：梯度检查（公式）

数值梯度与相对差（0.3 第 3 步手算过）：

$$\text{grad\_numerical} = \frac{\text{loss}(w+\text{eps}) - \text{loss}(w-\text{eps})}{2\,\text{eps}},\qquad \text{rel\_diff} = \frac{|\text{解析} - \text{数值}|}{\max(|\text{解析}|, |\text{数值}|, 10^{-8})}$$

判定：rel_diff < 1e-5 正确；> 1e-3 几乎必有 bug。这是验证反向传播实现正确性的金标准（呼应[第03课](<03：从零实现反向传播——链式法则与计算图.md>)）。

### 2.5 技术：激活统计与梯度流

逐层监控激活的均值/标准差：健康网络（归一化后）均值近 0、标准差近 1。|均值|>10 或 std>10 = 爆炸；std≈0 = 塌缩；零占比过高 = 死神经元。梯度流：画每层平均梯度幅度，健康网络各层大致相当；前层比后层小 1000 倍就是梯度消失（原课示例：0.0001/0.003/0.02/0.08 对 0.05/0.04/0.06/0.05）。

### 2.6 技术：过拟合单批 + LR 探查

过拟合单批（0.3 交叉验证段）能抓五类 bug：损失函数坏、backward 坏、架构装不下数据、优化器没接上参数、数据标签错位。LR 探查（Leslie Smith 2017）：学习率从 1e-7 指数升到 10 跑一个 epoch，画 loss-LR 曲线，最优 LR 大约在“损失下降最陡点”再小一个数量级处（原课示例：最陡在 1e-2，选 ~1e-3，原课参考）。

### 2.7 常见 PyTorch bug（原课表）

| Bug | 症状 | 修法 |
|---|---|---|
| 忘 `optimizer.zero_grad()` | 梯度跨批累加，损失振荡 | backward 前清零 |
| 测试忘 `model.eval()` | Dropout/BN 行为不对，结果每次不同 | eval() + no_grad() |
| 张量形状错 | 静默广播出错误结果、无报错 | 调试时逐步打印形状 |
| CPU/GPU 不匹配 | RuntimeError: expected CUDA tensor | 模型和数据都 .to(device) |
| 忘 detach | 计算图无限增长，OOM | .detach() 或 no_grad() |
| 原地操作破坏 autograd | RuntimeError: modified by in-place | x += 1 改成 x = x + 1 |
| 数据没归一化 | 损失卡在随机水平 | 输入标准化到均值 0 方差 1 |
| 标签 dtype 错 | 交叉熵要 Long 收到 Float | labels.long() |

### 2.8 主诊断表（原课表，症状→首选动作）

| 症状 | 可能原因 | 第一件事 |
|---|---|---|
| 损失卡在 −log(1/类数) | 模型输出均匀分布 | 查数据管道、标签对齐 |
| 几步后 NaN | 学习率过大 | 降 10 倍 |
| 一开始就 NaN | log(0) 或除零 | log/除法加 epsilon |
| 损失剧烈振荡 | LR 大或 batch 太小 | 降 LR、加大 batch |
| 降后平台期 | LR 对精调阶段过大 | 加 LR 调度（余弦/阶梯） |
| 训练高测试低 | 过拟合 | dropout/权重衰减/数据 |
| 训练=测试=随机 | 什么都没学 | 跑过拟合单批测试 |
| 训练=测试但都低 | 欠拟合 | 更大模型/更多特征 |
| 梯度全零 | 死 ReLU 或图被切断 | LeakyReLU、查 requires_grad |
| 训练中 OOM | batch 大或图没释放 | 减 batch、eval 用 no_grad |

## 四、Build It：原课分步代码与中文讲解

任务：一个监控激活、梯度、损失曲线的诊断工具箱，然后故意弄坏网络、逐个诊断。

### 4.1 第 1 步：NetworkDebugger 类

用 PyTorch 的钩子（hook）挂进模型，逐层记录前向激活统计与反向梯度统计，并对损失历史做健康判定（NaN/不降/振荡）：

~~~python
# 本块中文说明：NetworkDebugger——挂钩子逐层收集激活/梯度统计。
import torch
import torch.nn as nn
import math


class NetworkDebugger:
    def __init__(self, model):
        self.model = model
        self.activation_stats = {}
        self.gradient_stats = {}
        self.loss_history = []
        self.lr_losses = []
        self.hooks = []
        self._register_hooks()

    def _register_hooks(self):
        for name, module in self.model.named_modules():
            if isinstance(module, (nn.Linear, nn.Conv2d, nn.ReLU, nn.LeakyReLU)):
                hook = module.register_forward_hook(self._make_activation_hook(name))
                self.hooks.append(hook)
                hook = module.register_full_backward_hook(self._make_gradient_hook(name))
                self.hooks.append(hook)

    def _make_activation_hook(self, name):
        def hook(module, input, output):
            with torch.no_grad():
                out = output.detach().float()
                self.activation_stats[name] = {
                    "mean": out.mean().item(),
                    "std": out.std().item(),
                    "fraction_zero": (out == 0).float().mean().item(),
                    "min": out.min().item(),
                    "max": out.max().item(),
                }
        return hook

    def _make_gradient_hook(self, name):
        def hook(module, grad_input, grad_output):
            if grad_output[0] is not None:
                with torch.no_grad():
                    grad = grad_output[0].detach().float()
                    self.gradient_stats[name] = {
                        "mean": grad.mean().item(),
                        "std": grad.std().item(),
                        "abs_mean": grad.abs().mean().item(),
                        "max": grad.abs().max().item(),
                    }
        return hook

    def record_loss(self, loss_value):
        self.loss_history.append(loss_value)

    def check_loss_health(self):
        if len(self.loss_history) < 2:
            return "NOT_ENOUGH_DATA"
        recent = self.loss_history[-10:]
        if any(math.isnan(v) or math.isinf(v) for v in recent):
            return "NAN_OR_INF"
        if len(self.loss_history) >= 20:
            first_half = sum(self.loss_history[:10]) / 10
            second_half = sum(self.loss_history[-10:]) / 10
            if second_half >= first_half * 0.99:
                return "NOT_DECREASING"
        if len(recent) >= 5:
            diffs = [recent[i+1] - recent[i] for i in range(len(recent)-1)]
            if max(diffs) - min(diffs) > 2 * abs(sum(diffs) / len(diffs)):
                return "OSCILLATING"
        return "HEALTHY"

    def check_activations(self):
        issues = []
        for name, stats in self.activation_stats.items():
            if stats["fraction_zero"] > 0.5:
                issues.append(f"DEAD_NEURONS: {name} has {stats['fraction_zero']:.0%} zero activations")
            if abs(stats["mean"]) > 10:
                issues.append(f"EXPLODING_ACTIVATIONS: {name} mean={stats['mean']:.2f}")
            if stats["std"] < 1e-6:
                issues.append(f"COLLAPSED_ACTIVATIONS: {name} std={stats['std']:.2e}")
        return issues if issues else ["HEALTHY"]

    def check_gradients(self):
        issues = []
        grad_magnitudes = []
        for name, stats in self.gradient_stats.items():
            grad_magnitudes.append((name, stats["abs_mean"]))
            if stats["abs_mean"] < 1e-7:
                issues.append(f"VANISHING_GRADIENT: {name} abs_mean={stats['abs_mean']:.2e}")
            if stats["abs_mean"] > 100:
                issues.append(f"EXPLODING_GRADIENT: {name} abs_mean={stats['abs_mean']:.2e}")
        if len(grad_magnitudes) >= 2:
            first_mag = grad_magnitudes[0][1]
            last_mag = grad_magnitudes[-1][1]
            if last_mag > 0 and first_mag / last_mag > 100:
                issues.append(f"GRADIENT_RATIO: first/last = {first_mag/last_mag:.0f}x (vanishing)")
        return issues if issues else ["HEALTHY"]

    def print_report(self):
        print("\n=== NETWORK DEBUGGER REPORT ===")
        print(f"\nLoss health: {self.check_loss_health()}")
        if self.loss_history:
            print(f"  Last 5 losses: {[f'{v:.4f}' for v in self.loss_history[-5:]]}")
        print("\nActivation diagnostics:")
        for item in self.check_activations():
            print(f"  {item}")
        print("\nGradient diagnostics:")
        for item in self.check_gradients():
            print(f"  {item}")
        print("\nPer-layer activation stats:")
        for name, stats in self.activation_stats.items():
            print(f"  {name}: mean={stats['mean']:.4f} std={stats['std']:.4f} zero={stats['fraction_zero']:.1%}")
        print("\nPer-layer gradient stats:")
        for name, stats in self.gradient_stats.items():
            print(f"  {name}: abs_mean={stats['abs_mean']:.2e} max={stats['max']:.2e}")

    def remove_hooks(self):
        for hook in self.hooks:
            hook.remove()
        self.hooks.clear()
~~~

（核对两点：`register_full_backward_hook` 是较新 PyTorch API，旧版本叫 `register_backward_hook`；`out.std()` 在输出只有单个元素时（如 batch=1 且 1 维输出）返回 nan，演示脚本 batch 足够大时不触发。均为运行环境注意，不是逻辑错误。）

### 4.2 第 2 步：过拟合单批测试

~~~python
# 本块中文说明：0.3 节交叉验证手段的落地——8 个样本背不下来就是有根本 bug。
def overfit_one_batch(model, x_batch, y_batch, criterion, lr=0.01, steps=200):
    optimizer = torch.optim.Adam(model.parameters(), lr=lr)
    model.train()
    print("\n=== OVERFIT ONE BATCH TEST ===")
    print(f"Batch size: {x_batch.shape[0]}, Steps: {steps}")

    for step in range(steps):
        optimizer.zero_grad()
        output = model(x_batch)
        loss = criterion(output, y_batch)
        loss.backward()
        optimizer.step()

        if step % 50 == 0 or step == steps - 1:
            with torch.no_grad():
                preds = (output > 0).float() if output.shape[-1] == 1 else output.argmax(dim=1)
                targets = y_batch if y_batch.dim() == 1 else y_batch.squeeze()
                acc = (preds.squeeze() == targets).float().mean().item()
            print(f"  Step {step:3d} | Loss: {loss.item():.6f} | Accuracy: {acc:.1%}")

    final_loss = loss.item()
    if final_loss > 0.1:
        print(f"\n  FAIL: Loss did not converge ({final_loss:.4f}). Model or training loop is broken.")
        return False
    print(f"\n  PASS: Loss converged to {final_loss:.6f}")
    return True
~~~

（核对：二分类分支 `(output > 0)` 是对 logits 直接阈值——logits>0 等价于 sigmoid(logits)>0.5，写法正确；通过标准设为最终损失 < 0.1，与 0.3 节“接近零”的表述一致。）

### 4.3 第 3 步：学习率探查器

~~~python
# 本块中文说明：LR 从 1e-7 指数扫到 10，找损失开始恶化前的点。
def find_learning_rate(model, x_data, y_data, criterion, start_lr=1e-7, end_lr=10, steps=100):
    import copy
    original_state = copy.deepcopy(model.state_dict())
    optimizer = torch.optim.SGD(model.parameters(), lr=start_lr)
    lr_mult = (end_lr / start_lr) ** (1 / steps)

    model.train()
    results = []
    best_loss = float("inf")
    current_lr = start_lr

    print("\n=== LEARNING RATE FINDER ===")

    for step in range(steps):
        optimizer.zero_grad()
        output = model(x_data)
        loss = criterion(output, y_data)

        if math.isnan(loss.item()) or loss.item() > best_loss * 10:
            break

        best_loss = min(best_loss, loss.item())
        results.append((current_lr, loss.item()))

        loss.backward()
        optimizer.step()

        current_lr *= lr_mult
        for param_group in optimizer.param_groups:
            param_group["lr"] = current_lr

    model.load_state_dict(original_state)

    if len(results) < 10:
        print("  Could not complete LR sweep -- loss diverged too quickly")
        return results

    min_loss_idx = min(range(len(results)), key=lambda i: results[i][1])
    suggested_lr = results[max(0, min_loss_idx - 10)][0]

    print(f"  Swept {len(results)} steps from {start_lr:.0e} to {results[-1][0]:.0e}")
    print(f"  Minimum loss {results[min_loss_idx][1]:.4f} at lr={results[min_loss_idx][0]:.2e}")
    print(f"  Suggested learning rate: {suggested_lr:.2e}")

    return results
~~~

（核对：`suggested_lr` 取“最小损失位置往回退 10 步”的学习率，是对“最陡下降点再小一档”的工程近似；扫描前 deepcopy 权重、结束后恢复，模型不被破坏。）

### 4.4 第 4 步：梯度检查器

~~~python
# 本块中文说明：2.4 节公式的落地——数值导数对照反向传播导数。
def _flat_to_multi_index(flat_idx, shape):
    multi_idx = []
    remaining = flat_idx
    for dim in reversed(shape):
        multi_idx.insert(0, remaining % dim)
        remaining //= dim
    return tuple(multi_idx)


def gradient_check(model, x, y, criterion, eps=1e-4):
    model.train()
    x_double = x.double()
    y_double = y.double()
    model_double = model.double()

    print("\n=== GRADIENT CHECK ===")
    overall_max_diff = 0
    checked = 0

    for name, param in model_double.named_parameters():
        if not param.requires_grad:
            continue

        layer_max_diff = 0

        model_double.zero_grad()
        output = model_double(x_double)
        loss = criterion(output, y_double)
        loss.backward()
        analytical_grad = param.grad.clone()

        num_checks = min(5, param.numel())
        for i in range(num_checks):
            idx = _flat_to_multi_index(i, param.shape)
            original = param.data[idx].item()

            param.data[idx] = original + eps
            with torch.no_grad():
                loss_plus = criterion(model_double(x_double), y_double).item()

            param.data[idx] = original - eps
            with torch.no_grad():
                loss_minus = criterion(model_double(x_double), y_double).item()

            param.data[idx] = original

            numerical = (loss_plus - loss_minus) / (2 * eps)
            analytical = analytical_grad[idx].item()

            denom = max(abs(numerical), abs(analytical), 1e-8)
            rel_diff = abs(numerical - analytical) / denom

            layer_max_diff = max(layer_max_diff, rel_diff)
            checked += 1

        overall_max_diff = max(overall_max_diff, layer_max_diff)
        status = "OK" if layer_max_diff < 1e-5 else "MISMATCH"
        print(f"  {name}: max_rel_diff={layer_max_diff:.2e} [{status}]")

    model.float()

    print(f"\n  Checked {checked} parameters")
    if overall_max_diff < 1e-5:
        print("  PASS: Gradients match (rel_diff < 1e-5)")
    elif overall_max_diff < 1e-3:
        print("  WARN: Small differences (1e-5 < rel_diff < 1e-3)")
    else:
        print("  FAIL: Gradient mismatch detected (rel_diff > 1e-3)")
    return overall_max_diff
~~~

（核对：整个检查转到 double 精度做——float32 下有限差分的舍入误差会淹没 eps=1e-4 的信号，这一步是正确性的关键；`y_double` 要求 criterion 接受 double 的目标，CrossEntropyLoss 的 double 版目标需为整数类型。另注意每层只抽查前 5 个（展平索引 0—4）参数位置，非随机抽样，是教学取舍。）

## 七、失败模式、原文边界与工程注意

1. **过拟合单批的适用边界**：它验证“能不能学”，不保证“学得好”；单批失败说明有根本 bug，单批成功后仍可能过拟合、泄漏（补充提醒）。
2. **梯度检查遇上 Dropout/BN 会失真**（补充，原课未提）：随机的 dropout 掩码和批统计量让两次前向不可比，检查前应置 eval 或移除随机层；本课演示模型无此类层，不受影响。
3. **LR 探查是启发式**：原课“最优 LR 在最陡点前一档”是经验法则，结果依赖扫描范围与 batch，应当起点而非结论（原文边界）。
4. **钩子有开销**：NetworkDebugger 挂满钩子会拖慢训练，诊断完记得 `remove_hooks()`，生产中只在调试时启用（原课 Ship It 建议每 N 步记录）。
5. **60—70% 数字是估计**（原课参考）：引自原课对 Google 研究者的转述，非精确统计。
6. **`detect_anomaly` 显著拖慢训练**：只用于定位 NaN 源头，平时关闭。
7. **阈值都是经验值**：激活均值 >10、梯度 <1e-7/>100、首末层比 >100 等，是原课给的量级锚点，不是物理常数，跨任务要校准。
8. **先修数据再修模型**：主诊断表把“卡在随机水平”的第一件事指向数据管道——标签错位这类 bug 在模型侧永远查不出来（补充强调，与 0.3 第 1 步呼应）。
