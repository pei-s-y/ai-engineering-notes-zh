**1．机器学习到底在做什么**

机器学习通过数据确定模型的参数，让模型能够对新数据进行预测，或从数据中提取有用的结构。

以垃圾邮件识别为例：手写程序可以规定“出现某些词就判为垃圾邮件”；监督学习则使用大量邮件及其已知类别，估计一个分类模型。训练完成后，再用它判断新的邮件。

这里有两个不同阶段：

- **训练（training）**：根据训练数据，确定模型内部的参数。
- **推理／预测（inference / prediction）**：使用已经训练好的模型处理新输入。

以监督学习为例，可以写成：

$$
\hat y=f_\theta(x)
$$

`x` 是输入，`θ` 是从数据中学到的参数，`ŷ` 是预测结果，`y` 是已知的真实目标。训练时，算法利用数据确定 `θ`；预测时，通常固定 `θ`，只输入新的 `x`。

模型能够用于新数据，并不意味着它一定预测准确。**泛化（generalization）就是模型在未用于训练的数据上仍然表现良好的能力，需要通过实验评估。**

补充：原文“提供数据和正确输出”的解释主要对应监督学习；无监督学习并不要求每个样本都有正确答案。

**2．三种常见学习方式，以及半监督、自监督**

| 学习方式 | 训练时有什么 | 学什么 | 例子 |
|---|---|---|---|
| 监督学习 | 输入和对应的目标／标签 | 输入到目标的映射 | 邮件分类、房价预测 |
| 无监督学习 | 没有给定目标标签的数据 | 数据中的结构 | 客户聚类、降维 |
| 强化学习 | 状态或观测、动作、奖励等交互经验 | 让累计回报较高的策略 | 游戏决策、机器人控制 |

监督学习中的“监督”表示存在训练目标，不是指有人一直看着程序运行。

无监督学习常见任务包括：**聚类**，将相似样本组织到一起；**降维**，用更少的维度表示数据，同时尽量保留关心的信息。聚类形成的组别不保证天然对应现实中的某种正确分类。

强化学习关注行动带来的长期结果。一个动作当下可能没有奖励，却会影响之后能否成功。这里的策略（policy）描述智能体如何根据当前信息选择动作。也可以利用预先收集的交互数据学习，不一定每次训练都实时操作环境。

半监督学习使用少量有标签数据和大量无标签数据。本课介绍了三种思路：

- **标签传播**：让有标签样本通过相似关系影响无标签样本。
- **伪标签**：先训练模型，再用模型给无标签数据产生预测标签；这些标签可能出错，不能当成真实标注。
- **一致性正则化**：对于不改变语义的小扰动，希望模型输出保持一致。

自监督学习从数据本身构造训练目标。例如遮住部分文本后预测被遮住的 token，或根据前面的 token 预测下一个 token；也可以让同一张图像的不同增强视图具有一致的表示。

**“没有人工标签”不等于“没有训练目标”。** 自监督学习常被归入广义无监督学习或表征学习；不必记成“只要有预测目标，就一定属于传统监督学习”。另外，语言模型预测的是 token，它不总是一个完整的单词。

**3．分类、回归与损失函数**

| 对比项 | 分类（classification） | 回归（regression） |
|---|---|---|
| 要回答的问题 | 属于哪一类 | 数值是多少 |
| 目标 | 离散类别 | 数值量，通常是连续值 |
| 例子 | 设备正常／故障 | 设备下一时刻的温度 |
| 常见训练损失 | 交叉熵 | 均方误差 MSE、平均绝对误差 MAE |
| 常见评估指标 | 准确率、精确率、召回率、F1 | MAE、RMSE、R² 等 |

分类模型内部也可以输出各类别的概率或得分，最终再选择类别。“类别用数字 0、1 表示”不意味着它变成了回归问题。

三个基本计算式：

$$
\mathrm{Accuracy}=\frac{\text{预测正确的样本数}}{\text{全部样本数}}
$$

$$
\mathrm{MSE}=\frac{1}{n}\sum_{i=1}^{n}(\hat y_i-y_i)^2,
\qquad
\mathrm{MAE}=\frac{1}{n}\sum_{i=1}^{n}|\hat y_i-y_i|
$$

MSE 对较大的误差惩罚更重。交叉熵则会惩罚模型给真实类别分配过低的概率。

修正原文：分类对比表把 accuracy 放进了“损失函数”一栏。这里应区分：**损失用于指导训练，指标用于评价结果；准确率通常作为评估指标，不直接作为梯度下降的可微训练目标。** MSE、MAE 等则既可以用于训练，也可以用于评估。[scikit-learn 指标说明](https://scikit-learn.org/stable/modules/model_evaluation.html)

**4．一个完整机器学习项目的流程**

1. 定义任务：输入是什么、预测什么、结果用来做什么。
2. 收集和检查数据：来源是否可靠，标签是否正确，有没有缺失值、重复和异常。
3. 设计数据划分：预留验证集和测试集，处理好时间、用户或轨迹之间的关系。
4. 在训练集上拟合预处理与特征处理方法，再应用到其他数据。
5. 建立简单基线，训练候选模型。
6. 用验证集比较方案、选择超参数。
7. 方案确定后，在保留的测试集上做最终评估。
8. 部署后监控真实表现；数据分布或需求改变时重新检查模型。

**特征（feature）**是模型可以利用的输入信息。比如预测房价时的面积和房龄；在深度学习里，特征也可以由网络从图像或文本中学习得到。

原文把特征处理画在数据划分前。实际操作要区分“设计一个固定转换”和“从数据估计转换参数”：标准化的均值、方差，缺失值填充值，以及 PCA 等方法，都应该只从训练部分估计，然后用于验证／测试部分，否则会泄漏信息。[scikit-learn 数据泄漏说明](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)

原文提到的“数据清洗通常占 60%～80% 时间”可作为经验性提醒，不必记成适用于所有项目的固定比例。

**5．训练集、验证集、测试集怎么分工**

| 数据集 | 用途 | 类比 |
|---|---|---|
| 训练集（training set） | 学习模型参数 | 平时用于学习的习题 |
| 验证集（validation set） | 选择模型、调超参数、判断何时停止训练 | 用于调整复习方法的模拟考试 |
| 测试集（test set） | 评估已经选定的方案 | 留到最后的独立考试 |

70%／15%／15% 是一种示例，不是必须遵守的比例。小数据集可以在训练开发阶段使用 K 折交叉验证：每次拿 K−1 份训练，剩下一份验证，轮换后汇总表现。若需要最终独立评估，仍应妥善保留独立测试数据，或采用适当的嵌套评估方案。

原文说“测试集只能看一次”，重点是**不要根据测试结果反复选择模型和参数**。不是说第二次运行同一条评估命令就自动破坏实验，而是测试反馈一旦影响了方案选择，就不再是真正独立的最终考核。

还要注意划分方式：相邻视频帧、同一人的多条记录或同一条机器人轨迹往往高度相关。不能默认把所有行随机打散，就足以衡量对新场景的泛化能力。连续观测数据的实验尤其需要关注按轨迹或场景划分。

**6．过拟合、欠拟合、偏差与方差**

| 现象 | 常见表现 | 可以尝试的处理 |
|---|---|---|
| 欠拟合 | 训练与验证效果都较差 | 改善特征、增加适当的模型能力、检查训练是否充分、减弱过强的正则化 |
| 过拟合 | 训练效果好，验证效果明显较差 | 增加有效数据、限制模型复杂度、正则化、适用时使用数据增强或提前停止 |
| 泛化较好 | 训练与验证都达到任务要求 | 再用独立测试数据检验 |

训练准确率 99%、测试准确率 60%，常见解释是过拟合，但还应排查训练／测试分布差异、预处理不一致、标签问题和实现错误。不能仅凭两个数字就确定唯一原因。

**偏差（bias）**描述模型平均预测与真实规律之间的系统性差异；**方差（variance）**描述更换训练样本后，模型预测有多敏感。简单模型可能表达能力不足，复杂模型也可能对训练噪声敏感，但“模型越大必然越过拟合”不是普遍定律。

在平方误差及相应统计假设下，可以理解为：

$$
\text{期望预测误差}=\text{偏差}^2+\text{方差}+\text{不可约噪声}
$$

这是特定条件下的误差分解，不是所有损失函数都直接使用的通用等式。“不可约噪声”也是相对于当前观测信息和建模假设而言。

**参数与超参数也要分清：**参数是从训练数据得到的，例如本课的类别中心；超参数是控制模型或训练的设定，例如其他模型的学习率、正则化强度。数据生成器的 `separation` 控制合成数据的难度，不是本课分类器学到的参数。

**7．最近质心分类器：本课的核心算法**

质心（centroid）就是一组样本各特征的平均值。最近质心分类器先求出每个类别的中心，再把新样本分到距离它最近的中心所对应的类别。

对类别 c，训练得到的中心为：

$$
\mu_c=\frac{1}{N_c}\sum_{i:y_i=c}x_i
$$

预测新样本 x 时：

$$
\hat y=\arg\min_c\|x-\mu_c\|_2
$$

手算例子：类别 0 的两个样本是 `(0,0)`、`(2,0)`，中心为 `(1,0)`；类别 1 的样本是 `(4,4)`、`(6,4)`，中心为 `(5,4)`。新样本 `(2,1)` 到两个中心的距离分别为 `√2` 和 `√18`，因此预测为类别 0。

这是监督学习：计算各类别中心时，必须知道哪些样本属于哪个类别。它不等于在没有标签时寻找簇中心的 K-means，也不等于找最近若干训练样本投票的 KNN。

本课直接计算均值就完成了训练，不需要梯度下降。**训练不一定意味着反复迭代；不同算法确定参数的方式不同。**

配套源码的关键部分：

```python
def fit(self, X, y):
    self.classes = np.unique(y)
    self.centroids = np.array([
        X[y == c].mean(axis=0) for c in self.classes
    ])

def predict(self, X):
    distances = np.array([
        np.sqrt(((X - c) ** 2).sum(axis=1))
        for c in self.centroids
    ])
    return self.classes[distances.argmin(axis=0)]
```

来源：课程 `code/ml_intro.py`。理解代码时可以跟踪数组形状：

| 表达式 | 形状／含义 |
|---|---|
| `X` | `(样本数, 特征数)`，每行一个样本 |
| `y` | `(样本数,)`，每个样本的类别 |
| `X[y == c]` | 取出类别 c 的全部训练样本 |
| `.mean(axis=0)` | 沿样本维求平均，保留每个特征的均值 |
| `centroids` | `(类别数, 特征数)` |
| `X - c` | 每个样本分别减去当前中心，使用 NumPy 广播 |
| `.sum(axis=1)` | 把每个样本各特征的距离平方相加 |
| `distances` | `(类别数, 待预测样本数)` |
| `argmin(axis=0)` | 对每个样本找最近的类别中心索引 |

`score()` 使用预测类别与真实类别比较，再求布尔数组的平均值，也就是准确率。`True` 对应 1，`False` 对应 0。

对于这个使用欧氏距离的实现，两个类别中心之间的等距边界是线性的。遇到环状类别、多簇类别、严重尺度差异等数据时，一个中心可能不足以描述一个类别；特征缩放能改善尺度问题，但不能自动解决所有分类困难。

**8．为什么必须和基线比较**

基线（baseline）是容易实现的参考方案，用来判断模型是否真的提供了额外价值。本课代码包含两种：

- **随机基线**：按训练集中各类别的比例随机预测。有限测试集上的准确率会波动，不保证二分类恰好得到 50%。
- **多数类基线**：先找出训练集中最多的类别，再对所有测试样本都预测这个类别。

原文正文主要演示随机基线；本地完整程序还加入了多数类基线，且随机预测使用训练集类别频率，不是始终均匀抽取。

例如 99% 的数据都属于正常类别时，“永远预测正常”就有很高的准确率，却完全无法识别故障。因此，遇到类别不平衡，需要结合精确率、召回率、F1 等与任务目标相符的指标。指标不是越多越好，应能反映实际错误代价。

回归任务也可以设置简单基线，例如始终预测训练集目标的均值；预测时间序列时，则可以把“下一步等于当前值”作为候选基线。

**实验 A：二分类和基线**

程序实际生成 300 个样本，每个样本有 2 个特征；划分为 210 个训练样本和 90 个测试样本。训练得到的两个中心约为 `(1.037, 1.009)` 和 `(-0.977, -1.105)`。

| 方法 | 训练准确率 | 测试准确率 |
|---|---:|---:|
| 最近质心分类器 | 91.9% | 96.7% |
| 随机基线 | — | 46.7% |
| 多数类基线 | — | 43.3% |

这次测试准确率高于训练准确率，可能来自有限样本和随机划分，不要求每次测试分数都低于训练分数。多数类基线低于 50%，也不矛盾：代码依据训练集选多数类，而这次测试集类别比例不同。

程序显示“比随机基线提高 107.1%”，使用的是相对提升 `(模型准确率－基线准确率)／基线准确率`。准确率的绝对提升是 **50 个百分点**，不是提高了 107.1 个百分点，更不是准确率超过了 100%。

**实验 B：改变类别分离程度**

| `separation` | 测试准确率 |
|---:|---:|
| 0.5 | 64.4% |
| 1.0 | 75.6% |
| 1.5 | 86.7% |
| 2.0 | 96.7% |
| 3.0 | 98.9% |
| 5.0 | 100.0% |

在本例中，生成数据时把两类中心拉得更远，会降低类别重叠，使分类更容易。这里是在改变数据生成条件，不是在同一份真实数据上“调一个参数就让模型变好”。

**实验 C：改变特征维度**

| 特征数 | 测试准确率 |
|---:|---:|
| 2 | 93.3% |
| 5 | 99.2% |
| 10 | 100.0% |
| 20 | 100.0% |
| 50 | 100.0% |

本例每增加一个维度，都同时增加了能区分类别的信息。代码让两个生成中心的每个坐标相差 `separation`，所以中心间的欧氏距离是 `separation × √特征数`，并不是维度增多后总距离仍固定。

因此，结果不能推广成“特征越多越好”。真实数据中额外特征可能是噪声、重复信息，或者增加样本需求。实验 C 的每类样本数为 200，与实验 A 不同，不能把两个实验的分数差异只归因于某一个因素。

**实验 D：三分类**

测试准确率约为 98.9%，随机基线约为 34.4%。同一套算法可以处理更多类别：训练时多计算一些中心，预测时继续选最近的中心。

这些分数是小型合成数据上的教学演示，说明算法在这些设定下的行为，不代表真实任务上的性能承诺。

**10．本课代码和完整项目之间的区别**

本地示例只划分训练集和测试集，没有单独的验证集，也没有标准化、部署或监控。它用于说明最小的学习与评估过程，不是完整的生产项目模板。

复现或扩展时需要区分几种变量：

- `seed`：控制伪随机过程，便于重现数据与划分；换一个种子，结果可能变化。
- `n_per_class`：控制合成数据中每类样本数量。
- `n_features`：控制特征维度。
- `separation`：控制合成数据类别中心在每一维的差异。
- `test_fraction`：控制留给测试部分的数据比例。

本例的分类器没有需要调的学习率或迭代次数，但数据处理、距离选择和实验划分仍然涉及设计决策。

原文的 “Use It” 还展示了 scikit-learn 的实现。先知道三个接口的对应关系：`fit()` 学习，`predict()` 预测，`score()` 计算该分类器的准确率。原始 `ml_intro.py` 不依赖 scikit-learn；只有运行那段单独的库版本示例时才需要它。该示例与本地程序的数据生成方法不同，分数无需一致。

**11．没有免费午餐，以及何时采用机器学习**

“没有免费午餐”提醒我们：不存在在所有可能任务上始终最优的算法。实际选型要考虑数据量、特征、问题结构、解释需求、算力和维护成本；在本任务的数据上建立基线、比较方案，比只凭算法名气决定更可靠。

在以下情况下，应该认真比较简单规则、查表或已有数学模型：规则明确稳定；数据与标签不足；错误代价难以接受；结果需要强可解释性；问题变化速度超过模型维护能力。

对原文两点需要保留条件：少量数据不等于绝对无法做有意义的建模，是否可行取决于任务、先验和模型；确定性程序也不自动保证正确。关键是方法能否满足任务要求，并经过合适的验证。

本课 “Ship It” 提供的提示词模板，可以转化成每次建模前的一份检查记录：

1. 任务与目标：到底要预测什么？
2. 输入与数据：预测时真正能拿到哪些信息？目标标签从哪里来？
3. 学习方式：监督、无监督、自监督、半监督，还是涉及奖励的策略学习？
4. 成功标准：使用什么指标，哪种错误更值得关注？
5. 基线：简单规则、多数类、均值或其他现成方案表现如何？
6. 实验设计：怎样划分数据、避免泄漏、比较候选模型？
7. 使用条件：数据分布变化或输入异常时如何发现问题？

补充：存在 Agent、动作和环境，并不足以判定正在做强化学习。还要看是否通过奖励或回报目标学习策略。

**12．如何迁移到其他机器学习任务（补充理解）**

把本课知识迁移到其他机器学习任务时，可以继续使用“输入—训练目标—模型—评估”这四个问题。

例如，在文本自监督任务中，可以遮住部分词，让模型根据上下文预测被遮住的内容。训练目标由原始文本构造，不需要为每段文本额外人工标注类别；这与最近质心分类器使用类别标签的方式不同。

不同任务同样需要独立评估、合理基线和防止数据泄漏。训练损失较低，也不自动意味着下游任务表现更好，最终还要看任务指标。

**13．复习问题与课程练习**

先尝试不用看正文回答：

1. 监督学习、无监督学习、自监督学习的训练信息有什么区别？
2. 最近质心分类器训练时到底学到了什么？为什么不用梯度下降也算训练？
3. `mean(axis=0)` 和 `sum(axis=1)` 在本课代码里分别对什么维度操作？
4. 为什么训练、验证、测试三部分要分工？标准化参数应从哪部分数据计算？
5. 一个模型准确率 95%，是否就一定有用？需要知道哪些背景？
6. 为什么本课增加特征维度后的结果，不能说明真实项目中越多特征越好？

原文三个练习可以这样落实：

- **练习 1**：选一份数据，按 70%／15%／15% 分成训练／验证／测试，并写清每部分用途。如果使用 300 个样本，对应 210／45／45；这与主程序的 210／90 两部分划分不同。
- **练习 2**：自己列三个问题，分别写出输入、目标、学习方式和任务类型。可以用“设备故障类别”“下一时刻温度”“按运行模式对无标签设备记录分组”作核对参考。
- **练习 3**：面对训练准确率 99%、测试准确率 60%，先排查数据与实现，再给出三种处理过拟合的方案，并说明各自希望解决什么问题。

这一课掌握的证据，是能讲清上面的问题，读懂 `fit/predict/score`，并解释实际实验输出。读完正文和运行成功只是学习过程中的两个环节。
