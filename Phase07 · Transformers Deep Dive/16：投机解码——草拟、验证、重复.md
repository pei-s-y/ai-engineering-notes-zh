## 零、初学者先读：让小模型打草稿、大模型批作业

> 2026-11-06 整理的教学补充。首次学习先读本节，再进入后面的公式、原课代码与纠错。[第12课](<12：KV缓存与Flash Attention——推理优化.md>)优化了“一次前向”的成本，[第15课](<15：注意力变体——滑动窗口、稀疏与差分注意力.md>)改了注意力的拓扑；本课解决的是更根本的串行瓶颈——每生成一个 token 都要等上一个大模型前向，于是让小模型先猜、大模型一次批改一串。这是第七阶段的收官课。

### 0.1 先理解这一课在做什么

自回归生成是串行的：第 100 个 token 必须等第 99 个算完，因为它是第 99 个的输入。大模型一次前向 30ms（H100 上的 70B，原课参考），生成 100 个 token 就是 3 秒，GPU 每 30ms 里其实只忙了一个 token 的活。

投机解码的思路像“实习生打草稿、主管批阅”：让一个便宜 10 倍的小模型（草稿模型，draft model）抢先连写 N 个 token，再让大模型（验证模型，verifier）把这 N 个**一次**前向全部批改。猜对了的部分直接收下，猜错的位置当场改正——而那个“改正”本身也是一个新 token。于是大模型的每次前向不再只产出 1 个 token，而是 2—6 个。魔法在于数学保证：最终输出的分布与大模型自己慢慢写**完全相同**——不牺牲任何质量，只省时间。

直觉上为什么“批改”能省钱：验证 N 个草稿 token 只需一次并行前向（因果语言模型一次前向本来就会给出每个位置的分布），而逐个生成要 N 次串行前向。串行变并行，就是全部的把戏。

### 0.2 本课术语先翻成白话

- 自回归解码（autoregressive decoding）：一个 token 接一个 token 串行生成，延迟的根源
- 投机解码（speculative decoding）：小模型草拟 + 大模型验证的加速框架，输出分布与纯大模型相同
- 草稿模型（draft model）：便宜的小模型，负责抢先猜；通常比验证模型便宜 10—50 倍
- 验证模型（verifier）：目标大模型，每步只跑一次前向，负责批改
- 接受率 α（acceptance rate）：每个草稿 token 被验证模型接受的概率，典型 0.7—0.9
- 拒绝采样（rejection sampling）：按 min(1, q/p) 的概率接受草稿——本课算法的数学核心
- 残差分布（residual distribution）：(q−p)₊ 归一化后的“补发”分布，拒绝时从中采样
- 奖励 token（bonus token）：全部草稿被接受时，从验证模型的下一个分布里免费多拿的一个 token
- 期望产出（expected tokens per step）：每轮“草拟+验证”平均产出 (1−α^{N+1})/(1−α) 个 token
- Medusa：在验证模型上直接加多个输出头预测 t+1..t+k，不需要第二个模型
- EAGLE：让一层小草稿网络吃验证模型的隐层状态，接受率从 ~0.6 提到 0.85+
- 前瞻解码（lookahead decoding）：Jacobi 迭代式自我投机，完全不需要草稿模型
- 树注意力（tree attention）：一次前向同时验证多条候选续写的分支技巧
- KV 回滚（KV rollback）：拒绝后把验证模型 KV 缓存退回到已接受前缀的长度
- 贪心 vs 温度（greedy / temperature）：贪心解码草稿接受率高；高温采样两模型难对齐、接受率降

### 0.3 用小数字走一遍

**第一幕：一次接受/拒绝。** 设词表只有 3 个 token，验证模型在某位置给出 q=[0.5, 0.3, 0.2]，草稿模型给出 p=[0.2, 0.3, 0.5]，草稿恰好挑了 token 0（它按自己的 p 有 0.2 的概率会这么挑）。接受概率 = min(1, q(0)/p(0)) = min(1, 0.5/0.2) = 1——必收：大模型比小模型更喜欢这个 token 时，永远接受。反过来草稿挑 token 2：接受概率 = min(1, 0.2/0.5) = 0.4。规律：**草稿越自信（p 大）而大模型越不买账（q 小），越容易被拒**。

**第二幕：拒绝之后。** 若 token 0 的草稿被拒（本题中概率为 0，换个场景即可），从残差分布补发：raw = (q−p)₊ = [0.5−0.2, 0.3−0.3, 0.2−0.5]₊ = [0.3, 0, 0]，归一化后 [1, 0, 0]——只可能补发 token 0。合理性：大模型多出来的偏好（q 比 p 高的那 0.3）全部倾泻在 token 0 上。

**第三幕：分布等价（本课的灵魂）。** 把两条路合起来算最终拿到 token 0 的概率：接受路径 = p(0)×min(1, q(0)/p(0)) = min(p(0), q(0)) = 0.2；拒绝路径 = P(拒绝)×残差(0)。而 P(拒绝) = Σ_d p(d)×(1−min(1, q(d)/p(d))) = 1−Σ min(p,q) = 1−(0.2+0.3+0.2) = 0.3，恰好等于 Z=Σ(q−p)₊=0.3。于是拒绝路径贡献 0.3×1=0.3。合计 0.2+0.3=0.5=q(0) ✓。同样验证 token 1：min(0.3,0.3)+0=0.3 ✓；token 2：min(0.5,0.2)+0=0.2 ✓。**三个 token 的最终概率分毫不差地等于大模型自己的 q**——这就是“无质量损失”的证明，用六个数字就装下了。

**第四幕：三档结局。** 草稿数 N=3、接受率 α=0.8：

| 结局 | 概率 | 产出 token 数 | 大模型前向 |
|---|---|---|---|
| 全接受（+奖励） | α³=0.512 | 3+1=4 | 1 次 |
| 第 1 个被拒 | 1−α=0.2 | 1（残差补发） | 1 次 |
| 接受 1 个后拒绝 | α(1−α)=0.16 | 1+1=2 | 1 次 |

期望产出 = 1 + (α + α² + α³) = 1 + 0.8+0.64+0.512 = 2.952 个 token/轮——与公式 (1−α⁴)/(1−α)=0.5904/0.2 一致。每次草稿小模型跑 3 步（串行、便宜），大模型恒 1 次前向。

**第五幕：值不值。** 大模型 30ms/token、小模型 3ms/token：投机一轮 3×3+30=39ms 产 2.952 个 token ≈ 75.7 token/s；朴素 30ms 产 1 个 = 33.3 token/s——**2.27 倍加速**。若 α 降到 0.5：期望产出 1.875，一轮 39ms → 48 token/s，加速只剩 1.44 倍；草稿再差就倒贴。接受率就是这条技术的生命线。

以上是用于理解的算例（概率与期望均手算自洽），不是新增的推理或性能实测。

### 0.5 理解检查（含参考答案）

**问题1：** 为什么全部接受时能“免费”多拿一个奖励 token？

**参考答案：** 验证模型对 prefix+3 个草稿做一次前向时，因果结构会顺带给出第 4 个位置（前缀加全部草稿之后）的分布——这个位置大模型本来就算了，不用白不用。所以最幸运时一轮产出 N+1 个 token。

**问题2：** 草稿模型提议了一个 p=0 的 token 会怎样？

**参考答案：** 接受概率里 p=0 时比值定义为 +∞，min(1, ∞)=1，必接受——但真实模型采样几乎不会给出 0 概率 token；代码里这行防御是处理数值边界。反过来想：p 越小、q>0 时越容易接受，这符合直觉（小模型“赌对了一个冷门”）。

**问题3：** 为什么高温采样会让接受率下降？

**参考答案：** 两个模型都变得更“随机”时，它们对同一个位置的分布更难对齐——q/p 的比值更频繁地小于 1。贪心解码时两个模型都选同一个 argmax token，接受率天然高；温度越高，分布越平、越分散，草稿猜中大模型采样的概率越低。

**问题4：** 投机解码和“直接用小模型输出”有什么本质区别？

**参考答案：** 小模型输出不保证质量（分布是 p 不是 q）；投机解码的每一步都以大模型的 q 为最终裁决——0.3 第三幕证明了合成分布恰好等于 q。它是“无损加速”，不是“有损近似”。

**问题5：** KV 缓存回滚为什么麻烦？

**参考答案：** 验证前向会把 N 个草稿 token 的 K/V 都写进大模型缓存；拒绝发生时，第 j 个之后的部分是“基于未接受 token 算的”，必须退回到已接受前缀的长度再继续下一轮。生产实现用“先写草稿区、接受才提交”的缓冲区（原课：scratch KV buffers），逻辑不难但很琐碎（fiddly）。

## 一、这一课解决什么问题？

70B 大模型在 H100 上采样一个 token 约 30ms，3B 草稿模型约 3ms。让 3B 先猜 5 个 token，再让 70B 一次前向全部验证，总共 5×3+30=45ms，最多换来 5 个被接受的 token——而直排生成要 5×30=150ms。这就是投机解码的全部卖点：用一点额外显存（放草稿模型）换 2—4 倍的解码延迟（原课）。

关键在于这个把戏**保持分布不变**：投机采样（Leviathan 等 2023，与 Chen 等同时独立提出）保证输出序列与大模型自己生成的**同分布**。没有质量权衡，只有速度。

2026 年推理的四大草稿—验证家族（原课）：

1. **朴素投机（Leviathan 2023）**：独立草稿模型（如 Llama 3 1B）+ 验证模型（如 Llama 3 70B）。
2. **Medusa（Cai 2024）**：验证模型自己长出多个解码头，并行预测 t+1..t+k，无需第二个模型。
3. **EAGLE 家族（Li 2024, 2025）**：轻量草稿复用验证模型的隐层状态；接受率比朴素高；典型 3—4 倍。
4. **前瞻解码（Fu 2024）**：Jacobi 迭代，完全不需要草稿模型，自我投机。小众但零依赖。

2026 年的每个生产推理栈默认都带投机解码：vLLM、TensorRT-LLM、SGLang、llama.cpp 至少支持朴素 + EAGLE-2（原课）。

## 二、核心概念与推导

### 2.1 核心算法（原课六步）

给定验证模型 M_q 与更便宜的草稿 M_p：

1. 设 x₁…x_k 为已解码前缀。
2. **草拟**：用 M_p 自回归地提出 d_{k+1}, …, d_{k+N}，记草稿概率 p₁…p_N。
3. **并行验证**：对 x₁…x_k, d_{k+1}, …, d_{k+N} 跑一次 M_q，得到位置 k+1…k+N+1 的验证概率 q₁…q_{N+1}。
4. **从左到右接受/拒绝**：每个 i 以 min(1, q_i(d_i)/p_i(d_i)) 的概率接受。
5. **首次拒绝在位置 j**：从残差分布 (q_j−p_j)₊ 归一化后采样 t_j；j 之后的所有草稿丢弃。
6. **全部接受时**：从 q_{N+1} 再采样一个额外 token（免费奖励）。

残差分布是把数学拉回“恰好等于大模型分布”的关键（0.3 第三幕的六数字证明）。注意第 4 步的接受判定彼此依赖——必须是“接受前一个”才轮到下一个，这就是“从左到右”。

### 2.2 什么决定加速比

设 α = 每个草稿 token 的期望接受率，c = 草稿对验证的成本比。每轮：

- 朴素生成：每 token 一次大模型调用。
- 投机生成：每 (1−α^{N+1})/(1−α) ≈ 1/(1−α) 个 token 一次大模型调用（α 高时）。

推导（补充）：每轮产出 = 1 + 期望接受数 = 1 + Σ_{k=1}^{N} α^k = (1−α^{N+1})/(1−α)。经验法则：α=0.75、N=5 时大模型调用省 3 倍；草稿成本只有 1/10 量级，总墙钟降约 2.5 倍（原课）。用 0.3 第五幕的手算复演：α=0.8、N=3、30ms/3ms 的配置下，大模型调用从 1/token 降到 1/2.95 token（2.95 倍），墙钟 2.27 倍——与原课量级一致，差异来自成本假设。

**α 取决于（原课）**：

- 草稿与验证模型的匹配度：同家族/同训练数据显著提高 α。
- 解码策略：贪心对贪心 α 高；温度采样难对齐、接受率降（0.3 问题 3）。
- 任务类型：代码与结构化输出接受率高（可预测）；自由创作低。

### 2.3 Medusa——不要草稿模型的投机

Medusa 把草稿模型换成验证模型上的额外输出头。位置 t 的隐藏状态 h_t 同时喂给：head_0 预测 t+1（标准 LM 头）、head_1 预测 t+2、head_2 预测 t+3、head_3 预测 t+4（原课示意）。每个头各自出 logits，推理时从各头采样拼出候选序列，再用树注意力一次前向考虑所有候选续写。

优点：不需要第二个模型。缺点：增加可训练参数；需要约 1B token 的监督微调阶段；接受率略低于带好草稿的朴素投机（原课）。

### 2.4 EAGLE——复用隐层状态的好草稿

EAGLE-1/2/3（Li 等，2024—2025）把草稿做成一个微型 Transformer（通常 1 层），输入是验证模型的末层隐藏状态。因为草稿看得到验证模型的特征表示，其预测与验证模型的输出分布强相关——接受率从朴素的 ~0.6 爬到 0.85+（每 token、聊天基准、草稿用匹配的聊天数据训练；混合生产流量按 0.6—0.8 规划，原课引 Phase 17 · 05）。EAGLE-3（2025）加了候选续写上的树搜索；vLLM 与 SGLang 把 EAGLE-2/3 作为 Llama 3/4 与 Qwen 3 的默认投机路径（原课）。

### 2.5 KV 缓存的舞蹈

验证一次前向把 N 个草稿 token 灌进验证模型的 KV 缓存，扩展 N 条记录；若有草稿被拒，必须把缓存回滚到已接受前缀的长度。生产实现（vLLM 的 `--speculative-config`、TensorRT-LLM 的 LookaheadDecoder）用草稿 KV 缓冲区处理：先写、接受才提交。概念不难，但很琐碎（原课；0.3 问题 5）。

## 四、Build It：原课分步代码与中文讲解

原课实现核心的投机采样算法（拒绝步 + 残差分布），两个“模型”是手工定义的确定分布，便于解析验证接受数学。

### 4.1 第 1 步：拒绝步（原课代码）

~~~python
# 本块中文说明：接受判定——u 是均匀随机数，q 是验证概率，p 是草稿概率。
def accept_or_reject(q_prob, p_prob, draft_token, u):
    ratio = q_prob / p_prob if p_prob > 0 else float("inf")
    return u < min(1.0, ratio)
~~~

Leviathan 定理：这个伯努利判定加上拒绝时的残差采样，恰好保持验证模型的分布（0.3 第三幕的六数字手算就是证明骨架）。（核对）参数 `draft_token` 在函数体内未使用——接口为对齐直觉保留，判定只依赖两个概率与随机数。

### 4.2 第 2 步：残差分布（原课代码）

~~~python
# 本块中文说明：残差 = (q - p) 逐元素、负数清零、再归一化。
def residual_dist(q, p):
    raw = [max(0.0, qi - pi) for qi, pi in zip(q, p)]
    s = sum(raw)
    return [r / s for r in raw]
~~~

逐元素相减、负值清零、重归一化；任何拒绝都从这里采样。0.3 第二幕的手算：q=[0.5,0.3,0.2]、p=[0.2,0.3,0.5] → [0.3,0,0] → [1,0,0]。

### 4.3 第 3 步：一次投机步（原课代码）

~~~python
# 本块中文说明：整轮投机——草拟 N 个、一次验证、从左到右裁决。
def spec_step(prefix, q_model, p_model, N, rng):
    drafts = []
    p_probs = []
    ctx = list(prefix)
    for _ in range(N):
        p_dist = p_model(ctx)
        d = sample(p_dist, rng)
        drafts.append(d)
        p_probs.append(p_dist[d])
        ctx.append(d)

    q_dists = [q_model(prefix + drafts[:i]) for i in range(N + 1)]

    for i, d in enumerate(drafts):
        u = rng.random()
        q_prob = q_dists[i][d]
        p_prob = p_probs[i]
        if u < min(1.0, q_prob / p_prob if p_prob > 0 else float("inf")):
            prefix = prefix + [d]
        else:
            res = residual_dist(q_dists[i], p_model(prefix))
            prefix = prefix + [sample(res, rng)]
            return prefix
    prefix = prefix + [sample(q_dists[N], rng)]
    return prefix
~~~

五个被接受 → 一个奖励 → 一次验证前向产出六个 token（原课）。逐行核对（补充）：

- `sample` 是页面未定义的伪接口（按分布采样一个下标），照抄需自行实现；
- `q_dists` 列表推导对 i=0…N 各调一次 `q_model`（共 N+1 次大模型调用）——这是**教学写法**：真实实现把 prefix+全部草稿一次前向，因果结构天然给出每个位置的分布（第一节“串行变并行”正是省在这里）；本教学版把“一次前向”拆成了 N+1 次逐位调用，数学等价、速度不等价；
- 拒绝分支里 `p_model(prefix)` 的 prefix 已含被接受的草稿，恰好是“原前缀+drafts[:i]”这个第 i 步的正确上下文（与 q_dists[i] 对齐，正确）；
- 拒绝即 return：第 i+1 个之后的草稿全部作废（对应 2.1 第 5 步）；
- `prefix + [d]` 反复新建列表，O(N²) 拷贝——教学代码不必计较。

### 4.4 第 4 步：测量接受率（原课文字描述）

原文：在多个草稿质量水平下各跑 10,000 步投机，画接受率 vs 草稿—验证分布 KL 散度的曲线，应看到干净的单调关系（草稿越像验证模型、接受率越高）。数值为原课参考。

### 4.5 第 5 步：验证分布等价（原课文字描述）

原文：经验上，投机循环产出 token 的直方图应与直接从验证模型采样的直方图一致——这是 Leviathan 定理的实践版，卡方检验在采样误差内确认。0.3 第三幕已经用六个数字手工证过一遍。

## 五、把代码运行起来：补充入口与检查

（补充）原课页面没有展示 main.py 全文；以下是我写的最小检查脚本（纯标准库），复核 0.3 的手算并模拟投机步的分布等价。本机已实际运行：

~~~python
# 本块中文说明：复算 0.3 的接受/残差/期望产出（补充，非原课代码）。
import random

def residual_dist(q, p):
    raw = [max(0.0, qi - pi) for qi, pi in zip(q, p)]
    s = sum(raw)
    return [r / s for r in raw]

q, p = [0.5, 0.3, 0.2], [0.2, 0.3, 0.5]
print(residual_dist(q, p))          # 本机输出：[1.0, 0.0, 0.0]（0.3 第二幕）
print("P(reject) =", 1 - sum(min(pi, qi) for pi, qi in zip(p, q)))  # 0.3
for t in range(3):                  # 0.3 第三幕：逐 token 验证分布等价
    via_spec = min(p[t], q[t]) + max(0.0, q[t] - p[t])
    print(t, via_spec, q[t], abs(via_spec - q[t]) < 1e-12)  # 全部 True

alpha = 0.8
print((1 - alpha ** 4) / (1 - alpha))   # 本机输出：2.952（N=3 期望产出）
print(1 + alpha + alpha**2 + alpha**3)  # 同上：另一种数法
print(0.512, 0.2, 0.16)                 # 三档结局概率 α³, 1−α, α(1−α)

# 墙钟对比：大模型 30ms、小模型 3ms
for a, N in [(0.8, 3), (0.5, 3)]:
    et = (1 - a ** (N + 1)) / (1 - a)
    print(f"alpha={a} N={N}: {N*3+30}ms/step -> {et/(N*3+30)*1000:.1f} tok/s "
          f"(naive 33.3) speedup {et/(N*3+30)*30:.2f}x")
# 本机输出：alpha=0.8 -> 75.7 tok/s, 2.27x；alpha=0.5 -> 48.1 tok/s, 1.44x
~~~

## 七、失败模式、原文边界与工程注意

1. 草稿与验证模型不同家族/不同分词器：α 崩到几乎为 0，投机纯倒贴。选草稿第一原则是同家族（原课：same family boosts α significantly）。
2. N 不是越大越好：α 低时多猜的草稿大概率作废，只浪费草稿算力。用 (1−α^{N+1})/(1−α) 对 N 求导找甜点（练习 2），α=0.75 时 N=4—5 附近收益趋平（补充估算）。
3. KV 回滚写错是静默错误：输出看起来正常但缓存里混着未接受 token 的 K/V，长文本后质量缓慢劣化——练习 4 专门练这个，务必做。
4. `spec_step` 的 N+1 次验证调用是教学写法（4.3 核对）：照抄进生产得不到加速，真实实现必须一次前向读出所有位置。
5. 接受率的语境：0.85+ 是聊天基准上的每 token 值；混合生产流量按 0.6—0.8 规划（原课引 Phase 17 · 05），领域流量可能更低——容量规划别拿最好情况当均值。
6. 加速比数字（1.8—4×）都是原课参考：与硬件、批大小、序列长度、α 强相关；批处理大的服务里草稿/验证都吃不满 GPU，投机收益会缩水（补充边界）。
7. 拒绝采样要求 p、q 定义在同一词表上：换分词器的草稿直接失配；数值上 p(d)=0 而 q(d)>0 的 token 会因 p_prob=0 的 ∞ 分支被无条件接受——但这在连续分布上几乎不发生（补充）。
8. 分布等价依赖“验证模型从 q 采样”：若部署时对验证模型用了 top-p/top-k 截断，等价性证明不再严格成立，只能经验验证（补充边界，原课未展开）。

## 十、术语与完成标准

投机解码：小模型草拟、大模型一次验证的无损加速框架；草稿模型：便宜 10—50 倍的提议者；验证模型：分布的最终裁决者；接受率 α：每草稿 token 的接受概率，0.7—0.9 典型；拒绝采样：按 min(1, q/p) 接受的伯努利判定；残差分布：(q−p)₊ 归一化，拒绝时的补发来源；奖励 token：全接受时免费多拿的第 N+1 个；期望产出：(1−α^{N+1})/(1−α) 个 token/轮；Medusa：验证模型上多头并行预测、免第二模型；EAGLE：草稿吃验证模型隐层状态，α 可上 0.85+；前瞻解码：Jacobi 迭代的自我投机、零草稿；树注意力：一次前向验证多条候选分支；KV 回滚：拒绝后退回已接受前缀的缓存操作。

完成检查：

- 能用 0.3 的六数字手算证明“接受+残差”合成分布等于 q。
- 能算 α=0.8、N=3 的期望产出 2.952 并解释 1+Σα^k 的来历。
- 能算三档结局各自产出几个 token、验证几次（第四幕表格）。
- 能解释奖励 token 为什么免费、高温为什么伤 α。
- 能指出 `spec_step` 的 N+1 次验证调用与真实一次前向的差别。
- 能说出四大策略（朴素/Medusa/EAGLE/前瞻）各自的适用场景与参考加速。
