## 零、初学者先读：顺序计算为什么拖垮了RNN

> 2026-11-06 整理的教学补充。首次学习先读本节，再进入后面的公式、原课代码与纠错。本课是第七阶段的第一课：前面第05阶段已经见过序列到序列模型和“注意力机制”这个配件，本课讲为什么 2017 年之后大家干脆把循环网络整个换掉。

### 0.1 先理解这一课在做什么

这一课不训练任何模型，它回答一个“历史题”：2017 年之前，所有做序列（语言、翻译、语音）的最强模型都是循环神经网络（RNN, Recurrent Neural Network）家族——LSTM、GRU 统治了翻译基准整整五年。它们有三个致命弱点：算不快（必须一个词一个词处理）、记不住（远处的信息被一路压缩到消失）、装不下（整句话必须压进一个固定大小的向量）。2017 年的论文《Attention Is All You Need》提出一个激进的方案：彻底扔掉循环，让每个位置同时看所有位置。本课就是把这“三个瓶颈 + 一个解法”讲清楚，后面 15 课的全部内容都建立在这个决定上。

### 0.2 本课术语先翻成白话

- RNN（循环神经网络）=按时间顺序一个一个处理词的网络，每步把“当前词 + 上一步的记忆”压成一个新的记忆
- 隐状态（hidden state）=RNN 的“记忆”，一个固定长度的向量，每读一个词更新一次
- LSTM / GRU=带“门”的改进版 RNN，门决定记住多少、忘掉多少，缓解（但不消除）记忆衰减
- 顺序计算（sequential computation）=第 t+1 步必须等第 t 步的结果，天然无法并行
- 串行深度（serial depth）=一串必须排队完成的操作的最长链条；硬件再强也绕不开它
- 并行（parallelization）=互相不依赖的计算同时做，GPU 的看家本领
- 梯度消失（vanishing gradients）=误差信号往回传时逐层缩小，远处的词几乎学不到东西
- 注意力（attention）=让每个位置给所有位置打分，按分数加权取信息：$\sum_j a_{ij} v_j$
- 上下文窗口（context window）=注意力层一次能“看到”的位置数，内存代价随它平方增长
- 归纳偏置（inductive bias）=架构先天假设数据长什么样：CNN 假设平移不变，RNN 假设“越近越重要”
- 状态空间模型（SSM, state-space model）=参数化得更聪明的现代 RNN（如 Mamba），能并行训练
- 二次瓶颈（quadratic bottleneck）=注意力的内存和计算量随序列长度 N 的平方增长
- token（词元）=模型处理文本的最小单位，一个词或一个词片，本篇说“词”时常与它混用
- 训练墙钟时间（wall-clock time）=现实世界里训练真正花掉的小时数，区别于理论操作数
- epoch（轮）=把全部训练数据完整过一遍；原课说“每个 epoch 快 5–10 倍”用的就是这个词

### 0.3 用小数字走一遍

**（1）5 个词的句子，两边各需要几步。** 句子“我 昨天 在 京都 读书”，切成 5 个词。

- RNN：算第 1 个词的隐状态 h₁ → 用 h₁ 算 h₂ → …… → h₅。**5 步串行**，且后一步必须等前一步，想算 h₅ 就得先算完 h₁ 到 h₄。句子有 1024 个词就是 1024 步排队。

~~~text
RNN 的依赖图（箭头 = “必须先有它才能有我”）：

  x1      x2      x3      x4      x5      （5 个词，本来同时可用）
   ↓       ↓       ↓       ↓       ↓
  h1 ──►  h2 ──►  h3 ──►  h4 ──►  h5     （一条链：深度 = 5）

  时间 →  第1步    第2步    第3步    第4步    第5步
~~~

- Transformer：5 个词两两配对共 5×5=25 个注意力分数，这 25 个打分**互不依赖**，一次矩阵乘法全部同时算完。**1 步并行**。

~~~text
Transformer 的依赖图（25 个格子同时开算）：

       k1    k2    k3    k4    k5
  q1 [  ✓     ✓     ✓     ✓     ✓ ]
  q2 [  ✓     ✓     ✓     ✓     ✓ ]     每个 ✓ 是一个 q·k 打分，
  q3 [  ✓     ✓     ✓     ✓     ✓ ]     25 个 ✓ 互不依赖，一步全出。
  q4 [  ✓     ✓     ✓     ✓     ✓ ]
  q5 [  ✓     ✓     ✓     ✓     ✓ ]

  时间 →  第1步：全部完成
~~~

这就是原课说的“串行深度”：RNN 深度 = N（词数），注意力深度 = 1。

**（2）远处的信息还剩多少。** 假设 RNN 每过一步，旧记忆只保留 90%（衰减系数 0.9）：第 1 个词的信息传到 h₅，要经过 4 次更新，剩 $0.9^4 \approx 0.66$；若每步只保留一半，剩 $0.5^4 = 0.0625$。隔 50 个词、保留 0.9 时剩 $0.9^{49} \approx 0.006$——不到千分之六。这还不是消失，只是“淡化”；真正训练时的梯度消失是连“往哪个方向补救”的信号都一起变没了。

~~~text
每步保留 0.9 时，“我”字的信息沿途存量：
  h1:1.00 → h2:0.90 → h3:0.81 → h4:0.73 → h5:0.66   （5 词句：还剩约三分之二）
  ……隔 50 步：0.9^49 ≈ 0.006                        （长句：几乎归零）
~~~

**（3）固定宽度的瓶子。** 不管句子是 5 个词还是 500 个词，编码器输出都是同一个 512 维（举例）向量。5 个词压进 512 维很宽松；500 个词压进同一个 512 维，就是让 100 倍的内容挤同一个瓶子。翻译模型里解码器开工前能看到的就是这一个向量——信息一旦挤丢了，后面再聪明也捞不回来。

**（4）树状归约把深度从 N 压到 log N。** 就算做 8 个数的求和，也可以不排队：第 1 层同时算 (a+b)、(c+d)、(e+f)、(g+h)，第 2 层同时算两个部分和，第 3 层算总和——8 个数只要 $\log_2 8 = 3$ 层。注意力的“一步全出”是这种思想的极限形态；原课第 2 步要数的“深度”就是这类量。

以上是用于理解的算例，不是新增的训练或性能实测。

### 0.4 怎样连接到正文代码

本课是 Learn 型课，原课的 Build It 不训练神经网络，而是用两个纯 Python 函数做数值模拟：`rnn_style`（像 RNN 一样链式累加，后一步依赖前一步）和 `attention_style`（像注意力一样对全部元素求平均，元素之间互不依赖）。读的时候盯住一件事：两个函数做的加法次数一样多，差别只在“依赖关系”——谁能同时算、谁必须排队。

两个函数分别对应 0.3 节的两幅依赖图：`rnn_style` 的每次循环都在把“上一步的 h”掺进来，这就是链式图；`attention_style` 里没有任何变量跨越两次迭代存活，这就是广播图。学完本课后你可以自己做一个判断题：把 `rnn_style` 里的 `0.9` 换成 `1.0`，依赖结构变了吗？答案在第五节末尾的手算检查里（耗时不依赖系数，链条才是关键；但 0.3 节第 2 幅图的衰减数字会变成“信息永不丢失”）。

### 0.5 理解检查（含参考答案）

**问题1：** GPU 有一万个核心，为什么 RNN 用不上？

**参考答案：** RNN 第 t+1 步的输入是第 t 步的隐状态，1024 个词就是 1024 步必须排队的操作。一万 个核心只能干等着，同一时刻只有一个核心在干活——并行硬件被串行算法浪费了。

**问题2：** 注意力的“串行深度是 1”是什么意思？它不也要算很多次乘法吗？

**参考答案：** 深度数的是“必须排队的链条长度”，不是操作总数。所有 (i, j) 位置对的打分互不依赖，可以填进一个大矩阵一次性算完，链条长度为 1；RNN 的链条长度等于句长。决定墙钟时间的是深度，不只是次数。

**问题3：** Transformer 完胜 RNN，那它自己有没有新的代价？

**参考答案：** 有。注意力的打分矩阵是 N×N，内存随句长平方增长：2K 上下文没问题，128K 就必须上滑动窗口、RoPE 外推、Flash Attention 分块或线性注意力（分别见[第15课](<15：注意力变体——滑动窗口、稀疏与差分注意力.md>)与[第12课](<12：KV缓存与Flash Attention——推理优化.md>)）。RNN 拿内存换时间，Transformer 拿内存换并行。

**问题4：** LSTM 的门控（输入门、遗忘门等）到底解决了三个瓶颈中的哪一个？彻底吗？

**参考答案：** 只针对第二个（梯度消失），且只算“缓解”：门控让网络学会决定记多少、忘多少，为重要信息修了一条“高速公路”，远距离信息不必在每一步都被强行压缩。但它没有碰顺序计算（照样一步一步走）和固定宽度（记忆还是同一个尺寸的向量），而且高速公路本身也会衰减——原课的措辞是 softened but never eliminated。

能讲清这四个问题后，进入正文。

## 一、这一课解决什么问题？

2017 年之前，世界上每一个最先进的序列模型——语言、翻译、语音——都是循环网络。LSTM 和 GRU 在相当于翻译界 ImageNet 的基准上赢了五年，因为那是当时唯一的工具。它们有三个致命弱点：

1. **顺序计算**：无法沿时间轴并行，token t+1 需要 token t 的隐状态。1024 个 token 的序列意味着 1024 次串行步骤，而 GPU 每个周期能做约一百万次浮点操作（原课参考数字）。训练墙钟时间随序列长度线性增长——跑在为并行设计的硬件上，却只能串行。
2. **梯度消失**：50 个 token 之前的信息已经被 50 层非线性压缩过。门控单元（LSTM、GRU）缓和了挤压，但从未消除。“我去年夏天在飞往京都的飞机上读的那本书是……”这类长程依赖经常失败。
3. **固定宽度隐状态**：编码器把整个源序列挤进单个向量，解码器才开工。源序列是 5 个 token 还是 500 个 token 无所谓，瓶颈都是同一个形状。

2017 年论文《Attention Is All You Need》的方案很激进：彻底放弃循环，让每个位置并行地关注所有其他位置，用一次大矩阵乘法代替 1024 次串行计算。到 2026 年，这个结构统治了所有模态：语言（GPT-5、Claude 4、Llama 4）、视觉（ViT、DINOv2、SAM 3）、音频（Whisper）、生物（AlphaFold 3）、机器人（RT-2）。同一块积木，不同的输入。

前置知识（原课标注）：第三阶段深度学习基础、第05阶段第 09 课（序列到序列）、第 05 阶段第 10 课（注意力机制）。如果你对“注意力”这个词还有印象——当时它是**装在 RNN 上**的一个补丁（Bahdanau 2014：让解码器回头看编码器的每个位置）——本课讲的就是把宿主扔掉、只留补丁的那一步。整个第七阶段 16 课都在展开这个决定：[第02课](<02：从零实现自注意力——Q、K、V与缩放点积.md>)从零写注意力、[第03课](<03：多头注意力——并行的视角子空间.md>)多头化、[第04课](<04：位置编码——正弦、RoPE与ALiBi.md>)补上顺序信息、[第05课](<05：完整Transformer——编码器与解码器.md>)总装、[第14课](<14：从零搭一个Transformer——总装课.md>)从零搭完整的 Transformer。

## 二、核心概念与推导

### 2.1 循环本身就是瓶颈

RNN 的定义是 $h_t = f(h_{t-1}, x_t)$：当前记忆 = 函数（上一步记忆，当前输入）。每一步依赖上一步，所以算 $h_5$ 之前不可能算 $h_4$……不对，是算 $h_5$ 之前必须先算完 $h_4$。在现代 GPU 一万多个并行核心上，长序列会让 99% 的硅片闲着（原课参考）。

### 2.2 注意力是一次广播

自注意力（self-attention）计算 $output_i = \sum_j a_{ij} v_j$：第 i 个位置的输出是所有位置 value 的加权和，权重 $a_{ij}$ 来自 i 和 j 的相似度。关键在于：所有 $(i,j)$ 对**同时**算，整个 N×N 注意力矩阵在一次批矩阵乘法里填满，没有任何一步依赖另一步。GPU 最爱这种活。

换个比喻：RNN 像传话游戏——一句话挨个耳朵传下去，传到最后一个人时开头早就走样；注意力像把 5 个人同时拉进一个会议室，任何两个人都能直接对视，5×5=25 条视线一次性建立。（补充比喻，帮助建立直觉；严格的机制定义见[第02课](<02：从零实现自注意力——Q、K、V与缩放点积.md>)。）

### 2.3 加速不是常数，是复杂度等级的改变

- RNN：串行深度 $O(N)$——序列多长，队伍就多长。
- Transformer：串行深度 $O(1)$（并行扫描视角；树状归约则是 $O(\log N)$）。

用 0.3 节的数字感受这个差距的放大效应：

| 序列长度 N | RNN 串行步数 | Transformer 串行深度 |
|-----------:|-------------:|---------------------:|
| 5          | 5            | 1 |
| 512        | 512          | 1 |
| 1,024      | 1,024        | 1 |
| 16,384     | 16,384       | 1 |

差距不是“快几成”，而是“队列长度不再随 N 增长”。原课给出的实测口径：匹配硬件上 N=512 时，Transformer 每个 epoch 训练快 5–10 倍（原课参考），且差距随序列变长继续拉大——直到撞上注意力自己的 $O(N^2)$ 内存墙（Flash Attention 后来缓解了常数，见[第12课](<12：KV缓存与Flash Attention——推理优化.md>)）。

### 2.4 Transformer 付出了什么

注意力内存按 $O(N^2)$ 增长。2K 上下文无所谓；128K 上下文就需要滑动窗口、RoPE 外推、Flash Attention 分块或线性注意力变体（这些武器分别在[第04课](<04：位置编码——正弦、RoPE与ALiBi.md>)、[第12课](<12：KV缓存与Flash Attention——推理优化.md>)、[第15课](<15：注意力变体——滑动窗口、稀疏与差分注意力.md>)展开）。一句话：循环网络时间和内存都是 $O(N)$；Transformer 用内存换时间，再靠并行把时间抢回来。

### 2.5 归纳偏置的转变

RNN 天生假设“局部性”和“越新越重要”；Transformer 什么也不假设——每一对位置都是注意力的候选。这解释了两件事：Transformer 需要更多数据才能训好（没有先验可蹭），但数据够了之后能缩放得更远。Chinchilla（2022）把它形式化：给定足够 token，同等参数量的 Transformer 总能打赢 RNN（原课转述的研究结论）。

### 2.6 2026 年的后续：循环没有死，变成了组件

状态空间模型（SSM，如 Mamba）本质上是参数化得更聪明的 RNN：$O(N)$ 的扫描内存，靠选择性扫描获得并行训练能力，用更少代价恢复 Transformer 约九成的质量（原课参考）。2026 年多数前沿实验室训练的是 SSM+Transformer 混合模型（如 Jamba、Samba）——循环没死，它变成了一个组件。

### 2.7 用小例子把概念串起来（补充）

把 0.3 节的数字对回上面的概念：5 步串行 vs 1 步并行，是 2.1/2.2 的依赖图差别；$0.9^{49} \approx 0.006$ 的衰减，是 2.3 里“梯度消失”的数值化身；“5 个词和 500 个词挤同一个瓶子”，是固定宽度隐状态瓶颈。读原课代码时，把 `rnn_style` 想成 0.3 的第 1 幅图，`attention_style` 想成第 2 幅图即可。

### 2.8 一张对照表收尾（补充）

| 维度 | RNN / LSTM | Transformer（自注意力） |
|------|------------|--------------------------|
| 串行深度 | $O(N)$ | $O(1)$ |
| 每层计算 | N 步矩阵-向量乘 | 几次大矩阵乘 |
| 每层内存 | $O(N)$（隐状态逐个存） | $O(N^2)$（注意力矩阵） |
| 长程依赖 | 逐层衰减，门控只缓解 | 任意两位置一步直达 |
| 归纳偏置 | 局部性、时近性 | 无（每对位置都是候选） |
| 数据需求 | 小数据也能学 | 需要更多数据，但上限更高 |
| 典型失败 | 长句末尾“忘记”开头 | 长上下文内存爆炸 |

这张表是本课的“一页总结”，后续课程（[第02课](<02：从零实现自注意力——Q、K、V与缩放点积.md>)起）逐格兑现右列的每一项。

### 4.1 第 1 步：串行链 vs 并行归约

原课构造两个函数：一个把序列编码成加法链（串行，像 RNN），一个编码成并行归约（广播，像注意力）。**数学相同，依赖图不同。**

~~~python
# 本块中文说明：原课逐字转录。链式累加模拟 RNN 的串行依赖，求和归约模拟注意力的并行独立。
def rnn_style(xs):
    h = 0.0
    for x in xs:
        h = 0.9 * h + x   # can't parallelize: h depends on previous h
        # 中文注释：h 依赖上一轮的 h——就像 RNN 的隐状态，无法并行。
    return h

def attention_style(xs):
    return sum(xs) / len(xs)  # every x is independent
    # 中文注释：每个 x 互不依赖——就像注意力对全部位置同时打分。
~~~

原课把两个函数在最长 100,000 个元素的序列上计时。结论：RNN 版本是 $O(N)$ 的单条 CPU 流水线；即使在纯 Python 里，注意力风格的归约在长度 ≥ 1,000 时也会反超，因为 Python 的 `sum()` 是 C 实现，逐元素迭代没有解释器开销（原课参考）。

对着 0.3 节看这两个函数的对应关系：`h = 0.9 * h + x` 就是“每步保留 0.9”的那条衰减链——`rnn_style([1,0,0,0,0])` 算的正是 $0.9^4$；`sum(xs)/len(xs)` 则把所有元素一视同仁（权重全相同），是最朴素的“广播”。真正的注意力会把“一视同仁”换成“按打分加权”，打分机制在[第02课](<02：从零实现自注意力——Q、K、V与缩放点积.md>)从零搭出来。

（核对/补充：这两个函数做的是“累加”和“平均”，只是依赖结构的示意，不是注意力公式本身；原课自己也说明这是模拟，没有神经网络参与。）

### 4.2 第 2 步：数理论操作

两个算法都做 N 次加法，差别在**依赖深度**（dependency depth）：下一个操作开始之前，必须串行完成的操作有多少个。RNN 深度 = N；注意力深度 = 树状归约的 $\log(N)$，或并行扫描的 1。原课强调：决定 GPU 时间的是深度，不是操作数。（核对：这一步原课没有给出代码，只有这段概念描述，以上为忠实转述。）

### 4.3 第 3 步：长序列上的经验标度

原课打印一张让 $O(N)$ 差距可见的计时表。在 2026 年的 Mac 笔记本上：1,000 以下的序列快到测不出来；100,000 长度显示干净的线性扫描（原课参考）。把这张表外推到“16,384 token 的 Transformer 对比 12 层 LSTM 等价物”，就能理解为什么 2016 年训练墙钟时间是拦路虎（原课参考）。

（核对：本步原课同样只给了文字结论，`code/main.py` 的完整计时表未在课程页展示，本篇不虚构具体毫秒数。）

## 五、把代码运行起来：补充入口与检查

（补充）原课片段依赖 `code/main.py` 的计时脚手架，课程页未完整展示。以下是本篇补充的最小计时入口，只用标准库，可在本机直接运行；输出数值因机器而异，这里只验证“链式随 N 线性变慢、归约稳定地快”这一趋势：

~~~python
# 本块中文说明：补充的最小计时入口（非原课代码），验证两种依赖图的耗时趋势。
import time

def time_it(fn, xs, repeats=3):
    best = float("inf")
    for _ in range(repeats):
        t0 = time.perf_counter()
        fn(xs)
        best = min(best, time.perf_counter() - t0)
    return best

for n in [1_000, 10_000, 100_000]:
    xs = [0.01] * n
    t_rnn = time_it(rnn_style, xs)
    t_att = time_it(attention_style, xs)
    print(f"N={n:>7}  链式 {t_rnn*1000:8.2f} ms  归约 {t_att*1000:8.2f} ms")
# 预期趋势（不预设具体数值）：链式耗时随 N 大致线性翻 10 倍；
# 归约由 C 实现的 sum() 承担，增长平缓得多。
~~~

另一个零成本检查：`rnn_style([1, 0, 0, 0, 0])` 手算应得 $0.9^4 = 0.6561$（h 每步剩 0.9、加的 x 都是 0），正好对应 0.3 节第 2 幅图的衰减数字；`attention_style([1, 0, 0, 0, 0]) = 0.2`。这两个是纸笔可验的断言。

## 六、Use It：使用现成工具

本课没有“调用某个库”的 Use It，而是给出一张决策表：2026 年什么时候还该选 RNN（原课表格的中文整理）：

| 场景 | 选择 |
|------|------|
| 流式推理，一次一个 token，常数内存 | RNN 或状态空间模型（Mamba、RWKV） |
| 超长序列（>100 万 token），注意力内存爆炸 | 线性注意力、Mamba 2、Hyena |
| 没有矩阵乘加速器的边缘设备 | 深度可分离 RNN 在 FLOPs/瓦特上仍占优 |
| 其他一切（训练、批量推理、≤128K 上下文） | Transformer |

配套要点：Mamba 这类 SSM 本质是带结构化参数的 RNN，兼得两头——$O(N)$ 扫描内存 + 选择性扫描带来的并行训练；原课称其恢复 Transformer 九成质量且长上下文缩放更好（原课参考）。2026 年前沿实验室多训 SSM+Transformer 混合模型（Jamba、Samba）——循环是组件，不是主角。

（补充）这张表教的是“什么时候不要跟风”：如果一个任务是“智能音箱每次只听一个词、每词都给响应、内存只有几 MB”，给它上 Transformer 反而是错的——你要的恰恰是流式、常数内存，循环结构或 SSM 正对胃口。架构选择的第一问永远是“我的依赖结构和资源约束是什么”，不是“现在流行什么”。

## 七、失败模式、原文边界与工程注意

1. 把“Transformer 训练快 5–10 倍”当普适常数是误读：这是原课在 N=512、匹配硬件口径下给的经验值（原课参考），差距随序列长度变化，且会被 $O(N^2)$ 内存墙吃掉增长空间。
2. 注意力不免费：N×N 打分矩阵在 128K 上下文是不可接受的内存。工程上必须组合滑动窗口、RoPE 外推、Flash Attention、线性注意力（后续课展开）。
3. “RNN 已死”是误读：流式、超长序列、边缘设备三类场景里循环结构仍是正解；混合架构是 2026 年的主流答案（原课结论）。
4. 纯 Python 计时实验有两个坑（原课自己也点了其一）：小 N 时两个函数都快到测不出差异；`sum()` 的 C 实现让“并行归约”赢了“Python 解释器开销”而不全是赢了“算法结构”。要在心里把这两层分开。
5. 门控（LSTM/GRU）对梯度消失是“软化”不是“根治”：长程依赖失败仍然常规发生（原课措辞 routinely failed）。
6. Chinchilla 的结论有前提：同等参数量、喂够 token；不是“任何 Transformer 任何条件下都赢”。
7. 串行深度是硬下界：哪怕给无限硬件，依赖链上的操作仍要排队——这是并行模型选择时最该盯的量，比 FLOPs 总数更本质（补充：与 4.2 步呼应）。
8. “LSTM/GRU 赢了五年”不等于“它们没问题”：原课的叙事是“唯一可用的工具”带着三个结构性缺陷赢了五年，直到出现不依赖循环的替代品。读史时别把“曾经最强”误读成“没有瓶颈”。
9. 混合架构不是和稀泥：Jamba/Samba 这类 SSM+Transformer 混合是在“注意力的全局视野”与“循环的线性内存”之间做工程折中，各取所长（补充：为[第15课](<15：注意力变体——滑动窗口、稀疏与差分注意力.md>)的变体讨论埋个伏笔）。

## 九、Exercises：保留原课练习与验收方法

1. 原课 Easy：把 `rnn_style` 的标量隐状态换成 64 维向量隐状态，重新计时。串行开销随隐状态维度增长多少？验收标准：能报告至少三个维度（如 1、16、64）下的计时对比，并解释增长来自哪里（每步的向量运算变贵，但串行步数不变——开销应近似线性于维度；若用 NumPy 向量化每步，常数会小很多但步数还是 N）。
2. 原课 Medium：用纯 Python 实现并行前缀和（Hillis-Steele 扫描），验证它与串行扫描在长度 1024 上输出一致，并数出深度。验收标准：两组输出逐元素相等（用断言检查），深度按 $\lceil \log_2 1024 \rceil = 10$ 量级报出并解释；注意纯 Python 的“并行”是模拟——用嵌套列表表示每一层，同一层的格子在概念上同时算。
3. 原课 Hard：把注意力风格的归约移植到 PyTorch 并放到 GPU 上，序列长度从 64 扫到 65,536，对两个版本计时、画图并解释曲线形状。验收标准：能指出曲线上 GPU 被串行链饿死的区段，以及长度增大后并行版的平坦化（或被内存带宽接管的转折），并把曲线形状与依赖深度对应起来；报告中注明哪些数字是本机实测、哪些是推断。

## 十、术语与完成标准

循环（recurrence）：第 t 步依赖第 t−1 步的计算，迫使时间轴上串行；串行深度：依赖操作的最长链，即使在无限硬件上也是墙钟下界；注意力：$\sum_j a_{ij} v_j$，权重来自位置间相似度；上下文窗口：注意力层能接收的位置数，内存按其平方增长；归纳偏置：架构内置的数据假设（CNN=平移不变，RNN=时近性）；状态空间模型：为并行训练而结构化参数化的循环模型；二次瓶颈：注意力内存 $O(N^2)$，Flash Attention 只藏常数不改变量级。

本课关键数字速查（全部来自 0.3 节手算例与原课表述）：

| 数字 | 含义 | 出处 |
|------|------|------|
| 5 步 vs 1 步 | 5 词句子：RNN 串行深度 5，注意力深度 1 | 0.3 算例 |
| $0.9^4 \approx 0.66$ | 5 词句中第 1 词信息传到句尾的存量（每步保留 0.9） | 0.3 算例 |
| $0.9^{49} \approx 0.006$ | 隔 50 个词后同一信息的存量 | 0.3 算例 |
| $\log_2 8 = 3$ | 8 个数树状归约的深度 | 0.3 算例 |
| 5–10 倍 | N=512 匹配硬件上每 epoch 训练加速 | 原课参考 |
| 1024 | 1024-token 序列的 RNN 串行步数 | 原课表述 |

- 能写出 $h_t = f(h_{t-1}, x_t)$ 并解释为什么它禁止并行。
- 能解释“操作数相同、深度不同”为什么导致巨大的时间差，并算出 8 个数树状归约的深度（3）。
