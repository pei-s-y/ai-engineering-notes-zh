## 零、初学者先读：一笔训练预算该怎么分

> 2026-11-06 整理的教学补充。首次学习先读本节，再进入后面的公式、原课代码与纠错。前 12 课都在回答“这个零件怎么造”（自注意力、位置编码、MoE、KV 缓存），从[第14课](<14：从零搭一个Transformer——总装课.md>)开始动手总装；本课先回答一个更上游的问题——同样一笔钱，模型该多大、数据该多少。

### 0.1 先理解这一课在做什么

用装修做比喻：你有一笔固定预算（算力 C），要决定多少钱买家具（参数 N，模型容量）、多少钱请师傅多干几天（训练 token 数 D，把容量练熟）。买太多家具只刷一遍墙（参数多、数据少），家具是空的；家具太少反复打磨（参数少、数据多），房间还是小。经验法则 C≈6ND 说明这笔预算是“此消彼长”的：参数翻倍，数据就得减半。

更深一层看，“缩放定律”回答的是一个实验问题：把 N 和 D 各自放大 10 倍，损失各降多少？答案是一条幂律（power law）——损失按 N^-0.34、D^-0.28 这样的速度下降。知道了这两条曲线，你就能在花钱之前预测“这笔预算最多买到多低的损失、该按什么比例拆成模型和数据”。这就是为什么前沿实验室在训一个模型之前敢押注上千万美元的算力。

这一课的戏剧性在于三个时代给了三个不同答案：

1. **2020 年（Kaplan）**：堆参数。GPT-3 175B 参数只喂 300B token，比例约 1.7。
2. **2022 年（Hoffmann / Chinchilla）**：你们全都训练不足。最优比例约每个参数 20 个 token。
3. **2026 年（Llama 3 时代）**：故意过度训练到 1875 倍——因为推理成本才是大头。

三个答案都对，只是优化目标不同：第一个 optimizing 的是“当时的直觉”，第二个是“每个训练 FLOP 的损失”，第三个是“总拥有成本”。学会分辨“最优”到底最优的是什么，是这一课真正的收获。

### 0.2 本课术语先翻成白话

- 参数 N（parameters）：非嵌入（non-embedding）权重的个数，代表模型容量
- 训练 token 数 D（tokens）：训练时模型见过的 token 总量，代表容量的使用程度
- 算力 C（compute）：训练花的浮点运算次数（FLOPs），近似 C≈6ND
- 6ND 经验法则：每个参数每看一个 token 约花 6 次浮点运算（前向 2 次 + 反向 4 次）
- 缩放定律（scaling law）：损失随 N、D、C 变化的幂律公式
- 幂律（power law）：y∝x^-k 形式的“先快后慢”下降；log-log 图上是直线
- Kaplan 定律（Kaplan et al. 2020）：第一篇缩放定律论文，结论偏向“堆参数”，事后看是欠训练的
- Chinchilla 最优（Chinchilla-optimal）：每个 FLOP 损失最低的分配，约 D/N≈20
- 过度训练（over-training）：D/N 远大于 20，用额外训练算力换推理算力
- 不可约损失 E（irreducible loss）：数据本身的熵，模型再大也降不下去的地板
- 等算力曲线（IsoFLOP curve / profile）：固定 C 后 (N, D) 平面上的预算约束曲线，Chinchilla 论文用它直接测最优
- 涌现能力（emergent capabilities）：某些能力“突然”出现的说法；本课指出多半是度量方式的伪象
- 连续指标 vs 不连续指标（continuous / discontinuous metrics）：交叉熵 vs 精确匹配——前者平滑、后者会制造“假跳变”
- 有效算力（effective compute）：更好的数据/优化器/架构让同样 FLOP 走得更远，相当于把 C 乘了个倍数
- 网格搜索（grid search）：在约束 C=6ND 上枚举 (N, D) 找损失最低点的数值方法
- 数据受限区间（data-constrained regime）：高质量网页 token 总量有限，预训练逼近这个上限后的世界

### 0.3 用小数字走一遍

设预算 C=6×10¹⁸ FLOPs。由 C=6ND 得 ND=10¹⁸，先看三种典型分法（都花光同一笔预算）：

| 分法 | N（参数） | D（token） | D/N | 直觉 |
|---|---|---|---|---|
| 堆参数（Kaplan 风格） | 10¹⁰ | 10⁸ | 0.01 | 超大模型只看一遍小语料 |
| 对半分 | 10⁹ | 10⁹ | 1 | 两头都中等 |
| 堆数据 | 10⁸ | 10¹⁰ | 100 | 小模型反复看大语料 |

代入 Hoffmann 损失（第二节公式，A=406.4、B=410.7、α=0.34、β=0.28、E=1.69）。手算技巧：N=10^k 时 N^0.34=10^(0.34k)，只需一张小表（10^0.06≈1.15、10^0.2≈1.58、10^0.28≈1.91、10^0.48≈3.0、10^0.52≈3.3、10^0.76≈5.8）。例如 (10⁸)^-0.34=10^-2.72=10^-3×10^0.28≈1.91×10⁻³，乘 A≈0.774。

- 堆参数：406.4/(10¹⁰)^0.34 + 410.7/(10⁸)^0.28 + 1.69 ≈ 0.162 + 2.362 + 1.69 ≈ **4.22**
- 对半分：≈ 0.354 + 1.240 + 1.69 ≈ **3.28**
- 堆数据：≈ 0.774 + 0.651 + 1.69 ≈ **3.12**

同样的 6×10¹⁸ FLOPs，“小模型 + 多数据”比“大模型 + 少数据”损失低约 1.1 个 nat。再用 20 倍规则精确定位：N_opt≈0.22×(C/6)^0.5、D_opt≈4.5×(C/6)^0.5。这里 (C/6)^0.5=(10¹⁸)^0.5=10⁹，所以 N_opt≈2.2×10⁸、D_opt≈4.5×10⁹；验算 6ND=6×2.2×10⁸×4.5×10⁹≈5.9×10¹⁸≈C ✓，D/N≈20.5 ✓。把这个点代入损失≈3.10，几乎就是网格搜索的最优值（补充：本机网格枚举验证，见第十一节）。

再做一个“反推预算”的检查（这是工程师真正会问的问题）：Chinchilla 是 70B 参数、1.4T token，它花了多少算力？C=6×7×10¹⁰×1.4×10¹²=5.88×10²³ FLOPs。反过来用 20 倍规则：N_opt≈0.22×(5.88×10²³/6)^0.5≈0.22×3.13×10¹¹≈6.9×10¹⁰≈70B ✓，D_opt≈4.5×3.13×10¹¹≈1.4×10¹²≈1.4T ✓——Chinchilla 恰好站在自己的最优预算上，公式自洽。

现实检查（原课参考）：GPT-3 是 175B 参数、300B token，D/N≈1.7；Chinchilla 是 70B 参数、1.4T token，D/N=20；Llama 3 8B 是 15T token，D/N=1875，是 Chinchilla 的 94 倍。

以上是用于理解的算例，不是新增的训练或性能实测。

### 0.5 理解检查（含参考答案）

**问题1：** 为什么 C≈6ND 里的“参数个数”要排除嵌入层？

**参考答案：** 嵌入矩阵的大小由词表×维度决定，主要做“查表”而不参与每 token 的矩阵乘法主干；把它算进 N 会高估它的算力贡献。缩放定律关心的是“随计算增长的部分”，所以用非嵌入参数计数。

**问题2：** Llama 3 8B 的 D/N=1875 远超 20，是不是“错了”？

**参考答案：** 没错，是目标不同。Chinchilla 最小化的是“每个训练 FLOP 的损失”，训练成本只付一次；Llama 这种要被海量推理调用的模型，推理成本永远在付，所以宁可多训练（8B 在消费级 GPU 上放得下、延迟低），用训练算力换推理算力。

**问题3：** 0.3 里“堆参数”的损失 4.22 中，哪一项在惩罚它？

**参考答案：** B/D^β 项：410.7/(10⁸)^0.28≈2.36，占了总损失（扣除 E 后）的绝大头。参数多而数据少时，“数据不足”项 dominates；反之 N 项惩罚容量不足。

**问题4：** 如果把预算 C 扩大 100 倍，20 倍规则给出的 N 和 D 各扩大多少？

**参考答案：** 都扩大 10 倍——N_opt、D_opt 都正比于 (C/6)^0.5，C×100 → (C/6)^0.5×10。这正是“固定比例”的含义：预算增长时参数和数据同速率增长，D/N 恒为 20。而第三种拟合预测的 0.45/0.55 指数意味着 D 比 N 长得略快，比例缓慢上升。

能解释这四个问题后，进入下面的公式推导。

## 一、这一课解决什么问题？

你有 C 个 FLOPs 的训练算力，想要最好的模型，手里有两个旋钮：参数 N（更大、容量更高）和训练 token 数 D（更多、容量用得更充分）。C≈6ND，推高一个就得压低另一个，哪种更好？

“哪种更好”之所以是个真问题，是因为两种浪费都不直观：参数太多而数据太少，模型“背得下但没东西可背”；数据太多而参数太少，模型“有东西可背但背不下”。两者的损失代价在公式里是两个不同的幂律项（见 2.1），最优解在中间某个比例上——找到这个比例，就是这一课的全部内容。

2020 年前的答案是“猛堆 N”：GPT-3 是 175B 参数、约 300B token，比例约 1.7 token/参数，Kaplan 缩放定律支持这个选择。Hoffmann 等（2022）训练了一小族称为 Chinchilla 的模型，发现最优比例接近 **20 token/参数**——GPT-3 欠训练了 10 倍。Chinchilla（70B 参数、1.4T token）以 2.5 倍更低的推理成本在每个基准上都击败了 GPT-3（175B、300B token）（原课参考）。

2026 年是 Chinchilla 的世界——但有一个重要转折：Llama 3 8B 训练用了 15T token，比例 1875 token/参数，是 Chinchilla 最优的 94 倍。对于要大规模部署的模型，推理成本比训练成本更重要，所以“为了更小的可部署体积而过度训练（past Chinchilla）”是 2026 年的默认做法。

三个时代的决策对照（数值均为原课参考）：

| 时代 | 代表 | (N, D) | D/N | 隐含的优化目标 |
|---|---|---|---|---|
| 2020 | GPT-3 | 175B, 300B | 1.7 | “更大就是更好”的直觉 |
| 2022 | Chinchilla | 70B, 1.4T | 20 | 每个训练 FLOP 的损失最低 |
| 2026 | Llama 3 8B | 8B, 15T | 1875 | 训练 + 推理的总拥有成本最低 |

与前后课的衔接：第 5、7 课搭出了完整 Transformer 与 GPT 的训练目标，本课是“在动手训模型之前先算账”；[第14课](<14：从零搭一个Transformer——总装课.md>)会真刀真枪训一个小模型，那时你会发现“数据 1.1MB、参数 0.8M”这类选择背后正是本课的比例问题；[第12课](<12：KV缓存与Flash Attention——推理优化.md>)讲的推理优化，就是“推理成本很重要”这条线的工程落点。

## 二、核心概念与推导

### 2.1 Hoffmann 损失定律

来自 Chinchilla 论文，损失服从：

$$L(N, D) = \frac{A}{N^\alpha} + \frac{B}{D^\beta} + E$$

- N = 参数（非嵌入）
- D = 训练 token
- α≈0.34、β≈0.28（大致对称）
- E≈1.69，不可约损失的地板
- A≈406、B≈411

直觉：两项“此消彼长”。A/N^α 是容量不足的代价（模型太小记不住规律），B/D^β 是数据不足的代价（容量没被喂饱），E 是数据本身的熵——文本本质上具有不确定性，下一个 token 谁也猜不准的那部分就是 E。训练就是在这个曲面上，沿着“算力预算约束”找最低点。

这个形式和物理里的“两个相反的幂律相加”同构：想象一个 U 形槽，左壁是“模型太小”，右壁是“数据太少”，槽底随预算 C 增大而整体下移、位置缓慢右移。预算约束 C=6ND 不是水平线而是一条双曲线（ND 固定），你只能沿着这条双曲线走，找它扫过 U 形槽时的最低点。

注意公式的幂律形状：损失随 N、D 都是“先快后慢”的下降——参数从 1e8 加到 1e9（10 倍），A 项从 0.774 降到 0.354；再加 10 倍到 1e10，只降到 0.162。收益递减是幂律的本性，也是“什么时候停止加卡”的理论依据。

再注意三个常数各自的角色（补充）：A、B 是“两项相对权重”（本例几乎相等，说明容量与数据同等稀缺）；α、β 是“收益递减的速度”（0.34 意味着参数×10 只把该项降到原来的 46%）；E 是所有曲线共同的渐近线。做敏感性分析时，动 α、β 会改变结论的形状，动 A、B 只改变最优点的位置。

### 2.2 从约束到最优分配

在固定算力 C=6ND 下求 L 的最小值：把 D=C/(6N) 代入，对 N 求导置零。用上面的 α、β 解出来，N 的指数约 0.45、D 约 0.55——所以精确的最优比例随预算缓慢漂移，`code/main.py` 用网格搜索找它。论文的前两种拟合方法（直接测量最优点）给出两个指数都约 0.5，于是得到固定比例的经验规则。把 D=20N 代入 C=6ND：

$$N_{\text{opt}} \approx 0.22 \times (C/6)^{0.5},\qquad D_{\text{opt}} \approx 4.5 \times (C/6)^{0.5},\qquad D_{\text{opt}}/N_{\text{opt}} \approx 20$$

（补充推导：D=20N 时 C=6N×20N=120N²，所以 N=√(C/120)=√(C/6)/√20=0.224×(C/6)^0.5，纯代数；0.22 与 4.5 都是从“比例 20”一个数字推出来的，不是两个独立经验常数。）计算最优：每个参数 20 个 token。

（补充验证：用第三种拟合的常数做精确网格搜索，在 C=6×10¹⁸ 处最优比例约 31，比例-20 的点的损失 3.096 vs 网格最优 3.091，差 0.005 nat——20 倍规则在这个预算下依然接近最优。这正对应原课“精确比例缓慢漂移”的说法。）

### 2.3 为什么 2026 年还要过度训练

Chinchilla 最优最小化的是“每个训练 FLOP 的训练损失”。但训练成本只付一次，推理成本永远在付：一个月服务一万亿 token 的聊天机器人，推理占总成本的大头。Llama 的策略是“训小一点、训久一点”——8B 模型 15T token 是深度推理优化的：能放进消费级 GPU、延迟只有 70B Chinchilla 最优的几分之一、质量对多数任务够用（均为原课参考）。DeepMind 2024 年论文《Over-training is the new optimal》把它形式化：推理主导的工作负载，合适比例更接近 100—500 token/参数（取决于服务量）。

换个角度算（补充算例）：设一个模型部署后总共要被生成 10¹⁴ 个 token，单 token 推理 FLOPs 约等于 2N。70B 模型的终身推理算力≈2×7×10¹⁰×10¹⁴=1.4×10²⁵ FLOPs，是它训练成本（5.88×10²³）的约 24 倍——此时训练端省下的那点算力微不足道，把模型做小（哪怕多花 2 倍训练算力）才是正解。服务量越大，越该过度训练；反过来，一个只跑一次性批处理的离线模型，训练成本就是全部成本，Chinchilla 比例反而是对的。这给了“最优”一个操作性的判据：**先问这个模型要被调用多少次，再问该训多大**。

### 2.4 涌现 vs 平滑

有一种说法：某些能力（算术、多步推理、思维链跟随）在某个规模“突然涌现”。Schaeffer 等（2023）论证这是度量伪象：涌现型指标用不连续打分（精确匹配、阈值化准确率），掩盖了底层 logits 的平滑改进；连续指标（交叉熵）显示的是平滑曲线。举个类比（补充）：水位一直在匀速上涨，但只有漫过每级台阶时“淹没的台阶数”才 +1——台阶计数看起来“涌现”，水位本身是平滑的。2026 年的共识：基于连续损失的预测是可靠的，基准上的跳变多半是打分器伪象。做预算规划要用连续指标。

### 2.5 2026 年的全景

缩放定律仍然有效，但有修正项（原课表格转述）：

| 因素 | 怎么变了 |
|---|---|
| 数据质量 | 精选“好”token（Phi 风格）相当于 >2 倍有效算力 |
| MoE | 总参数与激活 FLOPs 解耦；缩放定律按每激活 FLOP 算（见[第11课](<11：混合专家MoE——稀疏激活.md>)） |
| 后训练 | 指令跟随、代码等能力随 SFT+RLHF 变化比预训练更大 |
| 多模态 | 图像与文本 token 一起缩放；每种模态有自己的曲线 |
| 合成数据 | 模型生成训练数据；有效算力可以复利 |

Muon 优化器（Kimi Moonlight，2024）在同等数据下比 AdamW 有约 2 倍有效算力收益，2026 年的一些训练默认用 Muon——它改变缩放定律的绝对常数，不改变其形状。

### 2.6 把小例串起来（补充）

0.3 节的 C=6×10¹⁸ 算例在正文的对应关系：三种分法的损失值（4.22 / 3.28 / 3.12）来自 2.1 的公式；20 倍规则定位（2.2e8, 4.5e9）来自 2.2 的公式；“堆参数最差”对应 Kaplan 时代 GPT-3 的处境（D/N=1.7）；“堆数据也不是无限好”对应 2.3 的推理成本论证（0.3 的堆数据分法 D/N=100，已经是一种温和的过度训练）。读第四节代码时，把 `chinchilla_loss` 想象成 2.1 的公式化身，把网格搜索想象成在 0.3 的表格里把每一行都填满。

还有一个值得记住的数量关系（补充）：从 0.3 的表格看，比例从 0.01（堆参数）走到 1（对半分）再到 100（堆数据），损失从 4.22 降到 3.12——但请注意这段收益的约 85% 发生在“从 0.01 到 1”这一步（4.22→3.28 贡献了 0.94 nat，全程只有 1.10 nat）。也就是说，只要别犯 Kaplan 式的极端错误，比例在 20—100 之间的具体取值其实相当宽容；真正的悬崖在“数据远少于参数”那一侧。这解释了为什么工程实践中“确保数据够”比“精确调比例”更重要，也解释了为什么 GPT-3 之后整个领域的第一反应是“加数据”而不是“微调比例”。

## 四、Build It：原课分步代码与中文讲解

> （核对）本课为 Learn 型课，课程页面仅展示一个代码块；第 2—4 步是原课对 `code/main.py` 的文字说明，页面未给出代码本体，本节如实转录说明、不虚构代码。Learn 型课的“Build”重在把公式变成可调用的函数，而不是搭工程。

### 4.1 第 1 步：Chinchilla 损失函数（原课代码）

这是全课唯一展示的函数：给定 (N, D) 返回预测损失。常数就是 2.1 节的 A、B、α、β、E。默认参数即论文第三种拟合的数值，调用时不需再传。

~~~python
# 本块中文说明：Hoffmann 缩放定律的损失函数，一行就是 2.1 节的公式。
def chinchilla_loss(N, D, A=406.4, B=410.7, alpha=0.34, beta=0.28, E=1.69):
    return A / N ** alpha + B / D ** beta + E
~~~

原课接着说：把 L 画成固定 C=6ND 下 (N, D) 平面上的等高线图，找最低点。0.3 节的三种分法就是这张图上的三个采样点；等高线沿着“比例 D/N”方向倾斜，最低谷在比例约 20—30 附近。

读图方法（补充）：这张图有两个轴（log N、log D），预算约束 ND=常数在 log-log 图上是一条斜率 −1 的直线，等高线是一族歪椭圆；最优解是直线与最内层椭圆的切点。练习 2 的“损失 vs log10(C)”曲线，就是把每个预算下这个切点的损失值连起来——一条斜率由 α、β 决定的近似直线。

### 4.2 第 2 步：计算最优前沿（原课文字描述）

原文：对从 1e17 到 1e25 FLOPs 的算力预算，求满足 6ND=C 约束下损失最小的 (N, D)，验证比例 D/N≈20。实现方式就是网格搜索：在每个预算下枚举 N（D 由约束反解 D=C/(6N)），取损失最低的点。这一步的教学价值是让你看到“比例随预算缓慢漂移”到底有多慢——跨 8 个数量级的预算，比例只在 20 附近小幅移动。

### 4.3 第 3 步：过度训练的代价（原课文字描述）

原文：计算训练一个 10 倍更小模型（N 取最优的 1/10、D 取 10 倍）要多付多少损失，并报告换来的推理 FLOP 节省（正比于 N）。这是 2.3 节“训练算力换推理算力”的定量版本：损失涨一点点，推理成本降 10 倍。用 0.3 的数字可以预演（补充算例）：在 C=6×10¹⁸ 处取 N=2.2×10⁷（最优 N 的 1/10）、D=4.5×10¹⁰（最优 D 的 10 倍，6ND 仍等于同一笔预算），代入公式得损失≈3.41，比最优的 3.10 高 0.32 nat——注意这是“10 倍过度”在极小预算下的代价，前沿模型在更大数据规模上代价小得多（原课与 DeepMind 2024 的结论）。

### 4.4 第 4 步：对表真实模型（原课文字描述）

原文：代入 GPT-3、Chinchilla、Llama 3 8B、DeepSeek-V3（激活参数）的已知 (N, D)，比较预测损失与报告损失。用 0.3 的手算可以预演：Chinchilla 的 (70B, 1.4T) 代入公式 L≈1.94（补充手算：406.4/(7×10¹⁰)^0.34≈0.083，410.7/(1.4×10¹²)^0.28≈0.164，加 E=1.69）。这是公式预测值，不是任何模型的实测损失；真实模型的报告损失还受数据质量、分词器、训练细节影响，只能期望量级吻合。

## 五、把代码运行起来：补充入口与检查

（补充）原课页面没有可独立运行的完整脚本入口；以下是我写的最小检查脚本（纯标准库），用来复核 0.3 节的算例。脚本分四段：三种分法对比、20 倍规则定位、网格搜索验证、Chinchilla 预算反推。本机已实际运行，输出与 0.3 的表格一致：

~~~python
# 本块中文说明：复算 0.3 节的三种预算分法与 20 倍规则（补充，非原课代码）。
import math

def chinchilla_loss(N, D, A=406.4, B=410.7, alpha=0.34, beta=0.28, E=1.69):
    return A / N ** alpha + B / D ** beta + E

C = 6e18  # 预算：ND = 1e18
for name, N, D in [("堆参数", 1e10, 1e8), ("对半分", 1e9, 1e9), ("堆数据", 1e8, 1e10)]:
    print(f"{name}: N={N:.0e} D={D:.0e} L={chinchilla_loss(N, D):.3f}")
    # 本机输出：堆参数 4.215 / 对半分 3.284 / 堆数据 3.115

# 20 倍规则定位
N_opt = 0.22 * math.sqrt(C / 6)
D_opt = 4.5 * math.sqrt(C / 6)
print(f"rule of thumb: N={N_opt:.2e} D={D_opt:.2e} ratio={D_opt/N_opt:.1f} "
      f"L={chinchilla_loss(N_opt, D_opt):.3f}")
# 本机输出：N=2.2e+08 D=4.5e+09 ratio=20.5 L=3.096

# 粗网格验证：这个预算下真正的最优点在哪里
best = min(((N, chinchilla_loss(N, C / 6 / N)) for N in
            (m * 1e7 for m in range(1, 60))), key=lambda t: t[1])
print(f"grid best: N={best[0]:.2e} D={C/6/best[0]:.2e} L={best[1]:.3f}")
# 本机输出：N=1.8e+08 D=5.6e+09 L=3.091 —— 比例约 31，20 倍规则的点只差 0.005 nat

# 反推 Chinchilla 的预算并核对 20 倍规则
C_ch = 6 * 70e9 * 1.4e12
print(f"Chinchilla budget C={C_ch:.2e}, "
      f"rule N={0.22 * math.sqrt(C_ch / 6):.1e}, "
      f"D={4.5 * math.sqrt(C_ch / 6):.1e}")
# 本机输出：C=5.88e+23, rule N=6.9e+10(≈70B), D=1.4e+12(≈1.4T)，与原课参考值一致
~~~

检查方法：三种分法的损失排序应为 堆数据 < 对半分 < 堆参数；20 倍规则的点应落在网格最优附近（差 <0.01 nat）；Chinchilla 反推的 (N, D) 应回到 70B/1.4T。以上均为本机实际运行的输出（属公式复算，不涉及训练）。运行耗时不到 1 秒，无任何外部依赖。

如果你想进一步实验（补充建议）：把预算 C 换成 1e17、1e20、1e23 各跑一遍，观察网格最优的 D/N 比例如何缓慢上移（0.3 的比例 31 会在更大预算下略降或略升，方向由 α、β 的差决定）；再把 A、B 互换（A=410.7、B=406.4），观察最优点几乎不动——这说明“A≈B”时两项对称，比例主要由 α、β 的差驱动。这两个小实验能把你对公式结构的直觉从“背下来”变成“推出来”。

## 六、Use It：使用现成工具

你多半不会自己训前沿模型，但缩放定律能告诉你三件事（原课）：

1. **微调数据够不够。** 若你的任务数据量低于基座模型的“20 token/参数”水平，预期会在某个损失地板上饱和——继续堆任务数据的收益会先递减后归零，此时该换更大的基座而不是更多的数据。
2. **要不要换更大的基座。** 若预算全花在推理上（服务量大、延迟敏感），优先选更小、训练更久的模型；反之一次性离线批处理选 Chinchilla 最优的大模型更划算。
3. **收益在哪里递减。** 超过 Chinchilla 最优的 1000 倍后，log-loss 的变化就是噪声——再多训练 token 也买不到可测量的质量提升。

三条判据的适用边界（补充）：第 1 条针对“任务适配数据量”，不针对预训练语料；第 2 条要求你能准确估计服务量（估不准时取保守的小模型）；第 3 条的“1000 倍”是数量级经验值，不是精确阈值。

2026 年的研究轨迹（原课）：数据受限区间（高质量英文网页约 5—10T token，前沿预训练正在逼近这个上限，合成数据/多语言/多模态/RLHF 扩展的微调是下一批杠杆）；算力倍增器技巧（Muon、MoE、数据精选——改变绝对常数，不改变渐近线，即“曲线平移、形状不变”）；RL 的缩放定律（开放问题，早期证据显示 RL 样本数也是幂律但指数与预训练很不同）。

## 七、失败模式、原文边界与工程注意

1. 把“D/N≈20”当铁律是最常见的误用：它最小化训练损失，不是部署成本；推理主导的工作负载合理比例是 100—500（原课，DeepMind 2024）。
2. 第三种拟合（α=0.34、β=0.28）推出的精确最优比例随预算漂移（本预算下网格最优约 31）；论文前两种拟合才支持固定 20。用公式前先说清楚自己引用的是哪种拟合（补充，本机网格验证支持）。
3. 比较损失时忽略 E：所有模型共享约 1.69 的地板，谈“损失从 2.0 降到 1.9”时先看可约部分（0.31→0.20 是降了 35%，不是 5%）（补充）。
4. 把“涌现”当规划依据：跳变多半是不连续打分器的伪象，预算规划要看连续指标（原课，Schaeffer 2023）。
5. 6ND 只是近似：它假设标准稠密 Transformer、每个 token 恰好过一遍数据；MoE 要按激活参数算，多 epoch 重复数据也不等于新 token（补充边界，与[第11课](<11：混合专家MoE——稀疏激活.md>)呼应）。
6. 数据质量能移动曲线（Phi 风格 >2 倍有效算力）、Muon 也能（约 2 倍）——这些“倍数”互相不叠加，别拿 4 倍去砍预算（补充提醒）。
7. 微调场景的“20 token/参数”判据指的是任务数据相对基座参数的比例，不是让你去凑预训练比例（原文边界，按原课 Use It 的语境理解）。
8. 缩放定律拟合自英文为主的预训练数据，换语言、换模态时常数 (A, B, α, β, E) 都要重估；直接套用发表常数做决策是隐性失败模式（补充）。

常见误读速查（补充）：

| 听起来对的说法 | 实际情况 |
|---|---|
| “Chinchilla 说必须 20 倍” | 它说的是训练 FLOP 最优；部署还要看推理 |
| “Llama 3 违反了缩放定律” | 它在另一条目标函数（总成本）上取最优 |
| “参数越多越聪明，涌现了” | 连续指标下是平滑改进，跳变是打分伪象 |
| “1e28 FLOPs 就能再降 0.1” | 幂律下这个代价以数量级速度增长（练习 2） |
| “多跑几个 epoch 等于更多数据” | 6ND 里的 D 指新鲜 token，重复见的边际价值递减 |

## 十、术语与完成标准

参数 N：非嵌入权重个数，决定容量；训练 token D：模型见过的 token 总量，决定容量利用程度；算力 C：训练 FLOPs，近似 6ND；6ND：前向 2 + 反向 4 的每参数每 token 运算数；幂律：y∝x^-k 的先快后慢下降，log-log 图上是直线；Kaplan 定律：第一篇缩放定律，偏向堆参数、事后看欠训练；Chinchilla 最优：每个预训练 FLOP 损失最小的 D/N≈20 分配；过度训练：D/N 远大于 20，用训练 FLOPs 换推理 FLOPs；不可约损失 E：数据熵构成的地板；涌现能力：多半是打分器伪象的“突然跳变”；连续指标：交叉熵这类平滑度量，预算规划应基于它；有效算力：数据/优化器/架构带来的训练效率倍数；等算力曲线：固定 C 时 (N, D) 的预算约束；数据受限区间：高质量 token 总量见顶后的训练世界。

完成检查：

- 能写出 C≈6ND 并解释 6 的来源（前向 2 + 反向 4）。
- 能手算 C=6×10¹⁸ 下 20 倍规则给出的 (N, D)（0.3 节算例）。
- 能反推 Chinchilla 70B/1.4T 的训练预算并核对规则自洽（0.3 节算例）。
- 能说出 GPT-3、Chinchilla、Llama 3 三个比例（约 1.7、20、1875）分别代表什么取舍。
- 能解释为什么推理主导的工作负载要过度训练（含终身推理算力的量级比较）。
- 能说出缩放定律公式里 A/N^α 与 B/D^β 各自惩罚什么。
- 能解释“涌现是度量伪象”的论证（不连续打分 vs 连续损失）。
