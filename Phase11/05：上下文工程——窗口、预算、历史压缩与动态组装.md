## 一、模型这次到底能看到什么

假设你要让助手修代码，模型可能需要项目规则、报错、相关代码、之前的讨论和可调用工具。把全部文件都塞进去，既可能超长，也可能把关键线索淹没。

**上下文（context）**指这次调用提供给模型的信息；**上下文窗口**是模型一次处理可容纳的 token 容量。它像当前工作台，不等于整个硬盘，也不等于永久记忆。**提示词工程**主要设计指令表达；**上下文工程**还决定检索什么、保留什么历史、选哪些工具以及怎样排序。

## 二、预算是一道加法题

原课示例：系统规则 500，工具定义 8000，检索资料 4000，历史 6000，当前问题 200，回答预留 4000，总需求 **22700 token**。输入为 18700，输出预留为 4000。不能只看用户问题长度。

示例窗口 32000，预留输出 4000，则输入最多按 28000 来安排；再保留安全余量应对消息封装等额外计数。实际服务可能还有独立输入/输出或推理预算限制，不能只用一个数字概括所有接口。

**Token** 是模型分词器的单位，英文单词数×1.3 只是粗估。中文连续段落 `split()` 可能只算一个“词”，实际 token 很多。计费和超窗检查应使用对应分词器或接口的计数工具及返回 usage。

| 组成 | 内容 | 超预算时怎么处理 |
|---|---|---|
| 稳定指令 | 任务边界、格式、规则 | 去重复，不随意截断关键约束 |
| 工具定义 | 名字、用途、参数 schema | 按任务挑工具，保留完整 schema |
| 检索材料 | 来源段落 | 重排、去重、筛选；保留出处 |
| 历史对话 | 过去问答 | 近期保留，较早压缩成事实与决定 |
| 示例 | 任务示范 | 挑少量相关且正确的 |
| 当前问题 | 用户这次需求 | 优先保留完整，过长时明确拆分 |
| 输出空间 | 给回答留的位置 | 与任务需要匹配，不被资料占满 |

## 三、Lost-in-the-middle 不等于真的“失忆”

该现象指某些任务中，把关键资料放在长输入中部时表现下降。它是特定模型和评测下的经验结果，不是所有模型必然下降固定百分比，也不能直接把正确率变化等同于注意力分数变化。

可尝试把稳定规则放前面、当前问题和最相关资料放后面、较次要内容放中间，并用同题不同位置测试验证。原课的“摆两端”函数把按相关性排序后的 A、B、C、D、E 重排成 A、C、E、D、B，使最相关的 A/B 分别在首尾。它只改变排列，不增加资料真实性。

不要为了缓存或位置偏好改变消息权限：文档中的命令始终是待处理材料，不应提升成系统规则。

## 四、压缩、检索和记忆分别做什么

**截断**只保留一部分文字，快但可能丢条件；**摘要**用更短文字重述，可能遗漏或改错；**关键句抽取**挑原句，较易追溯但不一定最短；**递归摘要**先总结各节再总结这些摘要，适合大文档但误差可能累积。压缩率不是唯一指标，要检查“答案所需信息是否仍在”。

历史摘要应优先保留：用户目标、已确认约束、决定、未完成事项、关键实体和来源。一次错误摘要如果被反复引用，会持续误导后续结果。

**短期记忆**是当前对话状态；**长期记忆**是跨会话保存的稳定事实或偏好；**情节记忆**是某次具体交互记录。后两者需要数据库/文件等外部存储，再在合适时检索给模型；不是模型聊天后自动改了权重。原文提到具体产品只是举例，不能由此推断其未公开的内部实现。

动态组装流程：识别任务→选择工具→检索资料→取相关历史/记忆→选择示例→分配预算→输出完整请求。工具选择也可能错，必须测试“必要工具被删掉”的失败情况。

## 五、原文 Build It 与逐步解释

### 步骤 1：估计token

count_tokens 用词数×1.3估计；count_tokens_json 先序列化对象再估计。这个近似不适合中文精确计费，也没有完整计入消息封装。

````python
# 本块中文说明：估计token
import json
import numpy as np
from collections import OrderedDict

# 通过空白词数粗估 token；不适合中文精确预算或计费。
def count_tokens(text):
    if not text:
        return 0
    return int(len(text.split()) * 1.3)

def count_tokens_json(obj):
    return count_tokens(json.dumps(obj))
````

### 步骤 2：预算分配

available=总窗口−回答预留；allocate在组件上限和剩余空间内裁剪内容并登记。report只画用量，不检查事实是否丢失。

````python
# 本块中文说明：预算分配
class ContextBudget:
    # 初始化本实例保存的配置和状态；self 指当前对象。
    def __init__(self, max_tokens=128000, generation_reserve=4000):
        self.max_tokens = max_tokens
        self.generation_reserve = generation_reserve
        self.available = max_tokens - generation_reserve
        self.allocations = OrderedDict()

    # 在组件上限和总预算内登记内容；正文说明重复分配等边界。
    def allocate(self, component, content, max_tokens=None):
        tokens = count_tokens(content)
        if max_tokens and tokens > max_tokens:
            words = content.split()
            target_words = int(max_tokens / 1.3)
            content = " ".join(words[:target_words])
            tokens = count_tokens(content)

        used = sum(self.allocations.values())
        if used + tokens > self.available:
            allowed = self.available - used
            if allowed <= 0:
                return None, 0
            words = content.split()
            target_words = int(allowed / 1.3)
            content = " ".join(words[:target_words])
            tokens = count_tokens(content)

        self.allocations[component] = tokens
        return content, tokens

    def remaining(self):
        used = sum(self.allocations.values())
        return self.available - used

    def utilization(self):
        used = sum(self.allocations.values())
        return used / self.max_tokens

    # 生成可阅读的统计报告。
    def report(self):
        total_used = sum(self.allocations.values())
        lines = []
        lines.append(f"Context Budget Report ({self.max_tokens:,} token window)")
        lines.append("-" * 50)
        for component, tokens in self.allocations.items():
            pct = tokens / self.max_tokens * 100
            bar = "#" * int(pct / 2)
            lines.append(f"  {component:<25} {tokens:>6} tokens ({pct:>5.1f}%) {bar}")
        lines.append("-" * 50)
        lines.append(f"  {'Used':<25} {total_used:>6} tokens ({total_used/self.max_tokens*100:.1f}%)")
        lines.append(f"  {'Generation reserve':<25} {self.generation_reserve:>6} tokens")
        lines.append(f"  {'Remaining':<25} {self.remaining():>6} tokens")
        return "\n".join(lines)
````

### 步骤 3：资料重排

先相关性排序，再把奇数位/偶数位分别放在首尾。score_relevance是词集合交集占查询词的比例，不是神经模型。

````python
# 本块中文说明：资料重排
def reorder_lost_in_middle(items, scores):
    paired = sorted(zip(scores, items), reverse=True)
    sorted_items = [item for _, item in paired]

    if len(sorted_items) <= 2:
        return sorted_items

    first_half = sorted_items[::2]
    second_half = sorted_items[1::2]
    second_half.reverse()

    return first_half + second_half

# 以词集合重叠计算相关性，仅用于教学。
def score_relevance(query, documents):
    query_words = set(query.lower().split())
    scores = []
    for doc in documents:
        doc_words = set(doc.lower().split())
        if not query_words:
            scores.append(0.0)
            continue
        overlap = len(query_words & doc_words) / len(query_words)
        scores.append(round(overlap, 3))
    return scores
````

### 步骤 4：历史压缩

add_turn存角色与内容；超阈值时移出最老两条并生成截短文本。summaries继续增长，因此需要额外总预算，不能保证真正长期有界。

````python
# 本块中文说明：历史压缩
class ConversationManager:
    # 初始化本实例保存的配置和状态；self 指当前对象。
    def __init__(self, max_history_tokens=5000):
        self.turns = []
        self.summaries = []
        self.max_history_tokens = max_history_tokens

    def add_turn(self, role, content):
        self.turns.append({"role": role, "content": content})
        self._compress_if_needed()

    def _compress_if_needed(self):
        total = sum(count_tokens(t["content"]) for t in self.turns)
        if total <= self.max_history_tokens:
            return

        while total > self.max_history_tokens and len(self.turns) > 4:
            old_turns = self.turns[:2]
            summary = self._summarize_turns(old_turns)
            self.summaries.append(summary)
            self.turns = self.turns[2:]
            total = sum(count_tokens(t["content"]) for t in self.turns)

    def _summarize_turns(self, turns):
        parts = []
        for t in turns:
            content = t["content"]
            if len(content) > 100:
                content = content[:100] + "..."
            parts.append(f"{t['role']}: {content}")
        return "Previous: " + " | ".join(parts)

    # 把摘要与近期消息拼成文本，注意总量仍需限制。
    def get_context(self):
        parts = []
        if self.summaries:
            parts.append("[Conversation Summary]")
            for s in self.summaries:
                parts.append(s)
        parts.append("[Recent Conversation]")
        for t in self.turns:
            parts.append(f"{t['role']}: {t['content']}")
        return "\n".join(parts)

    def token_count(self):
        return count_tokens(self.get_context())
````

### 步骤 5：按任务选工具

工具表带类别和估计长度；classify_intent匹配关键词；select_tools依注册顺序选择能装下的工具，不是最优组合搜索。

````python
# 本块中文说明：按任务选工具
TOOL_REGISTRY = {

        "description": "Execute a shell command",
        "tokens": 140,

    },
    "create_calendar_event": {
        "description": "Create a new calendar event",
        "tokens": 180,
        "categories": ["calendar"],
    },
    "list_emails": {
        "description": "List recent emails",
        "tokens": 160,
        "categories": ["email"],
    },
    "send_email": {
        "description": "Send an email message",
        "tokens": 200,
        "categories": ["email"],
    },
    "web_search": {
        "description": "Search the web for information",
        "tokens": 140,
        "categories": ["research"],
    },
    "query_database": {
        "description": "Run a SQL query on the database",
        "tokens": 170,
        "categories": ["code", "data"],
    },
    "generate_chart": {
        "description": "Generate a chart from data",
        "tokens": 190,
        "categories": ["data", "visualization"],
    },
}

def classify_intent(query):
    query_lower = query.lower()

    intent_keywords = {
        "code": ["code", "function", "bug", "error", "file", "implement", "refactor", "debug", "test"],
        "calendar": ["meeting", "schedule", "calendar", "appointment", "event"],
        "email": ["email", "mail", "send", "inbox", "message"],
        "research": ["search", "find", "what is", "how does", "explain", "look up"],
        "data": ["data", "query", "database", "chart", "graph", "analytics", "sql"],
    }

    scores = {}
    for intent, keywords in intent_keywords.items():
        score = sum(1 for kw in keywords if kw in query_lower)
        if score > 0:
            scores[intent] = score

    if not scores:
        return ["code"]

    max_score = max(scores.values())
    return [intent for intent, score in scores.items() if score >= max_score * 0.5]

# 按任务分类选工具并检查预算，不自动验证业务授权。
def select_tools(query, token_budget=2000):
    intents = classify_intent(query)
    relevant = {}
    total_tokens = 0

    for name, tool in TOOL_REGISTRY.items():
        if any(cat in intents for cat in tool["categories"]):
            if total_tokens + tool["tokens"] <= token_budget:
                relevant[name] = tool
                total_tokens += tool["tokens"]

    return relevant, total_tokens
````

### 步骤 6：组装与演示

重置预算，依次登记规则、工具、检索、历史和问题。代码主要验证分配报告，真实请求必须保留各次allocate的content并形成消息，不能只把budget对象发给API。

````python
# 本块中文说明：组装与演示
class ContextEngine:
    # 初始化本实例保存的配置和状态；self 指当前对象。
    def __init__(self, max_tokens=128000, generation_reserve=4000):
        self.budget = ContextBudget(max_tokens, generation_reserve)
        self.conversation = ConversationManager(max_history_tokens=5000)
        self.system_prompt = (
            "You are a helpful AI assistant. You have access to tools for "
            "code editing, file management, web search, and data analysis. "
            "Use the appropriate tools for each task. Be concise and accurate."
        )
        self.knowledge_base = [
            "Python 3.12 introduced type parameter syntax for generic classes using bracket notation.",
            "The project uses PostgreSQL 16 with pgvector for embedding storage.",
            "Authentication is handled by Supabase Auth with JWT tokens.",
            "The frontend is built with Next.js 15 using the App Router.",
            "API rate limits are set to 100 requests per minute per user.",
            "The deployment pipeline uses GitHub Actions with Docker multi-stage builds.",
            "Test coverage must be above 80% for all new modules.",
            "The codebase follows the repository pattern for data access.",
        ]

    def assemble(self, query):
        self.budget = ContextBudget(self.budget.max_tokens, self.budget.generation_reserve)

        system_content, _ = self.budget.allocate("system_prompt", self.system_prompt, max_tokens=1000)

        tools, tool_tokens = select_tools(query, token_budget=2000)
        tool_text = json.dumps(list(tools.keys()))
        tool_content, _ = self.budget.allocate("tools", tool_text, max_tokens=2000)

        relevance = score_relevance(query, self.knowledge_base)
        threshold = 0.1
        relevant_docs = [
            doc for doc, score in zip(self.knowledge_base, relevance)
            if score >= threshold
        ]

        if relevant_docs:
            doc_scores = [s for s in relevance if s >= threshold]
            reordered = reorder_lost_in_middle(relevant_docs, doc_scores)
            doc_text = "\n".join(reordered)
            doc_content, _ = self.budget.allocate("retrieved_context", doc_text, max_tokens=3000)

        history_text = self.conversation.get_context()
        if history_text.strip():
            history_content, _ = self.budget.allocate("conversation_history", history_text, max_tokens=5000)

        query_content, _ = self.budget.allocate("user_query", query, max_tokens=500)

        return self.budget

    def chat(self, query):
        self.conversation.add_turn("user", query)
        budget = self.assemble(query)
        response = f"[Response to: {query[:50]}...]"
        self.conversation.add_turn("assistant", response)
        return budget


# 运行该部分示例并展示结果；函数定义后还需调用才会产生输出。
def run_demo():
    print("=" * 60)
    print("  Context Engineering Pipeline Demo")
    print("=" * 60)

    engine = ContextEngine(max_tokens=128000, generation_reserve=4000)

    print("\n--- Query 1: Code task ---")
    budget = engine.chat("Fix the bug in the authentication module where JWT tokens expire too early")
    print(budget.report())

    print("\n--- Query 2: Research task ---")
    budget = engine.chat("What is the best approach for implementing vector search in PostgreSQL?")
    print(budget.report())

    print("\n--- Query 3: After conversation history builds up ---")
    for i in range(8):
        engine.conversation.add_turn("user", f"Follow-up question number {i+1} about the implementation details of the system")
        engine.conversation.add_turn("assistant", f"Here is the response to follow-up {i+1} with technical details about the architecture")

    budget = engine.chat("Now implement the changes we discussed")
    print(budget.report())

    print("\n--- Tool Selection Examples ---")
    test_queries = [
        "Fix the bug in auth.py",
        "Schedule a meeting with the team for Tuesday",
        "Show me the database query performance stats",
        "Search for best practices on error handling",
    ]

    for q in test_queries:
        tools, tokens = select_tools(q)
        intents = classify_intent(q)
        print(f"\n  Query: {q}")
        print(f"  Intents: {intents}")
        print(f"  Tools: {list(tools.keys())} ({tokens} tokens)")

    print("\n--- Lost-in-the-Middle Reordering ---")
    docs = ["Doc A (most relevant)", "Doc B (somewhat relevant)", "Doc C (least relevant)",
            "Doc D (relevant)", "Doc E (moderately relevant)"]
    scores = [0.95, 0.60, 0.20, 0.80, 0.50]
    reordered = reorder_lost_in_middle(docs, scores)
    print(f"  Original order: {docs}")
    print(f"  Scores:         {scores}")
    print(f"  Reordered:      {reordered}")
    print(f"  (Most relevant at start and end, least relevant in middle)")
````


## 六、运行和代码核对

安装 numpy 后，在本课目录运行 `python code/main.py`。虽然计数本身不需要 NumPy，仓库文件有该导入。会看到预算条形报告、文档重排、历史压缩、按问题选择工具、完整组装和词重叠相关性 demo。它不调用大模型。

重点读这些细节：

- `ContextBudget.allocations` 只记录各组件 token 数，`allocate` 返回截断后内容；完整应用必须保存并真正传入这些返回值。原 `ContextEngine.assemble` 最终主要返回预算对象，未发送完整 API 请求。
- `max_tokens` 与 `generation_reserve` 是总窗口和输出预留；需要验证预留非负且小于总量。
- 原 `allocate` 对已存在的同名组件再次分配时，会先把旧值也算进 used，可能重复占预算；更新前应扣除旧组件。
- 历史压缩 `_summarize_turns` 是截前 100 字符，不是模型摘要；旧摘要还会持续累积，不能保证整个 get_context 永远不超限。
- `chat` 先把当前 query 加进历史，再单列 user_query，可能重复计数。应先组装旧历史和当前问题，再存本轮消息。
- `select_tools` 用手填估算 token，而组装时只统计工具名字列表，不等于真实工具 schema 的 token 成本。
- `score_relevance` 是词集合重叠，不是神经语义相似度；`classify_intent` 没匹配时默认 code，可能给不相关问题选择错误工具。
- 按英文空格截断 JSON 或工具定义可能破坏结构；真实系统应按完整组件裁剪，而不是随意剪字符串。

补充预算算例：

```python
window = 32000
reserve = 4000
components = {"rules":500, "tools":8000, "docs":4000,
              "history":6000, "query":200}
used = sum(components.values())
remaining = window - reserve - used
assert remaining >= 0

```

## 七、应用、交付物与五项练习

代码助手的按需文件加载、知识助手的检索、跨会话偏好存储，都可用本课框架理解。RAG 是上下文工程的一种实现；第 15 课的稳定前缀缓存是在此基础上减少重复输入计算。

对应原文交付物，在笔记内写“上下文方案审查卡”：窗口/预留、各组件上限、优先级、截断策略、去重策略、记忆更新规则、验证样例。不要只写“更多上下文更好”。

1. **浪费检测**：标记占预算超过 30% 的组件，但不直接判定它浪费；检查其贡献，分别提出摘要、工具裁剪和文档重排。
2. **语义去重**：对相似度超过 0.8 的片段保留较高分者；阈值是实验参数。两个几乎相同的条款可能版本或数字不同，不能误删关键差异。
3. **对话回放**：逐轮记录各组件用量和压缩时刻，画出变化；还要检查历史摘要累积后的总量。
4. **工具打分排序**：按相关性选入预算，比较 5/10/20/50 个工具的选择准确率、任务完成率、耗时，而非只看 token 减少。
5. **三种压缩对照**：20 篇文档分别截断、摘要、关键句抽取，记录压缩比与问题答案保留率；低 token 但答不出问题不算成功。

自测：把历史写进数据库后，模型下次会自动知道吗？不会，还需要检索/加载进这次输入。为什么“计数未超限”也可能无法回答？关键依据可能被截掉，或模型没有效利用它。
