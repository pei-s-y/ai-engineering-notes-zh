# 00A：LLM 应用入门预备课——API、JSON、向量与状态

> 这篇是补充预备课，不是原课程单独的一课。面向会基础 Python、尚未完整做过项目的学习者。不要求先把所有框架安装一遍。

## 一、第十章和第十一章分别在做什么

第十章偏向模型内部：文本怎样变 token，Transformer 怎样算，训练怎样更新权重，推理怎样输出。第十一章偏向应用：怎样把一个已有模型、文档、工具和软件流程连接成可靠服务。LoRA 一课仍涉及训练，但多数课不从零训练大模型。

**模型**是把输入映射到输出的计算系统；**应用**还包含界面、数据、权限、接口、错误处理、存储和评估。用户看到“助手能查资料”，不等于模型权重里记住了所有资料，而可能是应用先检索再提供给它。

## 二、一个普通函数到一次 API 请求

本地函数 `add(2,3)` 在当前程序里执行。API 请求通常把参数发送给另一个进程/服务，等待结果，可能遇到网络超时、认证失败、速率限制、服务错误。**客户端**发请求，**服务端**处理请求；两者都可以在同一台电脑，也可以分开。

SDK 只是方便调用 API 的库。`client.xxx.create(...)` 是 SDK 方法，不代表本地模型，也不代表免费。`response.xxx` 是从响应对象读字段，具体字段由接口定义。

常见状态：200 类是成功；400 类是请求/权限/限流等问题，429 常见于限流；500 类通常表示服务端错误。不能把所有错误都当网络不好，也不能无条件重复提交有副作用动作。

## 三、字典、JSON、Schema 和类型提示

```python
import json

item = {"name":"耳机", "price":348, "available":True}
text = json.dumps(item, ensure_ascii=False)  # 对象序列化为JSON文本
restored = json.loads(text)                # JSON文本解析回对象
assert restored == item
print(restored["price"])                   # 预期348
```

键是字段名，值可能是字符串、数字、列表或对象。`obj["price"]` 是读取字典字段；`obj.get("price")` 在字段缺失时默认返回 None。`**args` 在函数调用中把字典展开为命名参数。

Schema 是规则，不是数据。例如“price 必须是非负数字”；类型提示 `price:float` 帮助工具检查代码，但普通 Python 类型标注本身一般不会在运行时强制验证。Pydantic 等库才负责相应的数据解析/验证。

**序列化**使程序对象能存储/传输；**反序列化**恢复可处理结构。合法 JSON 不等于业务正确，也不等于来源真实。

## 四、读 Python 项目时常见语法

| 写法 | 初学者理解 |
|---|---|
| `class X` | 把状态和操作组织在一起的类型 |
| `self.items` | 这个实例保存的数据，通常跨方法保留 |
| `__init__` | 创建实例时初始化数据 |
| `@dataclass` | 自动生成初始化/表示等样板方法 |
| `@tool` | 装饰器把函数包装成框架能识别的工具 |
| `if __name__ == "__main__"` | 直接运行文件时才执行下面的demo |
| `yield` | 分次产出结果，调用方逐项消费 |
| `async def / await` | 声明异步过程，等待时让出事件循环 |
| `try / except` | 处理特定失败，不能靠吞掉所有错误装作成功 |
| `lambda x:...` | 简短匿名函数，常用来指定排序键 |
| `zip(a,b)` | 两序列逐对遍历，长度不等时默认截到较短者 |

函数“已经定义”不表示“已经调用”；最后没调用 demo 就不会自动打印。变量叫 `confidence`、`semantic`、`production` 不证明程序真的实现了概率、语义理解或生产能力，要看具体计算。

## 五、向量和相似度无需先学完整线性代数

向量是有顺序的一列数字，如 [3,4]，长度为5；矩阵是多行向量排列。**维度**在本文通常指向量元素数；**shape**描述数组各轴长度。

查询向量 q 和文档向量 d 做点积、余弦或距离，得到排序分数。一个3维模型的坐标与另一个3维模型不一定相同，维数一致只是最低条件。相似度0.9不代表“90%事实正确”，只是当前度量下的相近程度。

**Embedding** 是数值表示；**检索**是从现有集合找内容；**生成**是模型产出新文本；**训练**是更新参数。四者可以连接，但不能混为一谈。

## 六、把本章串成一个知识问答系统

用户问题→检查输入→查询文档→取相关片段→与规则组成提示→调用模型→检查结构和证据→返回答案。重复问题可以查缓存，模型可请求工具，复杂任务可存状态并暂停，系统变更用评估集比较。

这里：提示词是任务说明，RAG是找证据，工具调用是请求外部动作，MCP是工具通信约定，状态图是执行流程，评估是检查质量。把框架名字暂时拿掉，这条数据流仍然成立。

## 七、五个特别容易混淆的词

**上下文**是这次输入；**长期记忆**是外部保存后再检索的内容；**模型参数**是训练学到的数值；**缓存**是避免重复计算或复用答案；**检查点**是保存执行/训练状态方便恢复。本章 Agent 检查点与第十章梯度检查点（激活重计算）是不同概念。

**状态无状态**也要看对象：HTTP/MCP 无状态不等于业务不能保存订单；API调用默认不记历史不等于应用不能每次补历史。

## 八、怎样做一次可信的小实验

1. 写清问题：例如“混合检索是否改善精确错误码查询”。
2. 固定文档和10个问题，标出正确证据。
3. 只改一个组件，其余参数相同。
4. 保存输出、分数、错误、版本、运行时间。
5. 报告失败，不预设新方法一定赢；扩大数据前先检查边界。

**预期输出**是代码逻辑推导的结果；**实际验证**是本次确实运行观察到的结果；**模拟输出**可以确实运行但仍不代表真实模型能力。三种标记可能同时存在：一个“已实际运行的模拟器”仍只是模拟器。

阅读每课时用四问：它接收什么？它输出什么？里面哪一步真的用了模型？失败怎样判断？能自己用一个小输入回答这四问，比记住一串英文名称更有用。
