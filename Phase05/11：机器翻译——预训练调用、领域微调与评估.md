## 零、初学者先读：翻译不是换词，是换一句完整的话

> 2026-11-06 新增的教学补充。首次学习先读本节，再进入后面的公式、原课代码与纠错。第09、10课搭好了“读句子→对齐→写句子”的机器，本课把它开进第一个真实任务：翻译。后面第12课摘要、第13课问答会反复借用这里的评估与流水线思路。

### 0.1 先理解这一课在做什么

逐词查词典式翻译注定失败：英语“我想你”译成法语是tu me manques，字面竟是“你缺我”（原课例）——没有任何词对词的对应能活下来。现代机器翻译（MT）不是查词典，而是第10课那种“整句读入、对齐、逐词写出”的生成机器。本课不再从头训练，而是学会**使用**2026年的现成机器：怎么调用（语言标记）、怎么评估（BLEU/chrF）、怎么在领域数据上微调、上线后查哪些错。

类比：前两课学的是发动机原理，本课学开车——车是预训练好的NLLB，要学的是仪表盘（语言标记）、质检（BLEU）、改装（微调）和路检清单（生产错误分类）。发动机坏了你会修（第09、10课），但不会开车照样上不了路。路检清单先混个眼熟（第七节会逐条展开）：

- 内容捏造：译文流畅但说了源文没有的事；
- 错目标语言：英→法翻出了德语；
- 术语漂移：同一术语前后译法不一致；
- 语域错位：该用敬语的地方用了口语；
- 长度异常：译文比合理比例长太多或短太多（报警信号，不自动等于错误）。

### 0.2 本课术语先翻成白话

- NMT（neural machine translation，神经机器翻译）=编码器-解码器式的翻译模型
- 平行语料 parallel corpus=一句源文配一句标准译文的对齐语料
- NLLB=No Language Left Behind，Meta的200语言翻译模型家族
- src_lang／forced_bos_token_id=NLLB的两个“语言开关”：告诉分词器源文按哪种语言切、强制解码器从哪种语言开始写
- tokenizer（分词器）=把文本切成模型词表里的子词单位（第04课BPE的用武之地）
- 假设 hypothesis=模型产出的候选译文
- 参考 reference=人工标准译文，评估的对照物
- BLEU=n-gram精确率几何平均×短译惩罚的自动评分，sacrebleu报0～100
- n-gram=连续n个词，1-gram就是单个词
- 截断计数 clipping=同一个词最多按参考中出现的次数计匹配
- 短译惩罚 brevity penalty（BP）=译文比参考短太多时的扣分项
- chrF=字符级n-gram的F分数，对词形变化丰富的语言更友好
- 领域微调 fine-tuning=在领域平行句上继续训练预训练模型
- 术语漂移 terminology drift=同一术语在两篇译文里译法不一致
- 语域 register=语言的正式程度，如法语的tu／vous之别
- 占位符 placeholder=UI字符串里{name}这类不能被翻译破坏的变量
- 回译 back-translation=把译文再翻回源语言，检查语义保留的辅助手段

### 0.3 用小数字走一遍

BLEU 1-gram精确率（真实BLEU是1～4-gram精确率的几何平均再乘BP，这里先拆最小零件）。参考译文“the cat sat on the mat”（6个词），候选“the cat sat on a mat”（6个词）：

~~~text
候选6个词，能对上参考的：the、cat、sat、on、mat（a在参考里没有）
1-gram精确率 = 5/6 ≈ 0.833
~~~

截断计数的作用：参考里the出现2次，候选若写the、the、the，也只能匹配min(候选次数, 参考次数)=2次——防止靠重复高频词刷分。再看短译惩罚：候选“the cat on the mat”只有5个词，每个都能对上（the截断计2），1-gram精确率5/5=1.0，但它比参考短——BP = e^(1−6/5) = e^(−0.2) ≈ 0.819，满分被砍掉近两成：只译一半拿不了高分。一句话记住BLEU的脾气：**对得全不够，还不能偷工减料**（本机Python已复核：0.833与0.819）。

以上是用于理解的算例，不是新增的翻译或评分实测。

### 0.4 怎样连接到正文代码

4.1是完整调用样例：src_lang="eng_Latn"设源语言，generate里的forced_bos_token_id强制从法语标记开始写——两个开关都拨对，才得到Les chats courent.。4.2对应0.3：corpus_bleu(hypotheses, references)里references要嵌套成[[参考]]，每个内层列表是同一句的一组参考译文流——嵌套形状错是最常见的接口事故。4.3的三层评估给0.3的数字定位：BLEU只是最底层的表面重叠，COMET等学习式指标和LLM裁判在其上。4.5的微调代码对应“改装”：text_target=...生成labels、PAD改-100。第七节的错误分类（内容捏造、错目标语言、术语漂移、语域、长度异常）就是路检清单——0.1类比的最后一件。

### 0.5 理解检查（含参考答案）

**问题1：** 为什么重复写the刷不高BLEU？

**参考答案：** n-gram精确率做截断计数：每个词的匹配数不超过它在参考中出现的次数；the在参考里只有2次，写10次也只计2次，而分母（候选总词数）还在涨。

**问题2：** 候选比参考短，为什么除了精确率还要有BP？

**参考答案：** 精确率的分母是候选自己的长度，译得越短越容易全对——不惩罚短译，模型会学会只译最有把握的半句。

**问题3：** src_lang和forced_bos_token_id是不是重复设置？

**参考答案：** 不重复。前者管输入侧（分词器按哪种语言的规则切源文），后者管输出侧（解码器第一个强制生成的目标语言标记）；只设一个，另一侧就可能走错语言。

## 一、这一课解决什么问题？

翻译把可变长源序列映射到目标语言，词序、习语与信息对应关系不同。本课关注可操作流水线：语言代码、配套分词器、生成参数、参考指标和上线错误检查，而不是词对词替换。

## 二、核心概念与推导

源文本→模型配套tokenizer与源语言标识→encoder→decoder cross-attention→目标子词→detokenize。NLLB的eng_Latn/fra_Latn是语言与文字系统标记，不是普通英语缩写。

（补充 2026-11-06）**流水线逐站读。** 这条链正是第09、10课机器的成品形态：

- tokenizer把源文切成子词（第04课BPE路线的落地）；
- encoder读入（第09课编码器）；
- decoder每写一个词经cross-attention回看源文全部位置（第10课）；
- 写出目标子词后再拼回文本。

两处新手易错：

- 语言标记eng_Latn是“语言_文字系统”的格式（英语_拉丁字母），不是随便的缩写，NLLB、mBART、M2M-100各家的约定互不通用——把一家的标记喂给另一家，轻则报错重则静默走错语言；
- 配套也包含“tokenizer必须与模型同源”：用A家的tokenizer切词、B家的模型读，词表编号对不上就是乱码。

BLEU用n-gram精确率的几何平均与短译惩罚；sacrebleu通常报告0～100，别和某些实现的0～1混用。chrF基于字符n-gram的precision/recall/F分数，对词形变化较敏感。需要说明参考译文、tokenization、大小写和评估签名。

（补充 2026-11-06）**BLEU三件套的分工（对应0.3）。** 完整BLEU = 1～4-gram精确率的几何平均 × BP。四个读法：

- 几何平均的脾气是“一票否决”：任何一阶精确率为0，整体直接归0——所以单句、短句的BLEU离不开平滑，4.2中文说明里“完全相同也不要机械要求默认corpus BLEU必为100”的根源就在这里（短句凑不出4-gram）；
- 为什么要四阶一起看：1-gram管“词对不对”，4-gram管“语序顺不顺”——只看1-gram，词全对但顺序稀烂的译文也拿满分；
- sacrebleu的意义是统一分词与文本处理（Post 2018的呼吁），让不同论文的分数可比——自己手搓BLEU正是“误导性基准”的常见来源；
- chrF把单位从词换成字符：德语、捷克语这类一个词七八种变化的语系里，词级匹配太苛刻、字符级还能认出“词形对了大半”。

评价三层：BLEU/chrF等表面重叠；COMET等学习式评价；人工或LLM按充分性、流畅性、语域等rubric打分。各指标所需source/reference不同；“reference-free”不是所有COMET/BLEURT配置都自带的属性。

（补充 2026-11-06）**三层评价对照表。**

| 层 | 代表 | 快慢 | 需要参考译文吗 | 长处／短处 |
|---|---|---|---|---|
| 表面重叠 | BLEU、chrF | 快 | 需要 | 可复现、可解释；对同义改写失明 |
| 学习式 | COMET、BERTScore | 中 | 多数需要 | 跟人工判断更相关；本身是模型，有偏差 |
| LLM裁判 | GPT-4等打分 | 慢、贵 | 可不用（reference-free） | 能评流畅/语域/文化；稳定性依赖rubric与版本 |

三层的分工像体检：BLEU是量体温（快、粗、可追踪），COMET是验血（精细但设备有偏差），LLM裁判是专家会诊（最贵最全面，也要校准）。原课的实操建议（思路参考）：任何一层用之前，都先在50～100条人工标注样本上校准；“80%一致率”类数字是原课参考，不是本笔记实测。这也是第七节第1条“BLEU 30/40/50不能跨语言、语料、分词当统一等级”的原因——同一个数字在不同语料上的含义完全不同。

（补充 2026-11-06）**微调那一小步为什么值得。** 预训练模型是泛用译者，法律、医疗、游戏文案的术语风格它没见过；几千条高质量领域平行句的继续训练，胜过几十万条噪声网页对（原课观点：数据质量是最大的生产杠杆）。4.5代码里两个细节别放过：

- text_target=...让tokenizer顺手生成labels；
- padding="max_length"补的PAD若不改成-100，模型会把“学预测PAD”也当任务——第五节的补充核对就是检查这一行有没有做对。

（补充 2026-11-06）**回译检查的能与不能（对应第九节Easy练习）。** “英→法→英”把译文再翻回源语言，对比与原文的差异：

- 能暴露明显的信息丢失、数字错译和词选漂移；
- 但两个方向的模型可能共享同种偏差（第七节第3条），回译相似不等于原译完全正确；
- 所以它只作辅助信号，不能替代人工审查或学习式指标。

### 2.9 用一个小例子把概念串起来（补充）

一句英文送NLLB英→法时，tokenizer要有源语言配置，generate要有目标语言标记。得到法语后先核对人物、日期、否定和{name}等变量，再看BLEU/chrF。即使句子很流畅，June误成July仍是事实错误；即使表达与参考不同，也可能正确，因此自动指标和人工审查各有职责。

## 四、Build It：原课分步代码与中文讲解

### 4.1 调用预训练NLLB

src_lang设源语言，forced_bos_token_id约束生成的目标语言标记。num_beams与length_penalty控制搜索，不是训练。原文法语句子是参考，实际输出受模型版本与设置影响。模型.eval与无梯度有助于明确推理语义。

~~~python
from transformers import AutoTokenizer, AutoModelForSeq2SeqLM

model_id = "facebook/nllb-200-distilled-600M"
tok = AutoTokenizer.from_pretrained(model_id, src_lang="eng_Latn")
model = AutoModelForSeq2SeqLM.from_pretrained(model_id)

src = "The cats are running."
inputs = tok(src, return_tensors="pt")

out = model.generate(
    **inputs,
    forced_bos_token_id=tok.convert_tokens_to_ids("fra_Latn"),
    num_beams=5,
    length_penalty=1.0,
    max_new_tokens=64,
)
print(tok.batch_decode(out, skip_special_tokens=True)[0])
~~~

~~~text
Les chats courent.
~~~

### 4.2 BLEU与chrF

references外层是一组参考译文流，每条流与hypotheses对齐；不是把每个句子随意嵌套。单句且不足4-gram的BLEU可能受有效阶数与平滑设置影响，即使完全相同也不要机械要求默认corpus BLEU必为100；chrF的表现约定另看接口。

~~~python
import sacrebleu

hypotheses = ["Les chats courent."]
references = [["Les chats courent."]]

bleu = sacrebleu.corpus_bleu(hypotheses, references)
chrf = sacrebleu.corpus_chrf(hypotheses, references)
print(f"BLEU: {bleu.score:.1f}  chrF: {chrf.score:.1f}")
~~~

### 4.3 三类评价与校准

原文列传统指标、学习指标和LLM裁判，均需在你的语言/领域人工样本上核对。原文COMET排名、80%一致率及“生产默认”无本次复现实验支持；不是一套工具名就能消除评估偏差。



### 4.4 生产错误分类

分别检查内容捏造、目标语言错误、术语不一致、礼貌/语域和长度异常。输出长度异常只是报警信号，不能自动证明幻觉；只靠输入长度比例也可能误伤合法扩写语言。



### 4.5 领域微调

原文只有一条平行句，是接口草图不是可用训练集。tok(text_target=...)会产生labels，但需明确目标语言，并把目标PAD改为-100以免把PAD当训练目标。领域数据质量重要，仍需独立验证，不能用“一条训练成功”证明效果。

~~~python
from transformers import Trainer, TrainingArguments
from datasets import Dataset

pairs = [
    {"src": "The defendant pleaded guilty.", "tgt": "L'accusé a plaidé coupable."},
]

ds = Dataset.from_list(pairs)


# 需核对目标语言与目标PAD的-100处理，原片段只是接口示范。
def preprocess(ex):
    return tok(
        ex["src"],
        text_target=ex["tgt"],
        truncation=True,
        max_length=128,
        padding="max_length",
    )


ds = ds.map(preprocess, remove_columns=["src", "tgt"])

args = TrainingArguments(output_dir="out", per_device_train_batch_size=4, num_train_epochs=3, learning_rate=3e-5)
Trainer(model=model, args=args, train_dataset=ds).train()
~~~

## 七、失败模式、原文边界与工程注意

1. BLEU30/40/50不能跨语言、语料和分词当统一质量等级；小于1分也不必然只是噪声，应做置信区间或配对检验。
2. 没有参考不能猜BLEU范围来冒充自动评分。
3. 回译相似不代表原译完全正确，两个方向可能共享偏差。
4. 原文80%成功、20%失败等比例未在本次验证。
5. 医疗/法律等译文的事实审查需要合格人工或领域流程，本文只是技术学习，不构成专业内容审查。
6. 某个模型“支持200语言”不等于所有方向都同样可靠。

## 十、术语与完成标准

NMT：神经机器翻译；parallel：对齐源/目标语料；BLEU：带短译惩罚的n-gram指标；chrF：字符F指标；register：语域；constrained decoding：施加词/格式约束的生成。

完成检查：

- 能区分源语言标识和目标语言控制。
- 能解释指标参考的嵌套形状。
- 能指出PAD标签与训练样本不足问题。
- 能审查实体、数字和占位符而非只看流畅度。
