## 零、初学者先读：聊天系统的四代家谱与一次工具循环

> 2026-11-06 新增的教学补充。首次学习先读本节，再进入后面的公式、原课代码与纠错。本课的 FAQ 检索就是[第14课](<14：信息检索——BM25、稠密向量、RRF与重排.md>)那条流水线的微缩版，工具循环则是走向 agent 的门——建议先有14课的“检索”概念再来读。

### 0.1 先理解这一课在做什么

聊天机器人不是“一段生成回复的代码”，而是**四种范式**的谱系，每一代都是为了治上一代最痛的失败而生：规则式死板但可靠 → 检索式保守但不会编 → 神经生成灵活但会胡说 → LLM+工具会办事但要管权限。用客服体系类比：规则式像按剧本走的电话IVR菜单（“按1查余额”）；检索式像柜台翻FAQ手册（问得接近才翻得到）；神经生成像一位会聊天但没有内部资料的新员工（嘴顺，内容难保）；LLM+工具像真正能操作系统的工作人员（查得到、办得了事，所以要配权限与审批）。2026年的生产系统不是四选一，而是**混合路由**：销户、扣款这类高危操作走规则；标准FAQ走检索；开放问题才交给带工具的生成模型。

（补充展开）学本课最容易犯的错是“新范式淘汰旧范式”的错觉。规则式今天仍跑在银行认证、航空订票这些不允许幻觉的场景里——**可靠但狭隘**恰恰是高危场景要的品质；检索式是所有客服“相似问题”功能的心脏。真正被淘汰的只有“一种架构包打天下”的想法。本课的正文代码因此不是五个孤立的玩具，而是同一条进化线的五个切片，读的时候随时问一句：这个范式把哪个失败留给了下一代去解决？

### 0.2 本课术语先翻成白话

- 意图（intent）=用户想要什么，一个类别标签（book_flight、reset_password）
- 槽位（slot）=完成任务缺的信息（日期、目的地），逐个问齐叫槽位填充
- 模式匹配（pattern matching）=用正则模板套用户输入
- ELIZA式反射（reflection）=把用户话里的片段原样弹回去当问题
- 检索式机器人（retrieval bot）=从既有问答库里挑最像的答案
- seq2seq=编码器读入、解码器生成的神经模型，能造句但不保证真实
- 幻觉（hallucination）=模型流畅地说出编造内容
- 工具调用（tool call）=模型输出结构化的“调哪个函数、给什么参数”
- agent loop=“模型→工具→观察→再决策”的循环，答完才退出
- max_steps=循环次数上限，防死循环，不是权限控制
- 提示注入（prompt injection）=用户或文档里藏话劫持系统提示
- 混合路由（hybrid routing）=按请求类型分流到不同范式的总调度
- AIML=ALICE 用的 XML 规则方言，一条“模式→模板”对一个
- 幂等（idempotent）=同一操作重复执行结果不变，工具调用安全的基本要求

### 0.3 用小数字走一遍

**规则匹配的一轮小对话**（正文4.1的 PATTERNS，逐条按顺序试）：

~~~text
用户：I feel sad today
  第1条 my name is (\w+)   → 不匹配
  第2条 i (need|want) (.+) → 不匹配（feel 不是 need/want）
  第3条 i feel (.+)        → 命中！捕获组 = "sad today"
  回复：Why do you feel sad today?
~~~

换几句话就能摸清规则系统的脾性：

~~~text
用户：I want a refund          → 第2条命中 → "Why do you want a refund?"
用户：My name is John and I feel sad
                              → 第1条先命中 → "Nice to meet you, John."
                                （后面的 feel 规则永远没机会——顺序即优先级）
用户：Today I feel sad         → 四条全没从句首匹配上（.match 锚定开头）
                              → 只落兜底(.*) → "Tell me more about that."
用户：今天心情不好            → 兜底（模式全是英文正则，中文一个都套不上）
~~~

五轮对话暴露规则式的全部性格：写得快、完全可解释；但**顺序遮挡**（先匹配宽规则会吞掉具体规则）、**锚定句首**（换个开头就失明）、**语言绑定**（换语言全部失效）。这也是为什么50年加规则从没加出通用智能——覆盖率随规则数线性涨，维护成本同步涨，能力却不涨。

**FAQ 阈值的那道闸**（正文4.2，行为演示）：设三个FAQ问句已编码成向量，用户来句"how do i reset my password"，与库里的同款问句余弦约0.82（假设值），高于阈值0.5 → 直接返回"Go to Settings > Security > Reset Password."；来句"我想退货"（中文），与所有英文问句的余弦只有约0.35（假设值），低于阈值 → faq_respond 返回 None，交给上层决定澄清还是转生成——**答不上来就明说**，这是检索式对比生成式最重要的美德，也是[第13课](<13：问答系统——抽取式、检索增强与拒答评估.md>)拒答思想在聊天场景的翻版。

**工具循环的一圈**（正文4.4，配2.9的2+3轨迹）：用户说“计算2加3”→ 模型返回 tool_call{name=add, arguments={a:2,b:3}} → 程序检查名字在 tools 里、args 是字典 → 本地执行 add(2,3)=5 → 结果5以 tool 角色写回 history → 模型下一轮看到5，返回最终文本。history 从1条变3条再收尾——模型“说要调用”与程序“已经执行”是两个事件，权限与副作用永远归程序管。

以上是用于理解的算例（行为与阈值数字为教学演示），不是新增的模型实测。读下面的代码时，把每个环节先对应回这里。

### 0.4 怎样连接到正文代码

五个 Build It 分段就是四代范式加调度：RulePattern/PATTERNS/rule_based_respond 是0.3第一段（注意 re.match 从句首匹配、顺序即优先级）；faq_respond 是第二段（阈值返回None的设计）；pipeline("text2text-generation") 加载 flan-t5-small 是神经生成那一代；agent_loop 是第四代（对照0.3第三段看 history 怎么长：先 append 用户的 assistant tool_call、再 append tool 结果，直到返回 content 退出）；hybrid_chat + is_destructive_action 是混合路由——但关键词检测只是教学路由，不是安全边界。第五节 mock_llm 的加法演示不联网就能跑通整圈循环。

### 0.5 理解检查（含参考答案）

**问题1：** 为什么兜底规则 `(.*)` 必须放在 PATTERNS 最后？

**参考答案：** 规则按顺序取第一个命中的；`(.*)` 匹配任何非空输入，放前面会把所有具体规则全部遮挡，机器人退化成只会说"Tell me more about that."。

**问题2：** FAQ 相似度低于阈值时，为什么返回 None 而不是返回最像的那条答案？

**参考答案：** 低于阈值说明没有把握，硬答会错答（检索式的失败方式就是“检错”）；返回 None 把决定权交给上层——澄清、转人工或转生成，比自信地答错好。

**问题3：** agent_loop 里“模型说需要调用工具”和“工具真的执行了”是同一件事吗？max_steps 管得住权限吗？

**参考答案：** 不是。模型只输出结构化请求，执行、校验、鉴权都是程序的活；真正动手前必须有权限检查与确认。max_steps 只限制循环轮数防死循环，与权限无关。

## 一、这一课解决什么问题？

聊天系统不只是一段生成回复代码。规则负责确定路径、检索利用固定知识、神经模型生成语言、工具循环连接受控功能。本课把这些路线拆开，再理解何时组合。

## 二、核心概念与推导

从ELIZA模式匹配到PARRY内部状态、ALICE规则库，再到接入后端服务的聊天助手，演进主线是表示、记忆、生成与行动能力的变化，不是旧方法全部失效。历史测试不等于机器人具备通用智能，更不能把模拟心理咨询当真实治疗。

（补充 2026-11-06）把七十年家谱排成时间线（原课 Concept 部分的事件）：

| 年份 | 事件 | 新增的能力 |
|---|---|---|
| 1950 | Turing 提出“模仿游戏”测试 | 对话成为机器智能的标尺 |
| 1966 | ELIZA：约200条模式，零状态 | 反射式“倾听” |
| 1972 | PARRY：恐惧/愤怒/猜疑三个数值变量 | **内部状态**——同样输入不同回应 |
| 1995 | ALICE：约4万条AIML规则 | 规则规模化的极限证明 |
| 2001 | SmarterChild：接30万IM用户＋后端查询 | **接外部服务**——工具调用的雏形 |
| 2016-2019 | seq2seq 聊天机器人潮 | 自由生成（也是失望之潮） |
| 2022+ | LLM + 工具循环 | 规划、行动、验证 |

读法：前三十年都在“匹配输入→吐模板→改一点状态”这台机器上加规则，覆盖率涨、通用性不涨；直到接入外部服务（2001）和自由生成（2016+）才换了机器。PARRY 那三个变量就是今天 persona 系统提示的祖先——一句 system prompt 的史前形态是三个浮点数。

（补充 2026-11-06）四范式按“表示、记忆、生成、行动”四个维度对照（理解第二节主线的一张表）：

| | 规则式 | 检索式 | seq2seq | LLM+工具 |
|---|---|---|---|---|
| 表示 | 正则模式 | 问答对向量 | 神经权重 | 神经权重+工具schema |
| 记忆 | 几乎没有 | FAQ库 | 对话日志训练 | history+外部检索 |
| 生成 | 模板填空 | 无（挑选） | 逐词生成 | 逐词生成+结构化调用 |
| 行动 | 无 | 无 | 无 | 可执行真实操作 |
| 典型失败 | 覆盖外即瞎 | 检错、过期 | 编造、跑题 | 越权、注入、死循环 |

规则式：匹配模式返回模板，可解释但覆盖有限。检索式：匹配已有问答，知识边界清楚但可能检错、过期。seq2seq：直接生成回复，灵活但可能不实。LLM+工具：生成工具请求，执行结果再回到上下文，必须管理权限、参数和终止。

混合架构可将高风险流程交给明确业务逻辑，FAQ优先检索，开放问题再进入生成与工具。检索和RAG都不能保证零幻觉；是否需要混合架构应看任务，不是所有项目一律相同。

（补充 2026-11-06）路由判断的一句话版：**能写成流程图的走规则**（认证、支付、销户——错一步都是事故，宁可死板）；**答案有标准版本的走检索**（退换货政策——库里有的就不必生成，还零幻觉）；**必须自由发挥才走生成与工具**（开放式咨询——但同时上权限与确认）。三个问题自测：这个请求答错的代价多大？答案有没有标准版？需要动真实世界的数据吗？代价小、无标准版、不动数据——才轮到纯生成。

（补充 2026-11-06）工具循环的 history 演化表（0.3第三段的展开，也是4.4代码的逐行走读）：

~~~text
第0步  history = [user: "计算2加3"]                          ← 1条
第1步  模型返回 tool_call(add, {a:2, b:3})
       history += [assistant: tool_call(add,...)]            ← 记下"我请求了什么"
       history += [tool: "5"]                                ← 记下"实际发生了什么"
                                                              ← 3条
第2步  模型看到完整history，返回 content: "2加3等于5"
       循环结束（没有tool_call就返回最终文本）
~~~

两个设计点值得盯住：assistant 的请求和 tool 的结果**分开记录**，模型下一轮能分清“我说要做”和“做出来的结果”；错误也走同样的路（unknown tool 的报错同样写回 history），让模型有机会改口而不是当场崩溃。

### 2.9 用一个小例子把概念串起来（补充）

工具循环的一次完整轨迹：user请求2+3→适配器返回name=add、arguments={a:2,b:3}→程序验证并执行本地加法→tool结果5加入history→模型再返回最终文本。模型说“需要调用”与程序已经执行是两个事件。max_steps只限制调用轮数，授权与真正副作用仍由程序负责。

## 四、Build It：原课分步代码与中文讲解

### 4.1 模板规则回复

RulePattern编译正则，按顺序.match并格式化捕获组。最后(.*)兜底，因此先匹配宽泛规则可能遮挡具体规则。模板不会理解真实意图，大小写忽略也不等于同义表达处理。

~~~python
import re


class RulePattern:
    def __init__(self, pattern, response_template):
        self.regex = re.compile(pattern, re.IGNORECASE)
        self.template = response_template


PATTERNS = [
    RulePattern(r"my name is (\w+)", "Nice to meet you, {0}."),
    RulePattern(r"i (need|want) (.+)", "Why do you {0} {1}?"),
    RulePattern(r"i feel (.+)", "Why do you feel {0}?"),
    RulePattern(r"(.*)", "Tell me more about that."),
]


# 依次匹配规则并返回模板，不是语义推理。
def rule_based_respond(user_input):
    for pattern in PATTERNS:
        m = pattern.regex.match(user_input.strip())
        if m:
            return pattern.template.format(*m.groups())
    return "I don't understand."
~~~

### 4.2 句向量FAQ检索

对FAQ问题预编码，输入向量归一化后点积找最高相似度。低于阈值返回None，让上层决定澄清或转生成；阈值不是置信概率，需用领域验证集标定。

~~~python
from sentence_transformers import SentenceTransformer
import numpy as np


FAQ = [
    ("how do i reset my password", "Go to Settings > Security > Reset Password."),
    ("how do i cancel my order", "Go to Orders, find the order, click Cancel."),
    ("what is your return policy", "30-day returns on unused items, original packaging."),
]


encoder = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2")
faq_questions = [q for q, _ in FAQ]
faq_embeddings = encoder.encode(faq_questions, normalize_embeddings=True)


# 低相似度返回None，由上层处理未知问题。
def faq_respond(user_input, threshold=0.5):
    q_emb = encoder.encode([user_input], normalize_embeddings=True)[0]
    sims = faq_embeddings @ q_emb
    best = int(np.argmax(sims))
    if sims[best] < threshold:
        return None
    return FAQ[best][1]
~~~

### 4.4 带工具调用的循环

llm是自定义适配器，返回content或单个tool_call字典；这不是任何供应商SDK的即用消息格式。代码检查工具名和args类型，再执行tools[name](**args)并将结果放回history。max_steps限制循环，但工具异常、权限与执行幂等性还需补全。

~~~python
# 教学工具循环，真实操作前必须补权限、schema与异常处理。
def agent_loop(user_message, tools, llm, max_steps=5):
    history = [{"role": "user", "content": user_message}]
    for _ in range(max_steps):
        response = llm(history, tools=tools)
        tool_call = response.get("tool_call")
        if tool_call:
            tool_name = tool_call.get("name")
            args = tool_call.get("arguments")
            if not isinstance(tool_name, str) or tool_name not in tools:
                history.append({"role": "assistant", "tool_call": tool_call})
                history.append({"role": "tool", "name": str(tool_name), "content": f"error: unknown tool {tool_name!r}"})
                continue
            if not isinstance(args, dict):
                history.append({"role": "assistant", "tool_call": tool_call})
                history.append({"role": "tool", "name": tool_name, "content": f"error: arguments must be a dict, got {type(args).__name__}"})
                continue
            fn = tools[tool_name]
            result = fn(**args)
            history.append({"role": "assistant", "tool_call": tool_call})
            history.append({"role": "tool", "name": tool_name, "content": result})
        else:
            return response["content"]
    return "I could not complete the task in the step budget."
~~~

### 4.5 组合为混合聊天

原示例的structured_flow、tools、llm等需要自己提供。用关键词检测危险操作只是教学路由，不是安全边界；否定、隐含意图、多语言都可能绕过或误判。

~~~python
# 关键词分流仅为演示，不能作为安全边界。
def hybrid_chat(user_input):
    if is_destructive_action(user_input):
        return structured_flow(user_input)

    faq_answer = faq_respond(user_input, threshold=0.6)
    if faq_answer:
        return faq_answer

    return agent_loop(user_input, tools, llm)


def is_destructive_action(text):
    danger_words = ["delete", "cancel", "charge", "refund", "transfer"]
    return any(w in text.lower() for w in danger_words)
~~~

print(agent_loop("计算2加3", {"add": add}, mock_llm))
~~~
预期最终返回包含5的文本；这只检验循环结构，不检验真实LLM理解能力。mock的工具参数字段arguments与原函数一致。本次不调用任何外部服务。

## 六、Use It：使用现成工具

原文比较各架构适用范围：固定业务流程偏规则、标准FAQ偏检索、开放回复偏生成、需要外部操作才引入工具。评估不能只有回复好不好，还要看任务成功、工具选择/参数正确、越界行为、成本、轮数和失败恢复。语料和检索返回内容都是不可信数据，不应被提升为工具权限指令。



## 七、失败模式、原文边界与工程注意

1. 原agent_loop没有完整异常捕获、参数schema校验、身份鉴权和幂等处理，不能直接上线。
2. assistant声称“已发送/已取消”必须与真实工具结果核对。
3. 外部文档也可能包含提示注入；系统提示、简单过滤和计划检查不能保证免疫。
4. 高风险操作需要权限与明确确认；练习只使用mock发送邮件，不实际发送。
5. 工具结果要带来源/调用ID，真实供应商消息协议需另写适配层。
6. max_steps之外仍要管超时、token预算、重试与日志隐私。
7. 来源中的攻击成功率和案例数字属于特定实验背景，不可当作本项目风险概率。
