## 一、这一课解决什么问题？

“Apple发布产品。该公司称它很快发货。”名字、名词短语、代词可能指向同一个实体。共指把这些提及聚为一簇，帮助问答、摘要、关系抽取与实体覆盖。

## 二、核心概念与推导

mention是文本中的具体跨度；entity是指向的对象；cluster是一组共指mention。antecedent是先行提及，anaphora向后回指，cataphora代词先出现再给名字。bridging如车→车轮是关联，并非严格指同一对象，不能直接合并为同一实体。

路线：Hobbs类规则依赖句法；mention-pair判断每对是否同指再聚类；mention-ranking为每个mention选先行词或无先行词；端到端span模型预测提及和先行词；生成模型直接输出簇但要检验遗漏与错合并。

MUC偏链接，B³逐提及看簇重合，CEAF做簇/实体匹配；CoNLL F1为MUC、B³、CEAF-φ4三项F1平均。BLANC、LEA提供其他视角。只报一个指标可能掩盖碎簇或大簇问题。

跨段远指、中文零指代、前指、同名不同人都困难。推断不清楚时保留未解析，不应强行选最近名字；性别与数字规则只是脆弱启发式。

### 2.9 用一个小例子把概念串起来（补充）

Apple…The company…it可聚为同簇，但the wheels与a car通常是部分-整体关联，不是同一实体。两个Apple字符串也可能分别指水果与公司。先标每处offset，再决定簇，保留未解代词比强行错合并更利于下游审计。

## 四、Build It：原课分步代码与中文讲解

### 4.1 调用预训练共指管线

原文doc._.coref_clusters是另一类扩展风格，不能直接假定spaCy experimental也用此接口。官方CoreferenceResolver把簇保存为doc.spans里的SpanGroup，名称默认coref_clusters前缀；有些组件先输出单token，需SpanResolver扩展完整短语。

~~~python
import spacy
nlp = spacy.load("en_coreference_web_trf")   # experimental model
doc = nlp("Apple announced new products. The company said it would ship them soon.")
for cluster in doc._.coref_clusters:
    print(cluster, "->", [m.text for m in cluster])
~~~

### 4.2 理解规则基线

按命名提及、代词、定指短语取候选，结合数一致、距离、语法角色打分。这里是任务流程，不是已经实现完整Hobbs算法。nearest名词可能是错误实体；把所有代词猜成最近人会造成系统性错误。



### 4.3 用生成模型输出簇

原prompt依赖text，要求JSON但不自带schema约束。mentions仅返回字符串会无法区分重复出现的位置，建议输出每个[start,end)；验证区间、原文片段与簇ID，再检查是否过度合并。

~~~python
prompt = f"""Text: {text}

List every pronoun and noun phrase that refers to a person or company.
Cluster them by what they refer to. Output JSON:
[{{"entity": "Apple", "mentions": ["Apple", "the company", "it"]}}, ...]
"""
~~~

### 4.4 评价提及与链接

先测mention检测P/R，再测共指链接/聚类；span对了但簇错了仍失败。按标注协议处理单例、嵌套提及、重叠与排除项，正式CoNLL分数使用相应标准scorer。



## 五、把代码运行起来：补充入口与检查

补充：验证提及offset与重复位置，纯标准库即可：
~~~python
def validate_mentions(text, clusters):
    seen = set()
    for cluster in clusters:
        for item in cluster:
            start, end = item["span"]
            if not 0 <= start < end <= len(text):
                raise ValueError("提及区间越界或为空")
            if text[start:end] != item["text"]:
                raise ValueError("提及文本与原文不符")
            if (start, end) in seen:
                raise ValueError("同一提及被重复归簇")
            seen.add((start, end))
    return True

text = "Apple said it will ship."
clusters = [[{"text": "Apple", "span": [0, 5]}, {"text": "it", "span": [11, 13]}]]
assert validate_mentions(text, clusters)
~~~

## 六、Use It：使用现成工具

单文档英文可比较适配当前环境的神经共指；多语言需该语言训练数据/模型；跨文档事件共指是额外任务，不能直接把单文档结果串接。下游NER→coref合并是一种集成方式，不意味着共指必然依赖NER先运行。关键实体可人工审核，保留每次合并来源与置信依据。



## 七、失败模式、原文边界与工程注意

1. 性别词典不应被视为真实身份事实；中性代词和机构等容易误判。
2. 跨窗口需要重叠、簇对齐与来源位置，不能简单按字符串相同合并。
3. 大簇错合并会污染关系抽取和知识图谱，撤销机制很重要。
4. 共指不一定能推断姓名未知的真实身份；簇可只用内部ID。
5. 原文83F1、长文下降15点、2000token界限是来源背景，不是通用限制。
6. quote内说话人与叙述人可能不同；“我/你”需对话角色信息。

## 十、术语与完成标准

mention：提及；antecedent：先行词；cluster：共指簇；anaphora：回指；cataphora：前指；bridging：关联指代；CoNLL F1：三指标F1平均。

完成检查：

- 能区分字符串相同与实体相同。
- 能检查[start,end)位置。
- 能解释bridging不等于同一实体。
- 能识别spaCy接口混用。
