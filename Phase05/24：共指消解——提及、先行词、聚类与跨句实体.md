## 零、初学者先读：让“他”和名字回到同一个人身上

> 2026-11-06 新增的教学补充。首次学习先读本节，再进入后面的公式、原课代码与纠错。本课是“信息抽取三部曲”的第一课：[第06课](<06：命名实体识别——BIO、规则、CRF与神经模型.md>)负责找出实体名字，本课把“名字、称呼、代词”归到同一个实体，[第25课](<25：实体链接与消歧——候选、上下文、知识库与NIL.md>)再把实体对齐到外部知识库，[第26课](<26：关系抽取与知识图谱——三元组、锚点、方向与溯源.md>)最后把实体连成知识图谱——三课是同一条流水线。

### 0.1 先理解这一课在做什么

[第06课](<06：命名实体识别——BIO、规则、CRF与神经模型.md>)的NER只认“写在纸上的名字”：输入“Apple发布产品。该公司称它很快发货。”，它只标出Apple，而“该公司”“它”也是同一实体的提及——原课参考：不做共指时，NER流水线会漏掉60%～80%的提及。本课的任务：把文档里所有指向同一实体的提法**聚成一簇**，让下游看到的是“一个实体”，而不是“一个名字加一堆代词”。

类比：想象一个群聊，同一个人注册了三个马甲——“小明”“该公司”“他”。人类读者天然知道是同一个人，程序不知道。共指消解就是**查马甲**：给每个账号做指纹比对（性别、单复数、距离、话题），把同一个人的马甲绑成一组；输出一串“账号组”，每组背后是一个真实身份。查马甲只认行为证据，不认表面字样——两个账号都叫“小明”不代表同一个人，一个叫“他”一个叫“该公司”反而可能是同一个人。

先认四种马甲（原课的提及类型，补充翻译）：

| 类型 | 例子 | 特点 |
|---|---|---|
| 专名 named entity | Tim Cook | NER能直接抓到 |
| 名词性 nominal | the CEO、该公司 | 有描述但不带名字 |
| 代词性 pronominal | he、它 | 最短、最依赖上下文 |
| 同位语 appositive | Tim Cook, Apple's CEO | 名字和描述并排，天然同指 |

### 0.2 本课术语先翻成白话

- 提及（mention）=文本里指某个实体的一小段文字，用字符区间[start,end)标记
- 实体（entity）=被指的真实对象；文本里永远看不到实体本身，只看得到提及
- 共指簇（cluster）=全部指向同一实体的提及集合，是本课的输出
- 先行词（antecedent）=代词往前找到的那个更早的提及：“他”的先行词是“小明”
- 回指（anaphora）=后出现的提及回头指前面的；前指（cataphora）=反过来：“当她走进门时，玛丽笑了”里的“她”
- 桥接指代（bridging）=关联但不等同：“车”和“方向盘”有关系，却是两个实体，**不能合并**
- 单例（singleton）=只出现一次、没有别的提及与它共指的提及
- 传递闭包（transitive closure）=A与B同指、B与C同指，则A、B、C并成一簇——mention-pair路线靠它拼簇
- MUC／B³／CEAF=三个共指指标，分别数链接、逐提及比簇、按簇配对；CoNLL F1=三者F1的平均
- 原课参考：2026年CoNLL-2012榜上SOTA约83 F1

### 0.3 用小数字走一遍

三句话、四个提及、两次配对判定，把共指的“搜索空间”走一遍（算例，字符区间可纸笔复核）：

~~~text
句1：小明加入了VW。          m1=小明 [0,2)
句2：他说这份工作很有意思。    m2=他   [8,9)
句3：小明下周去慕尼黑。        m3=小明 [19,21)
~~~

**第一步：列出提及。** 候选包括专名（小明×2、VW）和代词（他）。VW也是提及，同样进搜索空间。

**第二步：给代词找先行词。** “他”只能往前看（回指），候选是m1和VW。按规则基线的线索打分：

| 候选 | 单复数 | 类别 | 距离 | 句法角色 | 结论 |
|---|---|---|---|---|---|
| 小明（m1） | 单数✓ | 人名↔人称代词✓ | 最近✓ | 上句主语✓ | 选它 |
| VW（句1） | 单数✓ | 组织↔人称代词✗ | 同句 | 宾语 | 排除 |

判定：m2与m1共指。注意“组织↔人称代词✗”这条是脆弱启发式——公司名在英文里也常被指成they，中文用“它”，规则一硬就错（正文第七节的失败模式1）。

**第三步：字符串相同≠实体相同。** m3“小明”与m1字面一样，能直接并簇吗？不能只看字样：如果前文还出现过一位“王小明”，这个“小明”可能指另一个人。字符串重合只是**弱证据**，要与位置、话题一起判。本例假设没有歧义，判共指。

**第四步：传递闭包拼簇。** m1～m2（第二步）、m1～m3（第三步）→ 簇1={m1, m2, m3}（小明本人）；VW自己是单例簇。输出：两个簇、四个提及。

**反例（不能并簇的两种情形）。** 其一，桥接：“他开一辆车。方向盘有点旧。”——“方向盘”与“车”是部分-整体关系，相关但不**同一**，并簇等于宣称“方向盘就是那辆车”。其二，线索冲突：“小红加入了VW。他负责自动驾驶。”——若词典认定“小红”偏女性名，与“他”冲突，规则会把m2悬置；正确姿势是保留未解析，而不是硬选最近的。

以上是用于理解的算例，不是新增的训练或性能实测。读下面的正文时，把“路线”和“指标”都对应回这四个提及。

### 0.5 理解检查（含参考答案）

**问题1：** “Apple Inc.发布了产品。它很快发货。”里“它”的先行词是什么？为什么不是“产品”？

**参考答案：** 先行词是“Apple Inc.”。“产品很快发货”语义上通常不通，发布者才是“说它发货”的主体；代词消歧最终靠语义，规则系统只是用数一致、距离、句法角色去近似这些信号。

**问题2：** “我买了一辆车。轮子很差。”——轮子和车能进同一个簇吗？

**参考答案：** 不能。这是bridging（桥接指代）：轮子属于那辆车，是关联而非同一实体。合并会让下游把“轮子”当“车”本身。

**问题3：** 为什么共指要报MUC、B³、CEAF三个指标的平均，而不只报一个？

**参考答案：** 聚类质量没有一个指标能全概括：MUC只数链接、对碎簇（每个提及自己一簇）惩罚重；B³逐提及比簇重合、对单例反而宽松；CEAF要求预测簇与真实簇一一配对。只报一个会掩盖某种失败模式。

## 一、这一课解决什么问题？

“Apple发布产品。该公司称它很快发货。”名字、名词短语、代词可能指向同一个实体。共指把这些提及聚为一簇，帮助问答、摘要、关系抽取与实体覆盖。

## 二、核心概念与推导

mention是文本中的具体跨度；entity是指向的对象；cluster是一组共指mention。antecedent是先行提及，anaphora向后回指，cataphora代词先出现再给名字。bridging如车→车轮是关联，并非严格指同一对象，不能直接合并为同一实体。

（补充 2026-11-06）“实体在文本里不可见，可见的只有提及”——这句值得展开。你从没在纸上见过“小明本人”，你见到的是两个字符“小明”、一个“他”；共指的全部工作，就是从可见证据（字符串、位置、性别、单复数）推断不可见的分组。三条边界先立住：字符串相同不保证同指（两位“小明”），字符串不同不排除同指（“小明”与“他”），相关不等于同一（“车”与“方向盘”）。与[第06课](<06：命名实体识别——BIO、规则、CRF与神经模型.md>)的分工：

| | NER（第06课） | 共指（本课） |
|---|---|---|
| 输入 | 字符序列 | 提及候选（常含NER结果） |
| 输出 | 实体类型的span | 提及的分组（簇） |
| 回答的问题 | “这段文字里有个PER” | “这些提法是同一个PER吗” |

买车的例子再进一步：说“我买了辆车。**价格**很贵”时，“价格”桥接指那辆车，但若并进同簇，下游关系抽取就会抽出（车，是，价格）这种荒唐三元组——bridging错并的代价会在[第26课](<26：关系抽取与知识图谱——三元组、锚点、方向与溯源.md>)的图谱里兑现。

路线：Hobbs类规则依赖句法；mention-pair判断每对是否同指再聚类；mention-ranking为每个mention选先行词或无先行词；端到端span模型预测提及和先行词；生成模型直接输出簇但要检验遗漏与错合并。

（补充 2026-11-06）五条路线用“查马甲”串一遍：Hobbs规则（1978）像拿着语法说明书查代词，纯代词上反而难以超越；mention-pair是“两两握手”——任意两个提及配一次对判同指，再靠传递闭包拼簇（零节0.3第四步）；mention-ranking改成“每个新马甲只挑一个最像的前辈”，含“无前辈”选项；端到端span模型（Lee等，2017）先把所有可能的短语全列出来，同时打“是不是提及”和“先行词是谁”两套分，一条流水线出簇，是现代默认；生成路线直接问LLM，长文上会漏提及、会过度合并（正文4.3的提醒）。共同点：都逃不开零节0.3那三步——先有提及候选，再判同指，最后成簇；差别只在谁来判、判得多准。

MUC偏链接，B³逐提及看簇重合，CEAF做簇/实体匹配；CoNLL F1为MUC、B³、CEAF-φ4三项F1平均。BLANC、LEA提供其他视角。只报一个指标可能掩盖碎簇或大簇问题。

（补充 2026-11-06）三个指标的白话：MUC数“链接”——预测出的提及之间连对了多少条线，簇切碎（每个提及自己一簇）时它重罚；B³逐提及看“我的簇里坐对了多少人”，对单例反而宽松；CEAF要求预测簇和真实簇**一一配对**再算重叠，专治“一大簇吞掉所有”。一个经典作弊可以说明为什么必须三个一起看：把每个提及都单独成簇——B³可能给高分（很多提及本来就只出现一次，自己一簇恰是对的），MUC直接归零（一条链接都没建）。CoNLL F1取平均，是逼系统同时经受三种视角。原课参考：SOTA约83 F1、长文超过2000 token掉约15点——来源背景，不是本机实测。

跨段远指、中文零指代、前指、同名不同人都困难。推断不清楚时保留未解析，不应强行选最近名字；性别与数字规则只是脆弱启发式。

（补充 2026-11-06）中文零指代值得给个例子，对中文读者它是日常而非“困难”：“买了车。开去上班。”——主语“我”根本没写出来，但省略的主语也要参与共指（连到上文提及或对话双方）；英文几乎不这样省略，所以英文工具直接搬到中文会漏掉一整类提及。“前指”则反过来：“当她走进门时，玛丽笑了”里代词**先于**名字出现——这提醒“先行词”是逻辑概念不是位置概念：被依赖的那个叫antecedent，多数在前面，cataphora时在后面。

### 2.9 用一个小例子把概念串起来（补充）

Apple…The company…it可聚为同簇，但the wheels与a car通常是部分-整体关联，不是同一实体。两个Apple字符串也可能分别指水果与公司。先标每处offset，再决定簇，保留未解代词比强行错合并更利于下游审计。

## 四、Build It：原课分步代码与中文讲解

### 4.1 调用预训练共指管线

原文doc._.coref_clusters是另一类扩展风格，不能直接假定spaCy experimental也用此接口。官方CoreferenceResolver把簇保存为doc.spans里的SpanGroup，名称默认coref_clusters前缀；有些组件先输出单token，需SpanResolver扩展完整短语。

~~~python
import spacy
nlp = spacy.load("en_coreference_web_trf")   # experimental model
doc = nlp("Apple announced new products. The company said it would ship them soon.")
for cluster in doc._.coref_clusters:
    print(cluster, "->", [m.text for m in cluster])
~~~

### 4.2 理解规则基线

按命名提及、代词、定指短语取候选，结合数一致、距离、语法角色打分。这里是任务流程，不是已经实现完整Hobbs算法。nearest名词可能是错误实体；把所有代词猜成最近人会造成系统性错误。



### 4.3 用生成模型输出簇

原prompt依赖text，要求JSON但不自带schema约束。mentions仅返回字符串会无法区分重复出现的位置，建议输出每个[start,end)；验证区间、原文片段与簇ID，再检查是否过度合并。

~~~python
prompt = f"""Text: {text}

List every pronoun and noun phrase that refers to a person or company.
Cluster them by what they refer to. Output JSON:
[{{"entity": "Apple", "mentions": ["Apple", "the company", "it"]}}, ...]
"""
~~~

### 4.4 评价提及与链接

先测mention检测P/R，再测共指链接/聚类；span对了但簇错了仍失败。按标注协议处理单例、嵌套提及、重叠与排除项，正式CoNLL分数使用相应标准scorer。



## 五、把代码运行起来：补充入口与检查

补充：验证提及offset与重复位置，纯标准库即可：
~~~python
def validate_mentions(text, clusters):
    seen = set()
    for cluster in clusters:
        for item in cluster:
            start, end = item["span"]
            if not 0 <= start < end <= len(text):
                raise ValueError("提及区间越界或为空")
            if text[start:end] != item["text"]:
                raise ValueError("提及文本与原文不符")
            if (start, end) in seen:
                raise ValueError("同一提及被重复归簇")
            seen.add((start, end))
    return True

text = "Apple said it will ship."
clusters = [[{"text": "Apple", "span": [0, 5]}, {"text": "it", "span": [11, 13]}]]
assert validate_mentions(text, clusters)
~~~

## 六、Use It：使用现成工具

单文档英文可比较适配当前环境的神经共指；多语言需该语言训练数据/模型；跨文档事件共指是额外任务，不能直接把单文档结果串接。下游NER→coref合并是一种集成方式，不意味着共指必然依赖NER先运行。关键实体可人工审核，保留每次合并来源与置信依据。



## 七、失败模式、原文边界与工程注意

1. 性别词典不应被视为真实身份事实；中性代词和机构等容易误判。
2. 跨窗口需要重叠、簇对齐与来源位置，不能简单按字符串相同合并。
3. 大簇错合并会污染关系抽取和知识图谱，撤销机制很重要。
4. 共指不一定能推断姓名未知的真实身份；簇可只用内部ID。
5. 原文83F1、长文下降15点、2000token界限是来源背景，不是通用限制。
6. quote内说话人与叙述人可能不同；“我/你”需对话角色信息。
