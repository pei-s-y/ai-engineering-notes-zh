## 零、初学者先读：要的是有根据的答案

> 2026-11-06 新增的教学补充。首次学习先读本节，再进入后面的公式、原课代码与纠错。第11、12课让机器“产出一段话”，本课要求更严：每个答案都能指着原文说“在这里”。抽取式问答读的正是第10课式的联合编码，检索增强的后半程是第14课的地盘。

### 0.1 先理解这一课在做什么

用户问“初代iPhone什么时候发布”，想要“June 29, 2007”这个直接、有根据的答案，而不是“苹果的历史悠久而多彩”。三种做法像开卷考试的三种答题方式：

| | 抽取式QA | 检索增强（RAG） | 闭卷生成 |
|---|---|---|---|
| 前提 | 答案所在的篇章已给 | 语料很大，先找再答 | 什么都没给 |
| 做法 | 联合编码问题+篇章，划出答案区间 | 先检索top-k段落，再抽取/生成 | 凭参数里的记忆直接写 |
| 像谁 | 在指定段落里划线 | 先去书架找书再划线 | 不翻书凭记忆答 |
| 风险 | 可能划错片段 | 检索漏了就答不出 | 冷门/新事实最容易编 |

抽取式QA的技术内核：把question和passage拼在一起送进编码器（正是第10课cross-attention读两条文本的场景），训练两个输出头分别预测答案的**起始**与**终止**位置——输出是原文的一段字符区间，所以“按构造不会幻觉”；但篇章里没有答案时它也无从拒绝，SQuAD2为此引入了空答案与拒答。RAG（retrieval-augmented generation）把“给篇章”换成“先检索”：第14课的检索器打前站，本课的阅读器收尾。

### 0.2 本课术语先翻成白话

- 抽取式QA（extractive QA）=从给定篇章里划出答案区间
- 答案区间 span=passage里一段连续字符，用[start, end)定位
- SQuAD=斯坦福问答数据集；SQuAD 2.0含“无答案”问题
- 开放域 open-domain=不给篇章，先检索后回答
- 检索器 retriever=从语料里找候选段落的部件
- 阅读器 reader=在候选段落里找答案的部件
- RAG（retrieval-augmented generation，检索增强生成）=检索+阅读的两段流水线
- 稠密检索 dense retrieval=用向量编码器与余弦相似度做检索
- EM（exact match，完全匹配）=规范化后逐字比对，不匹配就是0分
- token-F1=按词重叠给部分分的指标
- 拒答 refusal=证据不足时回答“不知道”
- null score=“无答案”这个特殊选项的分数

### 0.3 用小数字走一遍

**字符区间怎么来的。** 篇章“Ada Lovelace was born in 1815. She wrote the first algorithm.”，问“Ada Lovelace生于哪年”。答案是1815，数格子：

~~~text
"Ada Lovelace was born in " = 3+1+8+1+3+1+4+1+2+1 = 25个字符
span = [25, 29)，passage[25:29] == "1815" ✓
~~~

区间是纯字符串算术，不需要任何模型——正文第五节的偏移检查就是这件事的代码版；原文iPhone例子里June 29, 2007的区间[40,53)同理由字符计数得到（本机Python已复核两者）。

**拒答怎么判定。** 同一篇章问“她出生在哪里”——篇章里根本没有地点。SQuAD2式做法是给“无答案”也打分：设null分数2.1、最佳区间分数1.8，null更高→返回空答案（拒答）；若换一个问题、最佳区间2.6>2.1，才输出该区间。没有这套机制，模型永远会硬划一个最像的片段——哪怕文不对题。原课4.1默认行为正是“永远返回最高分片段”，要显式handle_impossible_answer=True才启用空答案。

**EM与token-F1的宽严。** 标准答案“June 29, 2007”，预测“June 29th, 2007”：EM=0（字符串不相等，th一个字符就毁掉完全匹配）；token-F1：重叠june、2007共2词，精确率=召回率=2/3，F1≈0.667——重叠指标肯给部分分。两个指标一起报告才完整。

以上是用于理解的算例，不是新增的问答或检索实测。

### 0.4 怎样连接到正文代码

4.1的qa pipeline返回{score, start, end, answer}四件套——0.3的字符区间就是start/end字段；deepset/roberta-base-squad2是SQuAD2模型，中文说明提醒的“偏移57～70与字符串不符”正是要用context[start:end]亲手核对的原因。4.2把retrieve（稠密检索、归一化点积排序）和qa串成两段流水线，对应0.1“先找书再划线”；注意拼接后偏移属于combined字符串，文档与片段的映射要自己保存。4.3的rag_generate把检索段落拼进提示词交给llm——第11课的生成机器在问答里的用法，“仅上下文、不知道就说不知道”是提示意图、非技术保证。4.5的RAGAS四指标里，faithfulness对应“有根据”，context recall对应“检索漏了就答不出”。第五节的偏移检查代码可脱离任何模型运行0.3的第一个例子。

### 0.5 理解检查（含参考答案）

**问题1：** 检索没找到含答案的文档、文档在但阅读器选错了片段，这两类错误为什么必须分开数？

**参考答案：** 前者是retriever的召回失败，reader再完美也无处抽取；后者是reader的错误。混在一起就不知道该修检索还是修阅读，两者的训练数据与改进手段也不同。

**问题2：** 预测“June 29th, 2007”对标准“June 29, 2007”，EM给0分合理吗？

**参考答案：** 按EM的定义合理——规范化后逐字比对，不匹配就是0；它的苛刻正是token-F1存在的理由。两个指标量的是不同的东西，合在一起才完整。

**问题3：** 提示词里写了“不知道就说不知道”，为什么还不算有了拒答机制？

**参考答案：** 那只是对生成意图的软约束，不是技术保证；真正的拒答需要空答案分数或阈值校准，并用“可答/不可答”测试集度量混淆率——第七节第6条专门提醒这一点。

## 一、这一课解决什么问题？

用户需要直接且有根据的答案，而不是一段貌似相关的文字。本课区分给定篇章抽取、开放域检索+阅读器，以及参数记忆闭卷生成，再把检索与生成接成RAG。

## 二、核心概念与推导

抽取式QA联合编码question/context，预测答案起止位置；输出虽来自上下文，仍可能选错片段或脱离语境，不能说不可能给错误答案。SQuAD2训练包括无答案问题，可结合空答案分数拒答。

（补充 2026-11-06）**“划线”是怎么变成数字的。** 模型对passage的每个token各出两个分数：一个是“作为答案起点”的分数、一个是“作为终点”的分数（两个输出头）。流程四步：

- 训练时对正确起止位置做交叉熵；
- 推理时挑合法的“起点≤终点”组合里总分最高的那对；
- 再经token→字符的偏移映射截出答案串；
- 所以“答案”从头到尾是一组可学习的打分，不是检索字符串。

“按构造不会幻觉”仅指**输出字符串必是passage的连续子串**——选错片段、脱离语境照常发生（中文说明的提醒）。这也解释了4.1的返回四件套：start/end就是挑中的那对位置，score是这对组合的置信分数（跨域不可当概率标尺）。

（补充 2026-11-06）**联合编码的意义。** question和passage不是分别编码再比对，而是拼成一条序列一起过编码器——passage里每个token的表示都混入了问题的信息（第10课cross-attention读两条序列的场景）。

- “iPhone发布于___”这个问题会把“日期类词”位置的表示推向高分；
- 代价是每次换问题都要把整篇passage重新编码一遍；
- 这也是4.2把语料预编码交给检索器、只对top-k重编码的效率动机。

RAG先检索top-k，再阅读/生成。检索漏证据与阅读错证据是两类错误，要分开测。dense retriever分别编码query和文档，normalize后点积为余弦。

（补充 2026-11-06）**两层错误的分工表（对应0.5问题1）。**

| 症状 | 出错层 | 修哪里 |
|---|---|---|
| 答案所在文档根本没进top-k | 检索召回 | 换/调检索器、扩k、加混合检索（第14课） |
| 文档在、答案被读错或读偏 | 阅读器 | 换reader、微调、加rerank |

评估顺序也因此固定：先测“正确文档进没进top-k”（检索召回），再测阅读器——阅读器再好也修不了缺文档，这正是0.5问题1的答案，也是第七节“不能凭模型自报置信度上线”的依据之一。

（补充 2026-11-06）**dense检索的两个细节。**

- query和文档**分别**编码（bi-encoder；与把两者拼在一起过模型的cross-encoder相对）：分别编码才能离线建库、在线只算一次点积；
- 归一化后点积就是余弦（第03课2.2的近邻检索同一招）——余弦阈值的含义依embedding模型而变，0.3之类的数字不能跨模型通用（第七节第2条）；
- 第14课会把BM25与稠密检索做RRF融合并加重排，本课的单路dense只是起点。

（补充 2026-11-06）**引用存在≠引用支持。** 生成式答案里贴了一段检索原文，只证明“抄了”，不证明“这段话蕴含答案”——被引句可能带否定或条件（“2007年并未发布……”照样包含2007）。核验引用要判蕴含关系，三档做法：

- NLI式分类器：自动、便宜，本身也是模型、有误差；
- QA式追问：拿答案当问题去问原文，一致才可信；
- 人工：最可靠也最贵；
- 与第11课的路检清单同源：自动指标打底，关键内容人工兜底。

RAGAS的faithfulness是NLI式的自动化版本，“指标条件依版本/配置而不同”的中文提醒即指此。

EM是规范化后的完全匹配，token-F1给重叠部分分。支持问题回答质量、检索召回、引用支持和拒答校准不能用一个相似度代替。RAGAS等框架各指标需要的字段与裁判依版本/配置而不同，不能统称“都不需要gold”。

### 2.9 用一个小例子把概念串起来（补充）

若检索首先没找到发布日期所在文档，reader即使完美也无法从证据抽到日期；这叫召回失败。若文档已含日期但reader选成宣布日期，是阅读错误。原文给定passage中June 29, 2007的字符区间实际为[40,53)，这是字符串计算结果，不需要模型推理。

## 四、Build It：原课分步代码与中文讲解

### 4.1 预训练抽取式QA

qa返回score、字符start/end和answer。原课所示偏移57～70与给定字符串并不一致，应以实际context[start:end]核对；不能照抄参考偏移当标注。SQuAD2管线要显式handle_impossible_answer=True才把空答案候选纳入相应返回行为；score不是跨域可直接当置信概率的标尺。

~~~python
from transformers import pipeline

qa = pipeline("question-answering", model="deepset/roberta-base-squad2")

passage = (
    "Apple Inc. released the first iPhone on June 29, 2007. "
    "The device was announced by Steve Jobs at Macworld in January 2007."
)
question = "When was the first iPhone released?"

answer = qa(question=question, context=passage)
print(answer)
~~~

~~~python
{'score': 0.98, 'start': 57, 'end': 70, 'answer': 'June 29, 2007'}
~~~

### 4.2 稠密检索接抽取阅读器

corpus_embeddings为(N,D)，q_emb为(1,D)，相乘后得到每文档分数。取前k再拼接给qa。拼接后的字符偏移属于combined字符串，不是原文档偏移，需要保存文档与片段映射。原示例question只有四个候选文档，不涉及向量库。

~~~python
from sentence_transformers import SentenceTransformer
import numpy as np

encoder = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2")

corpus = [
    "Apple Inc. released the first iPhone on June 29, 2007.",
    "Macworld 2007 featured the iPhone announcement by Steve Jobs.",
    "Android launched in 2008 as Google's mobile operating system.",
    "The first iPod was released in 2001.",
]
corpus_embeddings = encoder.encode(corpus, normalize_embeddings=True)


# 原文真实检索：对query编码，与归一化文档向量点积排序。
def retrieve(question, top_k=2):
    q_emb = encoder.encode([question], normalize_embeddings=True)
    sims = (corpus_embeddings @ q_emb.T).squeeze()
    order = np.argsort(-sims)[:top_k]
    return [corpus[i] for i in order]


# 拼接检索段落交给抽取器；返回偏移属于拼接字符串。
def answer(question):
    passages = retrieve(question, top_k=2)
    combined = " ".join(passages)
    return qa(question=question, context=combined)


print(answer("When was the first iPhone released?"))
~~~

### 4.3 生成式RAG接口

检索3段拼进提示词，llm(prompt)负责调用。提示词要求“仅上下文、不知道就说不知道”是约束意图，不是技术保证。外部文档也可能含提示注入，应作为数据而非系统命令；回答需可追溯证据与拒答校准。

~~~python
# llm是外部可调用接口，提示词本身不保证正确或拒答。
def rag_generate(question, llm):
    passages = retrieve(question, top_k=3)
    prompt = f"""Context:
{chr(10).join('- ' + p for p in passages)}

Question: {question}

Answer using only the context above. If the context does not contain the answer, say "I don't know."
"""
    return llm(prompt)
~~~

### 4.4 真实评估维度

除了EM/token-F1，还要看人工语义正确、引用是否支持、可答/不可答拒答错误及检索召回。引用字符串确实来自检索结果，只证明引用存在，不证明它蕴含回答；需语义/人工核验。



### 4.5 RAGAS与指标条件

faithfulness检查回答断言与上下文支持；answer relevance看是否回答问题；context precision/recall衡量证据质量。某些context recall指标需要参考答案或标注；原文“一律reference-free”的表述不准确。框架名不是已完成评估的证明。

## 七、失败模式、原文边界与工程注意

1. 无证据时不应强抽一个跨度；应有无答案集和阈值校准。
2. cosine=0.3不能跨embedding模型通用，要在留出问题上调。
3. 检索引用命中不等于断言被支持；句子可能含否定或条件。
4. 单段抽取也会选错人物/时间，不能把“来自源文”当正确充分条件。
5. 40～60%幻觉减少、7～9题正确等均非本文实验结论。
6. 有拒答提示词不等于已经有安全拒答机制。

## 十、术语与完成标准

reader：基于证据读出答案；retriever：候选证据检索；EM：规范化完全匹配；token-F1：答案词重叠；faithfulness：相对给定证据的支持；拒答校准：可答性与风险权衡。

完成检查：

- 能说明RAG的检索与阅读两层错误。
- 能用字符串切片核对答案偏移。
- 能区分引文存在与引文支持。
