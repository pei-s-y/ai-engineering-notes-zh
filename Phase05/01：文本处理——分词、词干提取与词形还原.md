## 一、The Problem：为什么需要文本处理？

以这句话为例：

~~~text
The cats were running.
~~~

人能识别单词和语法，但程序需要明确规则：

1. 从哪里切分？句号是否单独保留？缩写里的撇号怎么处理？
2. 是否把不同词形合并？例如把 cats 和 cat 当成同一项。
3. 合并到什么程度？是否保留 running 的进行含义、were 的过去时含义？

文本处理会改变模型看到的表示。规则太粗糙，可能把不同含义错误合并；规则不一致，可能让训练和使用阶段看到不同的输入分布。

**补充说明：本课还没有完成模型训练或 token ID 编码。** 这里输出的是字符串列表。传统文本分类后面常接词袋、TF-IDF 等数值特征；大语言模型通常使用自己的 tokenizer 把文本转换成 ID。不要把“得到字符串 token”与“已经得到最终模型输入”混为一谈。

## 二、The Concept：三个操作，各自负责什么？

| 操作 | 中文 | 核心问题 | 结果特点 |
|---|---|---|---|
| Tokenization | 分词/标记化 | 文本切成哪些单位？ | 单位可以是词、子词、字符或字节 |
| Stemming | 词干提取 | 根据规则去掉部分词缀后剩什么？ | 结果可以不是词典里的单词 |
| Lemmatization | 词形还原 | 当前词形的基本词元是什么？ | 使用词表、形态规则，有时依赖词性 |

### 2.1 分词不是只能按空格切

~~~text
The cats were running.
→ ["The", "cats", "were", "running", "."]
~~~

空格只是可能的边界。标点、数字、撇号、网址、中文等都需要额外考虑。不同 tokenizer 可以有不同的合法切分约定，例如保留整个缩写或拆开其中的成分；关键是符合任务并保持一致。

### 2.2 词干提取不负责恢复“标准英语”

词干提取常通过后缀规则归并形式。完整词干工具可能把 running 处理成 run，也可能产生 poni 这种不直接用于自然语言表达的结果。

它适合某些检索索引和粗粒度统计，但有过度归并和归并不足的风险。**词干应作为内部表示，不应直接替换展示给用户的原句。**

### 2.3 词形还原与词性

词元 lemma 是基本形式。例如：

~~~text
cats（名词复数）→ cat
ran（动词过去式）→ run
were（be 的一种形式）→ be
better（形容词比较级）→ good
~~~

POS 是 part of speech，即词性。NOUN 表示名词，VERB 表示动词，ADJ 表示形容词。词形还原可能需要这些信息，不能只看字母后缀。

**原文表述边界：** “词形还原通常比简单删后缀更符合语言形式”不等于“所有方法都必须显式传 POS”。只按词形查表的 lookup 模式可以不使用 POS；是否需要取决于实现。

### 2.4 不存在通用的“预处理越多越好”

先问下游任务需要保留什么。例如：

- 搜索索引可能希望归并单复数，减少词形差异。
- 时态分析可能不能丢掉过去式和进行形式。
- 情感分析不能随意删掉 not 等否定成分。
- 预训练 Transformer 通常应遵守配套 tokenizer 的输入约定。

原课介绍的选型方向可理解为：能容忍粗糙归并时考虑词干，需要基本词元时考虑词形还原；最终应以具体任务评估为准，而不是一律同时使用两者。

## 四、Build It · Step 1：实现正则分词器

### 4.1 原课代码的中文注释版

~~~python
import re

def tokenize(text):
    # 按三个分支依次尝试：
    # 1. 英文字母串，可选地带一段内部直撇号和字母
    # 2. 连续数字
    # 3. 其他非空白单字符
    return re.findall(
        r"[A-Za-z]+(?:'[A-Za-z]+)?|[0-9]+|[^\sA-Za-z0-9]",
        text
    )
~~~

这里仅增加注释和换行，与原课 Build It 的规则相同。

### 4.2 把正则表达式拆开

| 片段 | 含义 | 例子 |
|---|---|---|
| [A-Za-z]+ | 一个或多个英文字母 | cats、running |
| (?:'[A-Za-z]+)? | 可选的一段“直撇号 + 字母” | weren't 中的 't |
| [0-9]+ | 一个或多个数字 | 123 |
| [^\sA-Za-z0-9] | 一个非空白、非英文字母、非数字字符 | .、!，也包括单个汉字 |
| 分支之间的 \| | 在候选分支中选择能匹配的分支 | 先按词的模式尝试，再考虑其他分支 |

几个 Python/正则语法点：

- r"..." 是原始字符串，让 Python 不先把 \s 等反斜杠序列当成普通转义处理。
- + 表示前一项出现一次或多次；? 表示零次或一次。
- \s 匹配空格、制表符、换行等空白。
- 字符类开头的 ^ 表示排除；它不是这里的“句子开头”。
- (?:...) 是非捕获分组：只负责组合规则，不让 findall 只提取这个组里的内容。
- findall 返回所有匹配到的片段，不会自动去掉句号或把文字转成小写。

### 4.3 原课测试与输出

~~~python
print(tokenize("The cats weren't running at 3pm."))
~~~

~~~text
['The', 'cats', "weren't", 'running', 'at', '3', 'pm', '.']
~~~

重点看三个地方：

1. weren't 被保留为一个 token，因为表达式专门允许内部直撇号。
2. 3pm 被拆成 3 和 pm，因为数字串、字母串分属不同分支。
3. 句号单独保留，空格不保留。

### 4.4 补充边界测试

~~~text
3.14              → ['3', '.', '14']
state-of-the-art  → ['state', '-', 'of', '-', 'the', '-', 'art']
https://example.com → ['https', ':', '/', '/', 'example', '.', 'com']
你好世界          → ['你', '好', '世', '界']
don’t             → ['don', '’', 't']
~~~

最后一个例子使用弯撇号 ’，不是代码专门匹配的直撇号 '。

**重要限制：** 这个英文规则不能直接当中文分词器。中文只是被兜底分支逐字符接住；空白信息也丢失了，不能保证从这些 tokens 精确恢复原始排版。[正则语法参考](https://docs.python.org/3/library/re.html)

## 五、Build It · Step 2：只实现 Porter Step 1a

### 5.1 原课代码的中文注释版

把下面函数接在 tokenize 后面：

~~~python
def stem_step_1a(word):
    # 长后缀必须先判断：caresses → caress
    if word.endswith("sses"):
        return word[:-2]

    # ies → i：ponies → poni
    if word.endswith("ies"):
        return word[:-2]

    # ss 不变：caress → caress
    if word.endswith("ss"):
        return word

    # 其他 s 结尾删除一个字符；避免单独的 s 被删成空串
    if word.endswith("s") and len(word) > 1:
        return word[:-1]

    # 不匹配时保持原词
    return word
~~~

### 5.2 为什么这样写？

endswith 用于判断结尾；word[:-2] 是切片，表示保留除最后两个字符之外的部分。

以 ponies 为例：

~~~text
p o n i e s
去掉最后两个字符 e、s
得到 p o n i
~~~

这就实现了 ies → i，而不是 ies → y。

每个命中条件会立刻 return。顺序很重要：如果先判断通用的 s 规则，caresses 可能只被截掉一个 s，无法得到目标词干。

### 5.3 原课测试与输出

~~~python
words = ["caresses", "ponies", "caress", "cats"]
print([stem_step_1a(w) for w in words])
~~~

~~~text
['caress', 'poni', 'caress', 'cat']
~~~

再测试：

~~~python
print(stem_step_1a("running"))
~~~

~~~text
running
~~~

因为 Step 1a 只覆盖上述复数等后缀规则，没有处理 ing。

### 5.4 原文纠错：poni 不需要被“修正成 pony”

原文说完整 Porter 的 Step 1b 会修正 poni，这不准确。原始规则的 Step 1a 本来就把 ponies 映射成 poni；Step 1b 处理带条件的 eed、ed、ing 等变化，不负责恢复 pony。

词干不是必须存在于词典里的英语单词。要得到规范词元，应该区分 stemming 与 lemmatization，而不是把词干算法误认为不完整的拼写修复器。[Porter 原始算法](https://tartarus.org/martin/PorterStemmer/def.txt)

## 六、Build It · Step 3：实现查表式词形还原

### 6.1 原课代码的中文注释版

继续接在同一文件中：

~~~python
# 键是（小写词形，词性），值是基本词元
LEMMA_TABLE = {
    ("running", "VERB"): "run",
    ("ran", "VERB"): "run",
    ("runs", "VERB"): "run",
    ("better", "ADJ"): "good",
    ("best", "ADJ"): "good",
    ("cats", "NOUN"): "cat",
    ("cat", "NOUN"): "cat",
    ("were", "VERB"): "be",
    ("was", "VERB"): "be",
    ("is", "VERB"): "be",
}

def lemmatize(word, pos):
    # 用词形和词性共同查表
    key = (word.lower(), pos)
    if key in LEMMA_TABLE:
        return LEMMA_TABLE[key]

    # 未命中时使用教学用的简单回退，保留原版局限
    if pos == "VERB" and word.endswith("ing"):
        return word[:-3]
    if pos == "NOUN" and word.endswith("s"):
        return word[:-1]

    return word.lower()
~~~

### 6.2 按执行顺序理解

以 lemmatize("running", "VERB") 为例：

1. 构造元组键 ("running", "VERB")。
2. 检查这个键是否在 LEMMA_TABLE 中。
3. 查到值 "run"，立即返回。
4. 后面的删除 ing 规则不会再执行。

这很重要：示例中 running 能正确变成 run，主要是因为查表命中，**不是因为简单删 ing 就足够**。

字典的键使用元组，表示需要同时满足“词形”和“词性”。word.lower() 用来构造小写键，但没有把 word 变量本身改写。

### 6.3 原课测试与输出

~~~python
print(lemmatize("running", "VERB"))  # run
print(lemmatize("cats", "NOUN"))     # cat
print(lemmatize("better", "ADJ"))    # good
print(lemmatize("watched", "VERB"))  # watched
~~~

watched 保持不变：词表没有这一项，回退规则也没有处理 ed。

### 6.4 必须理解的失败案例

~~~text
hopping + VERB  → hopp       缺少双辅音规则
sing + VERB     → s          不能因为以 ing 结尾就无条件截断
business + NOUN → busines    不代表末尾 s 一定是复数后缀
Playing + VERB  → Play       查表键变小写，不等于回退前 word 已变小写
~~~

这些行为是原代码的局限，注释版没有悄悄修复。真实工具需要更完整的词表、形态规则或训练模型，不能把这张小表当成通用英文分析器。

## 七、Build It · Step 4：把函数接成统一入口

### 7.1 原课代码的中文注释版

~~~python
def preprocess(text, pos_tagger=None):
    # 第一步：得到原始字符串 tokens
    tokens = tokenize(text)

    # 分支 A：小写化后提取词干
    stems = [stem_step_1a(t.lower()) for t in tokens]

    # 分支 B：有标注函数就调用；没有就把全部 token 暂当名词
    tags = pos_tagger(tokens) if pos_tagger else [
        (t, "NOUN") for t in tokens
    ]
    lemmas = [lemmatize(word, pos) for word, pos in tags]

    return {
        "tokens": tokens,
        "stems": stems,
        "lemmas": lemmas
    }
~~~

### 7.2 不是“先词干，再词形还原”

~~~text
原始文本 → tokenize → tokens
                       ├─ 转小写 → Step 1a → stems
                       └─ 词性标注 → lemmatize → lemmas
~~~

stems 和 lemmas 是供观察的两种表示，不是连续变换。lemma 分支收到的是原始词，而不是已经截断的词干。

### 7.3 函数作为参数是什么意思？

pos_tagger 是一个可调用对象。你把一个函数传给 preprocess，它就会用这套函数给 tokens 标注。

函数需要返回类似：

~~~python
[("cats", "NOUN"), ("were", "VERB"), ("running", "VERB")]
~~~

如果不传，pos_tagger 默认是 None，程序就给全部 token 填 NOUN。这样虽能运行，但不代表词性正确。

三元表达式 a if condition else b 表示“条件成立用 a，否则用 b”；列表推导式则逐项生成新列表。

## 八、补齐原配套脚本：演示标注器与主程序

原文正文的 Step 4 只给出统一入口；仓库 main.py 还补了下面两个函数。把它们接在前四步之后，就能直接运行。

~~~python
def demo_pos_tagger(tokens):
    # 只是教学词表判断，不是训练好的词性标注模型
    verbs = {"running", "ran", "runs", "were", "was", "is", "watched"}
    adjs = {"better", "best"}
    out = []

    for t in tokens:
        low = t.lower()
        if low in verbs:
            out.append((t, "VERB"))
        elif low in adjs:
            out.append((t, "ADJ"))
        else:
            out.append((t, "NOUN"))
    return out

def main():
    text = "The cats were running at 3pm."
    result = preprocess(text, pos_tagger=demo_pos_tagger)

    print(f"input:  {text}")
    print(f"tokens: {result['tokens']}")
    print(f"stems:  {result['stems']}")
    print(f"lemmas: {result['lemmas']}")

if __name__ == "__main__":
    main()
~~~

这个标注器没有利用上下文，只看词是否属于几个集合，其他全部标成名词。数字、标点也会进入默认分支，因此只能辅助演示。

`__name__` 这一段表示：直接运行文件时执行 main；导入这个文件时，不自动运行主程序。

新建 nltk_demo.py，放入：

~~~python
import nltk

# 第一次运行通常需要联网下载；之后通常使用本地缓存

nltk.download("wordnet")
nltk.download("averaged_perceptron_tagger_eng")

from nltk.tokenize import word_tokenize
from nltk.stem import PorterStemmer, WordNetLemmatizer
from nltk import pos_tag

text = "The cats were running."

# 词级分词，不是 BPE；使用该工具自己的分词约定
tokens = word_tokenize(text)

# 完整 Porter 工具，与本课只实现 Step 1a 的函数不同
stems = [PorterStemmer().stem(t) for t in tokens]

# 基于英文 WordNet 的词形还原器
lemmatizer = WordNetLemmatizer()

# 返回 Penn Treebank 风格的词性，例如 NNS、VBD、VBG
tagged = pos_tag(tokens)

def nltk_pos_to_wordnet(tag):
    # 两个工具的标签体系不同，调用前需要转换
    if tag.startswith("V"):
        return "v"
    if tag.startswith("J"):
        return "a"
    if tag.startswith("R"):
        return "r"
    return "n"  # 原文的简化默认策略，不代表所有其他成分都是名词

lemmas = [
    lemmatizer.lemmatize(t, nltk_pos_to_wordnet(tag))
    for t, tag in tagged
]

# 补充打印，原课计算到 lemmas 为止
print("tokens:", tokens)
print("stems:", stems)
print("tagged:", tagged)
print("lemmas:", lemmas)
~~~

执行：

~~~bash
python nltk_demo.py
~~~

### 9.3 每个资源与函数负责什么？

- punkt_tab：word_tokenize 所用的句子切分资源。
- wordnet：英文词汇与形态查询资源。
- averaged_perceptron_tagger_eng：英文词性标注资源。
- PorterStemmer：更完整的词干算法，不是自动“保证输出词典词”。
- WordNetLemmatizer：按提供的词性查找词元，不自行完成句子级词性预测。

WordNet 接口使用 n（名词）、v（动词）、a（形容词）、r（副词）等标记；默认 pos 是 n。查不到词元时保留输入词。[WordNetLemmatizer 文档](https://www.nltk.org/api/nltk.stem.wordnet.html)

### 9.4 应观察什么？

**以下是根据接口与示例给出的预期，未在本次环境中安装资源后实测：**

~~~text
tokens 通常为：['The', 'cats', 'were', 'running', '.']
stems 通常为： ['the', 'cat', 'were', 'run', '.']
tagged 通常包含 cats/NNS、were/VBD、running/VBG
lemmas 通常为：['The', 'cat', 'be', 'run', '.']
~~~

与手写 Step 1a 相比，完整词干工具能处理 running。注意原课 NLTK 示例没有对输入词统一 lower，词形还原结果中的 The 可能保留大写；不要把大小写转换和词形还原当成同一操作。

如果结果略有不同，先记录库、模型和资源版本，而不是直接判断算法错误。

新建 spacy_demo.py：

~~~python
import spacy

# 加载英文小型处理管线，包含本示例所需的模型与规则
nlp = spacy.load("en_core_web_sm")

# 返回 Doc 对象，而不是普通字符串列表

~~~

### 10.3 原文展示的参考输出

**这是原课给出的输出，不是本次重新安装模型后得到的实测：**

~~~text
The the DET
cats cat NOUN
were be AUX
running run VERB
. . PUNCT
~~~

DET 是限定词，AUX 是助动词，PUNCT 是标点。这个标签体系与手写示例、NLTK Penn Treebank 标签都不完全相同。

spaCy 先分词形成 Doc，再由配置的组件赋予词性、词形还原等属性；它不一定“自动有所有能力”，要看加载了哪些组件。rule 模式的 lemmatizer 需要前面的组件提供词性；lookup 模式则可以只查词形表。[spaCy 语言特征说明](https://spacy.io/usage/linguistic-features#lemmatization)

### 10.4 原文选型建议与补充说明

- 理解和拆解各步骤：NLTK 的函数式组合很直观。
- 使用统一管线处理批量文本：spaCy 提供工程化组件。
- 使用预训练 Transformer：通常使用模型配套 tokenizer，不额外强行做词干归并。

原文说 spaCy 更快、更准且难以替换组件，这些说法不应绝对化。它有可配置组件，速度和准确率也要在同一任务与数据上比较；不要把工具名当成效果保证。

## 十一、操作排错：遇到什么问题该看哪里？

| 现象 | 优先检查 |
|---|---|
| ModuleNotFoundError: nltk 或 spacy | 是否在当前 Python 所属虚拟环境里安装了库 |
| NLTK LookupError | 缺少哪一个具体资源；按报错中的资源名检查下载 |
| spaCy 提示找不到 en_core_web_sm | 是否为当前 Python 下载了英文管线 |
| 下载失败、超时或证书错误 | 网络、代理、证书环境；不要盲目关闭安全校验 |
| 改代码后结果与原课不同 | 是否改变输入、词性、大小写、规则顺序或库版本 |
| lemma 仍是原词 | 可能缺少规则、词表项、正确 POS；也可能本来就是基本形式 |

which python

python -m pip show nltk spacy

## 十二、原课强调的两个工程失败模式

### 12.1 可复现性漂移

升级库、模型或规则后，切分与词形结果可能改变。应记录：

1. Python 和第三方库版本。
2. 使用的语言模型/词典资源。
3. 正则与大小写等配置。
4. 一组固定输入及其预期输出。

原文建议为约 20 个典型句子建立回归测试。可以覆盖缩写、直/弯撇号、URL、小数、中文、空字符串和多空格。升级时检查变化是否合理，不要只看程序是否还能启动。

**原文举的具体版本间缩写变化只是例示，不能把它当作已经核实的 spaCy 版本行为。**

### 12.2 训练与推理不一致

如果训练时把所有词变小写并做词干归并，部署时却直接使用另一套表示，模型接收到的特征就可能不一致。

把预处理作为可复用函数和模型流程一起保存，而不是让训练、部署各重写一份。若还要学习词表或 TF-IDF 参数，应在训练数据上拟合，随后固定用于验证和测试，避免信息泄漏。

补充原则：保留原始文本；不要默认删除否定词、大小写和标点；中文应选适合中文的方案，而不是直接套英文后缀规则。

## 十四、Exercises：原课三项练习，怎样开始？

### 练习 1：让 URL 保持完整（原课 Easy）

目标：下面句子中的网址是一个 token。

~~~text
Visit https://example.com today.
~~~

操作顺序：

1. 先运行原 tokenize，确认网址目前怎样被拆开。
2. 在普通词分支之前加入 URL 候选分支。
3. 测试网址后有空格、句号、括号等情况。
4. 明确你采用的标点边界规则，不要把“匹配到 http”误认为完成。

验收重点：网址主体完整，后面的 today 和句号仍能按预期识别。一个简单 URL 正则不等于完整网址语法验证器。

### 练习 2：实现 Porter Step 1b（原课 Medium）

原课重点是 ed、ing 及双辅音处理。完整规则还涉及带条件的 eed、元音、回补 e 等，不只是新增两个 endswith。

建议先用这些成对案例驱动实现：

~~~text
hopping  → hop
motoring → motor
sing     → sing
plastered → plaster
~~~

检查顺序：

1. 先判断是否满足删除后缀的条件。
2. 如果允许删除，再处理剩余词干的双辅音。
3. 查阅本笔记末尾提供的原始规则来源，补齐其他条件。
4. 保留 Step 1a 测试，避免新增规则破坏已有结果。

这里的任务是词干算法，不要求输出都成为真实词典词。

### 练习 3：WordNet 查表 + 词干回退（原课 Hard）

目标：比较纯 WordNet、纯 Porter、混合策略在带词性和标准 lemma 标注的数据上的表现。

操作顺序：

1. 准备固定的词、POS 与标准 lemma 对。
2. 对齐词性标签体系。
3. 分别得到三种策略的输出。
4. 用“预测 lemma 与标准 lemma 完全相同的数量 / 总数量”统计准确率。
5. 观察哪些词因回退而改善，哪些词变成了不是真正 lemma 的词干。

**补充陷阱：** WordNet 返回原词，不一定说明“词典没有这个词”，它可能本来就是基本形式。若要判断回退条件，应明确区分“找到原形”和“未找到候选”；不能仅用返回值是否变化判断。

原课没有提供这些练习的完整答案。本笔记给出操作与验收方向，不把提示伪装成已经完成的实验结果。

## 十五、和之前 BPE 那一课的联系

两课都谈 token，但重点不同：

- 本课用人工规则切词，并讨论是否归并词形。
- BPE 从语料中学习片段合并，再映射为模型 ID。
- stemming/lemmatization 会改变词形，通常不可逆；它们不是 BPE。
- “先词干化，再 BPE”不是固定标准流程，可能与预训练模型的训练输入不一致。

你后续学习 Agent 时，需要理解文本进入模型的约定；不必因此认为每个 Agent 系统都要先把用户输入变成词干。

## 十六、术语表与完成标准

| 术语 | 本课应掌握的含义 |
|---|---|
| Token | 由具体切分方案定义的单位，不一定是完整单词 |
| Stem | 规则删改后缀产生的词干，不一定是词典词 |
| Lemma | 基本词元，不等同于随意截断的片段 |
| POS tag | 词性标记，不同工具的标签体系可能不同 |
| Morphology | 形态变化，如时态、数、格等词形变化 |
| Fallback | 主策略未命中时采用的回退策略，不保证更准确 |
| Pipeline | 按依赖顺序组织的处理流程 |

学完后应能独立做到：

- 解释分词、词干提取、词形还原分别解决什么问题。
- 看懂正则的三个分支，预测 3pm 和中文会怎样切分。
- 解释规则顺序和 return 为什么影响结果。
- 说明 running 在 Step 1a 与查表分支中为何不同。
- 运行原项目示例，并对照笔记解释四行输出。
- 说明 NLTK 需要哪些资源、为什么要映射 POS。
- 运行 spaCy 示例，并区分原文参考输出与自己环境的实测结果。
- 知道哪些处理会丢信息，并保持训练/推理流程一致。

一句话回顾：**先决定怎么切，再决定哪些词形需要归并；保留任务需要的信息，比盲目增加预处理步骤更重要。**
